# H3 人物场景道具提取（原 H3 V78.3.0.59 规则融合版）

仅当用户在“人物场景道具提示词”下拉框选择本方案时执行。它是批量工厂统一资产提取链的一种规则，不创建另一套 H3 服务、数据库或任务中心。

本规则在**一次模型请求、一个 JSON 返回**内完成下面两个逻辑阶段：先从视频原文确定正式人物、人物事实、关系、场景和关键道具；再基于刚完成的事实为全部正式人物写完整外形。不得把第二阶段拆成逐人请求，也不得要求系统补调。

运行时会提供：当前书“视频原文”、`style.system` 已保存的内容类型／时代世界观／统一视觉风格，以及用户已人工锁定的资产事实（若有）。原 H3 的模板变量由这些运行时输入替代，不要输出变量名或模板符号。

## 同次推理阶段一：正式人物、事实、关系、场景与道具

### 【V59 AUTO正式人物名单判断｜只确定正式人物基础身份】

先判断哪些人物需要进入正式人物名单。不得生成分镜、镜头、VIDEO、改写正文或解释过程。

1. 第一人称“我”默认第一主角；如原文明确真实姓名、女主／男主、关系称谓、昵称或外号属于同一人，合并为一个正式人物基础身份，禁止重复建人。
2. 主角必须进入正式人物名单。其他人物只有在稳定姓名／称谓、关键关系、跨分镜持续、承担关键对白、直接推动主线或需要长期外形一致时才进入正式人物名单。
3. 一次性摄影师、服务员、司机、护士、医生、保安、路人、宾客、普通同学、职员、士兵、侍卫、群体成员等默认不建正式人物卡；它们后续属于临时人物／群体链。原文明确要求其长期身份连续时才可提升为正式人物。
4. 系统界面、系统提示、弹幕、聊天记录、监控、名单、合同、榜单等信息载体不是正式人物。系统精灵／助手只有长期具象化并作为持续角色时才进入正式名单。
5. 只依据当前书视频原文判断，不引用旧项目、旧人物卡或本地人名、性别、年龄模板。人工锁定事实除外，且必须保留。
6. 返回顺序：主角优先，其余按剧情重要性与首次有效出场排序。一个人物只保留一个稳定 `slot_id` 槽位；不要因不同年龄、回忆或别称重复建人。

### 【V59 第二步：只按强制名单生成人物卡】

`style.system` 已经确认内容类型、时代／世界观和统一视觉风格，不得重新判断或改写。结合完整原文，为每个正式人物确认：规范名称、别称、性别、唯一年龄阶段、主角身份、人物事实与专属原文证据。

1. 人物集合必须与阶段一确认的正式人物一一对应；不得增删、合并、换序或用别称替代规范名称。
2. “我”必须结合全文识别主角身份及对应真实姓名／别称。性别只能依据身份称谓、亲属关系、他／她、男孩／女孩及人物专属原文强证据判断；不得只凭姓名猜测。
3. 年龄阶段只能选一个：女婴儿、男婴儿、小女孩、小男孩、少女、少年、年轻女性、年轻男性、中年女性、中年男性、老年女性、老年男性。用户人工锁定值优先。
4. 祖宅、家规、堂哥、少爷、老爷、大宅等弱词不能单独判定古代；现代、古代、民国、仙侠、科幻、校园等必须依赖完整强证据和已保存风格。

### 【V52通用小说人物关系图与分镜选角Skill｜关系图独立，只读人物卡】

1. 正式人物是唯一权威节点。名单外角色只能作为提及／群体／临时实体说明，不得新增正式人物、删除、合并、改名、改阶段或改外形。
2. 逐句识别完整姓名、真实别名、身份称谓、亲属称谓、职业称谓、代词、群体称谓、说话人、受话人、动作执行者、动作承受者和所属链。称谓必须绑定所属人，例如“丈夫助理的母亲”不得误认成女主母亲。
3. 第一人称必须区分主叙事、信件、日记、转述、回忆、梦境、小说内小说和多主角章节；第二人称结合说话人与受话人；第三人称不能只按最近人物匹配。
4. 每条关系必须有方向、原文证据、置信度、时间范围和世界线。过去／现在、前任／现任、身份揭晓前后、前世／今生、平行世界、时间循环不得互相污染；推测、传闻、伪装和事实必须区分。
5. 出场状态区分 `visible`、`speaker`、`addressee`、`offscreen_voice`、`mentioned_only`、`photo_visible`、`screen_visible`、`memory_visible`、`dream_visible`、`system_entity`、`group_visible` 和 `unknown`。仅被提到、传闻、资料名、联系人名、历史关系对象默认不得视为画面出场。
6. 电话、广播和录音标记 `offscreen_voice`；照片、监控、视频和手机屏幕按可见媒介标记；回忆、梦境和前世画面只在画面真正切入时标记可见。无法确认的代词或称谓保留低置信度，不得强行绑定。

### 场景与关键道具

只提取视频原文可追溯且会影响人物连续性、镜头空间或剧情动作的可见场景和关键道具。场景必须写空间结构、时段、光线、陈设、氛围和可见状态；道具必须写材质、外观、状态、持有／使用事实。不得把抽象情绪、旁白、聊天记录、系统界面或一次性无关背景物伪装成资产。

## 同次推理阶段二：全部正式人物完整外形

### 【V55人物卡外形隔离系统规则｜人物外形接口最终系统级规则】

本阶段在同一响应内，基于上一步的每个人物事实和已保存 `style.system` 结果，完成全部人物的外形；覆盖旧版固定年龄、固定题材人物模板、自动扩人物、自动拆阶段及“老年人物／古风男性／通用人物”等标签式旧写法。

1. 每个人物只描述当前确认的唯一人物槽位。不得把小说中其他人物的年龄、性别、亲属身份、服装或气质迁移到该人物。
2. 规范名称、`slot_id`、有效性别、年龄阶段、人工锁定字段为硬事实。不得擅自改名、改性别、改阶段、合并、重复或遗漏人物。
3. 使用已分析的题材、时代、世界观和当前时间线，再根据身份、职业、阶层、年龄、性别和专属原文证据自由设计发型、服装、配饰、装饰和鞋履。题材知识只作设计依据，禁止固定套装。
4. 少女／少年、成年、中年、老年必须严格隔离。少女和成年人物不得出现“老年人物、年迈、苍老、老态龙钟、佝偻”等老年身份锚点；老年人物也不得写成少女或少年。
5. 每个人物外形开头必须准确写出“亚洲＋年龄层＋性别”。自然顺序覆盖：身份与颜值定位、脸型骨相、皮肤、眉眼、鼻唇、发型发色、身高身形体态、服装款式层次、材质配色、配饰与必要装饰、鞋履、整体气质与稳定视觉识别点。
6. 年轻女性与年轻男性默认高颜值、自然上镜、穿搭高级且有辨识度；中老年真实体面，不丑化。同批人物必须在脸型、眼型、发型、身形、服装轮廓、主色和气质上形成清晰差异。
7. 只写可见、可拍、可直接用于图片与视频一致性的纯中文外形。不得写镜头、运镜、对白、旁白、字幕、Logo、水印、JSON、Markdown、字段名、分析过程、候选、自检或待补充文字。
8. 外形通常为 400 至 1600 个中文字符；不得使用“年轻女性、黑长发、穿西装”之类简化标签，也不得套用固定古风、现代、豪门或年龄模板。

## 唯一输出契约

只返回一个合法 JSON 对象，不要 Markdown、代码围栏或解释：

```json
{
  "characters": [
    {
      "name": "人物规范名称",
      "prompt": "完整人物外形提示词，已经融合身份事实、关系、已保存 style.system 和稳定识别点"
    }
  ],
  "scenes": [
    {"name": "场景名称", "prompt": "完整可见场景提示词"}
  ],
  "props": [
    {"name": "道具名称", "prompt": "完整可见道具提示词"}
  ]
}
```

每个数组可为空；每项必须有非空 `name` 与 `prompt`。人物 `prompt` 已是最终完整外形，必须可直接保存到单书资产库，后续不得要求逐人补调。人物关系、别称、证据、性别、年龄阶段和出场状态用于本次推理与后续导演 Trace 持久化，不要另输出第二份人物卡或第二份外形结果。
