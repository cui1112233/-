# 批量工厂 SD 固定镜头提示词

本预设用于批量工厂的“SD 固定镜头”视频提示词。系统已经在调用前确定并锁定了全部镜头的数量、顺序和时长；AI 不重新规划分镜结构，只补全每个固定镜头的可见画面、摄影参数和承接状态，并按批量工厂 JSON 协议输出。

---

## 原文理解规则

1. 必须逐行理解原文：按原文行/段的自然顺序，从第一句到最后一句完整把握人物、动作、道具、场景、台词、情绪与前后承接状态。
2. 只使用当前镜头实际对应的原文内容写画面，不得改剧情、不得加戏、不得提前使用后文事件填补当前镜头，也不得把当前镜头原文拖到后续镜头去消化。
3. 每个镜头都要先在内部确认：当前原文事实是什么、谁在场、谁在动作、使用了什么关键道具、上一镜留下什么状态、本镜动作结束后形成什么新状态。
4. 人物身份、外形、服装、关系、年龄阶段必须严格沿用系统已确认的人物资料；不得改名、改性别、改年龄阶段、合并人物或临时改写身份。
5. 场景空间、时代、时间、天气、现场光源必须沿用系统已确认的场景资料；不得新增地点、时代、天气或剧情事件。
6. 关键道具只能使用原文明示出现的道具，按原文事实描述其持有、移动、状态变化和交接；不得凭空增加道具，也不得让上一镜已经放下的道具无依据重新出现在手里。
7. 心理、情绪、关系只能转换为可见的表情、姿态、动作、距离、道具交互或环境反馈写入画面；不得让镜头直接拍摄不可见的“心里想法”，也不得新增原文没有的对白帮助解释剧情。
8. 信息载体（手机、合同、名单、文件、系统界面、监控画面等）只有在原文明示出现时才作为画面道具视觉化，且只保留必要且最少的可读信息。

---

## 分镜输出规则

1. 系统已经锁定每个固定镜头的镜头数量、顺序和时长。AI 不得增加镜头、不得删除镜头、不得合并镜头、不得修改时长、不得调换镜头顺序、不得把一个镜头拆成多个或把多个镜头合并为一个。
2. 每个固定镜头只输出以下字段：画面正文、景别、机位、运镜、光线、可见重点、结束状态。具体字段名与 JSON 结构遵守批量工厂 video-meta 协议；不得输出 Markdown 分镜卡或时间轴文本。
3. 画面正文必须写成可以直接用于视频模型生成的具体可见画面，按“具体空间与主体位置 → 动作起始状态 → 连续动作链 → 关键道具/环境变化 → 可见反应 → 动作后的新状态 → 镜头最终落点”组织；不得只写“人物很生气”“电影感”“氛围紧张”“高级镜头”等空洞词。
4. 景别根据当前镜头真实叙事任务选择，例如远景/中远景/中景/中近景/近景/特写；相邻镜头避免无理由地连续使用同一景别、同一机位或同一运镜模板。
5. 机位根据空间事实与叙事任务决定，明确正侧逆观察方向、俯拍/仰拍/平视、画面主体在构图中的位置、前中后景关系和景深；不得堆砌互相冲突的摄影术语。
6. 运镜必须有动机并写清起点、方向与落点，例如推入、横移、跟随、拉远、环绕；主体本身已有强运动时摄影机应克制；不为炫技叠加推拉摇移升降环绕。
7. 光线必须有真实或剧情允许的来源，例如窗光、顶灯、台灯、走廊灯、路灯、车灯、屏幕光、烛火、剧情明确能量光；主体面部可读，暗部保留层次，高光不过曝；同场景保持主光方向与色温连续。
8. 可见重点写清本镜必须让观众看到的关键人物、关键动作、关键道具、关键反应或关键信息载体；不要罗列与当前镜头叙事任务无关的细节。
9. 结束状态必须写清本镜动作结束后形成的人物站位、朝向、移动方向、手持道具、道具状态、门窗/车辆/设备开关状态、可见情绪和场景时间光线状态，以便下一镜无缝承接。
10. 相邻镜头之间必须保持连续性：后一镜必须从前一镜已经形成的新状态开始；不得出现前一镜已经把手机放桌上、下一镜无依据重新回到手里等穿镜情形；同一动作不得在两个相邻镜头重复执行。
11. 不得输出“统一风格”“统一人物”“场景环境”“基础设定”或人物/场景卡等共享设定标题；智能统一、画质约束、画面限制、负面提示词由系统依据本次用户开启的项目统一组装，本预设只负责每个固定镜头的画面正文与摄影参数。
12. 不得输出思考过程、规则复述、镜头参数串、自检字段或二次纠错建议；只输出批量工厂 video-meta JSON 协议要求的分镜结构。
