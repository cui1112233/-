## 3. 后端架构

### 3.1 技术特征

- 使用 Express，不使用旧版手写 HTTP 分发函数。
- `server.js` 只负责应用组合：创建 app、挂载中间件、挂载路由、启动服务。
- JSON 请求体限制当前为 `50mb`。
- 静态资源从 `public/` 提供。
- 页面路由由 `routes/pages.js` 提供。
- API 配置、生成历史、上游请求工具集中在 `lib/shared.js`。

### 3.2 主要路由

| 方法 | 路径 | 鉴权 | 功能 |
|------|------|------|------|
| `GET` | `/` | 无 | 首页 |
| `GET` | `/script` | 无 | 剧本生成页 |
| `GET` | `/agent` | 无 | Agent 工作区 |
| `GET` | `/tts` | 无 | 配音页 |
| `POST` | `/api/login` | 无 | 登录并返回 Bearer token |
| `GET/POST` | `/api/config` | Bearer token | 读取或保存当前全局 API 配置 |
| `POST` | `/api/test` | Bearer token | 测试上游 AI API |
| `POST` | `/api/chat` | Bearer token | 代理转发到上游 AI API |
| `GET` | `/api/prompt` | Bearer token | 读取提示词文件 |
| `GET/POST/DELETE` | `/api/history` | Bearer token | 生成历史管理 |
| `POST` | `/api/tts` | Bearer token | TTS 代理 |

### 3.3 请求链路

```text
浏览器页面
  │
  ├─ GET /、/script、/agent、/tts
  │    └─ routes/pages.js -> servePage(...)
  │
  ├─ /api/login
  │    └─ routes/auth.js -> tokenMap
  │
  └─ 需要登录的 /api/*
       └─ middleware/auth.js -> Authorization: Bearer <token>
            ├─ routes/config.js
            ├─ routes/chat.js
            ├─ routes/prompt.js
            ├─ routes/history.js
            └─ routes/tts.js
```

## 4. 前端页面结构

当前前端是 Express 多页面，不再把首页作为剧本页和 Agent 页的 SPA 容器。

| 页面 | 文件 | 主要脚本 | 职责 |
|------|------|----------|------|
| 首页 | `index.html` | `public/js/common.js` | 导航入口、最近创作、设置、登录、历史入口 |
| 剧本生成 | `views/script.html` | `public/js/common.js` + `public/js/script.js` | 小说粘贴、人物场景提取、剧本生成、复制导出 |
| Agent | `views/agent.html` | `public/js/common.js` | Agent 工作区占位 |
| 配音 | `views/tts.html` | `public/js/common.js` + `public/js/tts.js` | 文本配音和批量生成 |

页面之间通过真实路由跳转：

- `/script`
- `/agent`
- `/tts`

`public/js/common.js` 负责公共行为：

- 主题切换。
- 侧边栏收起和移动端遮罩。
- `data-href` 路由跳转。
- API 设置弹窗。
- 登录状态和 Bearer token。
- Toast 提示。

## 5. 鉴权与配置

### 5.1 登录

`POST /api/login` 接收用户名和密码，验证通过后生成随机 token，并返回：

```json
{
  "token": "<token>",
  "username": "<username>"
}
```

前端将 token 保存到 `localStorage.auth_token`，后续 API 请求通过：

```http
Authorization: Bearer <token>
```

服务重启后内存中的 tokenMap 清空，用户需要重新登录。

### 5.2 API 配置

`GET /api/config` 返回脱敏配置，只暴露 `hasApiKey`。

`POST /api/config` 保存：

```json
{
  "provider": "custom",
  "baseUrl": "https://example.com/v1",
  "model": "model-name",
  "apiKey": "secret"
}
```

当前配置仍写入全局 `api-config.json`。用户级配置隔离尚未完成。

## 6. AI 生成流水线

### 6.1 人物与场景提取

剧本生成页先调用非流式或流式文本接口，让模型根据 `prompts/人物场景提取.md` 提取人物和场景 JSON。

输出会被前端整理为人物卡片和场景卡片。

### 6.2 剧本生成

生成阶段组合以下提示词：

- `prompts/连续开头.md` 或 `prompts/爆款开头.md`
- `prompts/通用规则.md`
- `prompts/剧情模式.md`、`prompts/画布模式.md` 或 `prompts/剧本模式.md`

前端将小说原文、人物 JSON、场景 JSON 和格式选择一起发送到 `/api/chat`。后端转发到 OpenAI 兼容的 `/v1/chat/completions`。

流式模式下，后端透传上游 SSE chunk，前端实时渲染生成结果。

## 7. 部署与运行

### 7.1 安装依赖

```bash
npm install
```

### 7.2 启动

```bash
npm start
```

启动后控制台输出本机和局域网访问地址：

```text
Server running on (Express):
本机访问: http://127.0.0.1:3000
局域网访问: http://<局域网IP>:3000
```

### 7.3 基础验证

```bash
node -c server.js
node -c public/js/common.js
node -c public/js/script.js
node -c public/js/tts.js
node scripts/validate-multipage-architecture.js
```

未登录访问受保护 API 应返回 `401`：

```bash
curl -s -o /tmp/qiantie-config.json -w '%{http_code}\n' http://127.0.0.1:3000/api/config
```


## 8. 已知限制

- 当前登录只完成身份入口，用户数据隔离尚未完成。
- `api-config.json`、`outputs/index.json` 和生成文件仍是全局共享。
- `test-gen.js` 仍使用旧的 `X-Auth-Token` 方式，后续应更新为登录后使用 `Authorization: Bearer <token>`。
- TTS 依赖外部服务 `tts2.121w.com`，稳定性受该服务影响。
- 账号密码当前写在服务端代码中，适合局域网临时使用，不适合公开部署。
