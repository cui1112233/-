# Agent 原后台文本模型贯通：第一项实际落地

基线：`cui1112233/-` 的 `v88`，`cbc089ad508973d5e3fbb5c6df2bfc5ed676e7a4`。
这不是全量 Lovart 对标完成报告，也不是图片／视频工作流已接通声明。

## 已实现

- `/agent` 挂载此前的聊天主入口，保留居中和文稿分栏样式。
- `/shuihuo-production`、`/batch-factory`、原主导航和登录不变。
- 前端从原 `/api/models?kind=text` 读取授权目录，选择原目录字符串 ID。
- `POST /api/agent/chat` 接收可选 `textModelId`，旧调用不传时仍用原默认模型。
- 团队响应器先检查原账号权限、团队及个人额度，再解析原目录的模型配置。
- 使用所选模型的真实 modelId、endpoint 和 credential；不复制密钥库、不增加用户配置表单。
- 所选模型不可用时拒绝，不回退到默认模型；所选模型有效时不要求无关默认配置完整。
- 响应的 `resolvedModel` 只含 catalogId、modelId、source；前端显示实际解析回执，缺失或不一致时不假报已切换。
- `GET /api/agent/capabilities` 在原 apiAuth 后注册；未更新后端时前端禁用切换，只允许原默认路径。
- 沿用原用量记录；不同模型不借用旧默认模型的价格。catalog 路径未定义价格时标记 pricingUnconfigured，不假报费用为零。
- 客户端断开信号传给原请求函数。无自动重试、无新收费生成、无服务重启。

## 实现边界

当前 V88 是混合迁移运行时，所以本项只补已有 Node 网关的兼容接线，没有新增 Node 服务、供应商适配器、数据库或另一套登录。生产能力继续以现有 Go 服务为目标；这不是完成去 Node。

用户本机导出的批量工厂客户端实际使用 V12，当前 Git 基线使用 V11；两者能力和参数不能仅凭相同函数名视为完全兼容。本项没有把 V11 文件覆盖到本机 V12，也没有修改其代理端口。

图片、视频、局部编辑、合成和上传尚未在新聊天入口接通。原生产接口/页面保留。后续需核实原任务和素材对象、模型标识以及受控执行回执，不能让助手文字代替真实任务结果。

## 更新边界

代码先放进基于 v88 的功能分支供审阅；不强推、不自动合并、不部署公网。用户本机曾有大量未提交改动，应按文件差异合并，不能 git reset --hard，也不能整份覆盖 App.jsx。原后台需要按已有启动方式加载本次代码后，能力接口才会返回 textModelSelection=true；前端刷新不能替代后端更新。

本项让“文本模型选择”真正进入执行链。它不证明用户当前浏览器已更新，不证明图片/视频链已完成，不把旧只读检查报告当作模型可用性的证据。
