## 2. 产品定位：批量工厂是“水货生产”的小说前贴版本（已确认）

- **水货生产**：主要做漫剧解说。
- **批量工厂**：主要做小说前贴。

两者在产品壳层、个人作品、工作台、预设 / Prompt / 图片 / 视频生产习惯上尽量对标和复用；小说获取、小说前贴、121 发布、多书批量等由批量工厂自己的业务逻辑负责。

核心映射：

`水货生产：一行一个分镜 → 批量工厂：一行一本小说`

顶部主入口：

`小说列表 / 引擎配置 / AI推理 / 批量操作 / 取消操作 / 任务/日志 / 上传121`

其中：

- 小说列表：对应水货生产“分镜调整”。
- 引擎配置：保持原名。
- AI推理：保持原名，不改成 AI导演。
- 批量操作：只负责实际媒体生成、重试、合并。
- 上传121：替换水货生产“导出剪映”的位置。
- 人物场景预设：不是全局顶部入口，是单书工作区。
- 原“资产/导演”主列：新版直接叫“预设”。

## 3. 小说获取 → 批量工厂 → 个人作品（已确认）

### 3.1 进入即创建作品并打开小说列表

废弃旧流程：

`Intake → 待建立批次 → 点击创建 V11 批次 → 工作台`

新版：

```text
小说获取
↓
进入批量工厂
↓
系统自动创建作品 / 文档
↓
直接进入小说列表
```

自动创建作品不等于自动执行 AI、生成图片、生成视频或上传121。

### 3.2 个人作品卡片

左上角显示生产模式标签：

- `批量工厂`
- `水货生产`

主标题才是文档名，例如：

```text
[批量工厂]
2026-09-11-001
```

文档名允许重命名。重命名只改显示名称，不改 projectId、bookId、任务关系、来源关系、121 发布绑定。

### 3.3 30 本小说 = 1 个批量工厂作品文档

默认按 30 本一档自动拆分：

- 1～30 本 → 1 个文档
- 31～60 本 → 2 个文档
- 61～90 本 → 3 个文档
- 91～120 本 → 4 个文档

100 本示例：

```text
100 本
↓
├─ 2026-09-11-001 → 30 本
├─ 2026-09-11-002 → 30 本
├─ 2026-09-11-003 → 30 本
└─ 2026-09-11-004 → 10 本
```

### 3.4 同一次拆分出来的多个文档

创建时复制同一套初始配置：引擎配置、AI推理配置、其他作品级统一设置。创建完成后各文档独立保存、独立修改，不再联动。

`001 修改 ≠ 自动修改 002 / 003 / 004`

实现层可保留隐藏 source/import group id 追踪同一次导入，但不作为用户可见交互。

## 4. 小说获取内容版本、内容范围、二次编辑、爆款、121发布（已确认）

### 4.1 小说获取传入的是“已经选定的完整内容版本”

小说获取可能传入：原文、去敏感化原文、不去敏感化原文、AI1、AI2、以后新增版本等。批量工厂接收本次实际送入的那个版本，并保留完整内容。

建议概念：

- `sourceVariant`：本次来自小说获取的内容版本类型。
- `sourceContentFull`：该版本完整内容，禁止被批量工厂二次编辑直接覆盖。

### 4.2 内容范围 = 前 N 条有效正文

`内容范围：5` = 忽略空白行，取前5条有效正文。  
`内容范围：10` = 忽略空白行，取前10条有效正文。  
空行不计数。

```text
sourceContentFull
↓
内容范围 N
↓
sourceFrontContent = 前 N 条有效正文
sourceRemainder = 第 N 条有效正文之后的剩余完整内容
```

内容范围只决定前贴生产区，不裁掉来源全文。

### 4.3 支持二次编辑

用户可直接编辑内容范围内的前贴文本，保存为独立工作文本：

`workingFrontContent`

它用于视频生产，不覆盖 `sourceContentFull`。

### 4.4 “爆款”是前贴文本的 AI 改写动作

```text
当前前贴文本
↓ 点击【爆款】
AI生成爆款候选
↓
展示改写结果
↓
用户点击【替换】
↓
workingFrontContent = 爆款结果
```

若不点击替换，则当前工作文本保持不变。

“原文直转 / 爆款开头”不再是两个互斥的大生产模式；新版是：来源版本 + 内容范围 + 手动二次编辑 / 爆款候选替换。

### 4.5 “改文 / 不改文”控制121正文，不控制视频是否使用改写文本

无论开关是什么，只要用户已经二次编辑或接受爆款替换，`workingFrontContent` 都可以用于视频生产。

#### 不改文

```text
视频生产：workingFrontContent
121正文：sourceContentFull
```

#### 改文

```text
视频生产：workingFrontContent
121正文：workingFrontContent + sourceRemainder
```

即只替换内容范围覆盖的前 N 条正文，后面继续拼接小说获取保存的剩余正文。

### 4.6 爆款是否上传不再增加独立开关

- 爆款未替换 → 不影响当前工作文本。
- 爆款替换成功 → 成为 `workingFrontContent`。
- 不改文 → 爆款只做视频，121 仍传 `sourceContentFull`。
- 改文 → 爆款替换前贴段，并与 `sourceRemainder` 拼接上传121。

### 4.7 数据必须可逆

至少保留：

```text
sourceVariant
sourceContentFull
contentRangeN
sourceFrontContent
sourceRemainder
workingFrontContent
publishRewriteEnabled
publishContent
```

`publishContent` 在上传前根据开关计算，不覆盖 `sourceContentFull`。

### 4.8 与旧 maxTxt 区分

小说获取旧 `maxTxt / 截取字数` 是按字数；批量工厂 `内容范围：5 / 10 / ...` 是按有效正文行数，两者不是同一语义。

## 6. 引擎配置（只管模型 / 运行参数）

顶部 Tab：

`[模型配置] [发布统一]`

模型配置：

- 视频：视频模型 / VIDEO 时长 / 画幅 / 匹配音频

### 6.1 配置继承与单分镜 / 单 VIDEO Override（已确认）

保留单分镜 / 单 VIDEO 独立覆盖设置。当前已确认允许单分镜覆盖：

- 视频模型
- VIDEO 时长 / 时长上限

生效优先级：

```text
作品统一配置
↓
单书 override（若有）
↓
单分镜 / 单VIDEO override（若有）
↓
effectiveEngineConfig
```

未覆盖字段继续向上继承。单分镜修改不能反向覆盖整本小说或作品统一设置。

## 8. 固定开头（单个视频 / 多个视频语义已确认）

固定开头与“爆款”完全不同：

- 爆款：改当前前贴文字内容。
- 固定开头：控制最终哪些分镜被真正转成视频，以及首个视频目标格式 / 时长。

### 8.1 单个视频

AI 仍正常分析全部当前生产文本并生成全部分镜 Prompt，但媒体层只执行 `分镜01 / VIDEO01`。

```text
分镜01 Prompt → VIDEO01
分镜02 Prompt → 保留，不执行视频
分镜03 Prompt → 保留，不执行视频
...
```

10s 模式就把 VIDEO01 作为10s目标；15s同理。

### 8.2 多个视频

就是正常完整生产逻辑：AI 根据 `workingFrontContent + 视频提示词 + 约束设置` 正常得到多少有效分镜，就执行多少 VIDEO。

不增加固定数量，不增加额外停止条件。

```text
单个视频 = AI照常得到全部分镜，媒体层只执行VIDEO01
多个视频 = AI照常得到全部分镜，媒体层执行全部分镜/VIDEO
```

## 9. 分镜与 VIDEO：1:1（硬规则）

```text
一本小说
├─ 分镜01 → VIDEO01
├─ 分镜02 → VIDEO02
├─ 分镜03 → VIDEO03
└─ ...
```

不存在 VIDEO 下再嵌套 Shot。

左右箭头切换当前分镜，并同步切换：预设、人物/场景/道具引用、视频提示词、画面提示词（若有）、画面图片、VIDEO结果、任务状态。

如果某分镜从未生成画面提示词，则不显示“画面提示词”Tab。

---

## 10. VIDEO 目标时长 / 请求时长 / 实际时长（硬规则）

`≤10s / ≤15s` 是单个 VIDEO 的能力上限，不是必须生成满。

区分：

- `targetDurationSec`：AI / 业务目标
- `requestedDurationSec`：真正发给 provider
- `actualDurationSec`：provider 成品真实时长

目标6s、模型输出10s → 接受10s，不裁剪当前单段。模型仅支持固定档位时，由 adapter 选择可用档位；实际时长按真实结果记录。

## 11. 人物 / 场景 / 道具：有图不用词（硬规则）

| 当前分镜引用对象 | 对象图存在 | 基础设置开启 | 最终视频输入 |
|---|---|---|---|
| 是 | 是 | 是 | 只传图片，不传该对象文字 Prompt |
| 是 | 是 | 否 | 只传图片，不传该对象文字 Prompt |
| 是 | 否 | 是 | 传该对象文字 Prompt |
| 是 | 否 | 否 | 什么都不传 |
| 否 | 任意 | 任意 | 什么都不传 |

基础设置只控制最终视频链路中“无图时的文字回退”；不控制已有图片上传，也不控制画面图链路的资产文字补齐。

---

## 12. 画面提示词永远不直接进入视频生成（硬规则）

`画面提示词` 只用于生成 `画面图片`。

视频生成：

- 有画面图片 → 上传画面图片
- 只有画面提示词、没有画面图片 → 忽略画面提示词
- 绝不把画面提示词编译进视频 Prompt

旧 `visualPrompt → compiledPrompt → 视频模型` 语义必须废弃 / 重构。

---

## 13. 系统自动判断文生 / 图生

不增加用户选择“文生视频 / 图生视频”。系统按当前分镜已有资产自动决定：

- 有画面图片 → 使用
- 当前分镜引用的人物 / 场景 / 道具有图 → 使用相关图
- 某对象无图 → 仅基础设置允许时使用该对象文字 Prompt
- 无视觉图 → 实际走纯文本视频

同一分镜允许多张相关参考图，例如：

`画面图片 + 女主图 + 男主图 + 客厅图 + 手机图`

超过模型上限时由 capability / adapter 显式处理，业务层不能擅自静默丢图。


## 15. 跟随音频：两个独立能力（已确认）

两个都关、单独开任意一个、两个同时开都允许。

### 15.1 生成阶段按音频时长约束

AI按真实音频总长规划分镜目标时长；provider 实际输出可以不同，不按单段强裁。

### 15.2 合成阶段按音频时长匹配

`自动倍率 = 视频实际总时长 ÷ 音频实际时长`

- >1.0x：加速
- =1.0x：原速
- <1.0x：允许慢放拉长

用户手动修改倍率时，直接覆盖自动推荐值，不叠乘。

TTS / 音频主要用于时长和节奏，不默认混入最终视频音轨。

## 16. 画面图片生成（已确认）

画面图是独立于最终视频 Prompt 编译的一条生成链路。

当前分镜引用对象逐个判断：

- 对象有图 → 用图，按照“有图不用词”不再注入该对象 Prompt。
- 对象无图但有资产 Prompt → 直接使用对应资产 Prompt 补齐视觉信息。
- 对象既无图也无 Prompt → 不凭空伪造。
- 再叠加当前分镜画面提示词。
- 交给当前有效图片模型生成画面图片。

### 16.1 无图文字回退不受“基础设置”控制

```text
画面图生成：
对象有图 → 用图
对象无图但有Prompt → 用Prompt补齐
不看基础设置开关

最终视频生成：
对象有图 → 用图，不用该对象Prompt
对象无图 → 是否使用该对象Prompt，由基础设置决定
```

### 16.2 批量“画面图”的执行范围

批量操作里的“画面图”只处理实际存在画面提示词的分镜。没有画面提示词的分镜，不因为批量按钮而凭空生成画面图。

## 17. 批量操作、任务与取消操作（已确认）

批量操作固定：

- 人物场景图
- 画面图
- 生视频
- 重试
- 合并

`AI推理 = 生成 Prompt / 规则`  
`批量操作 = 实际消耗模型资源`

重试支持用户勾选小说，并优先只重试失败阶段，避免重做已成功步骤。

### 17.1 每次批量操作形成独立 operation

每次实际批量任务形成一组独立 operation，用来关联这一次选中的小说、分镜、任务类型、队列任务和后续链路。

### 17.2 顶部“取消操作”只取消当前这一次 operation

点击顶部 `取消操作` 只针对当前这一次正在执行的批量 operation，不是一键停止整个作品。

不会影响：之前已经完成的媒体 / Prompt、其它 operation、与本次 operation 无关的任务、其它30本作品文档、已经成功保存的原始结果。

### 17.3 不伪造 provider 撤销能力

- 队列中尚未提交 provider → 直接取消，不再提交。
- provider 支持真实 cancel API → 尝试真实取消并记录结果。
- provider 不支持取消 / 已不可撤销 → 显示“已请求取消 / 停止后续处理”，不能伪装为“已取消成功”。

供应商结果即使随后返回，也不能继续自动触发本次 operation 的下游合并 / 上传121。

### 17.4 已完成结果不回滚删除

取消是停止继续执行，不是撤销历史结果。已成功结果保留，除非用户之后主动删除或重生成。

## 18. 小说列表“一行一本小说”的状态体系（已确认）

采用 **主状态 + 当前阶段 + 辅助标记**，不把十几个细碎步骤都塞成主状态。

### 18.1 主状态

建议固定为：

| 主状态 | 建议颜色 | 含义 |
|---|---|---|
| 待开始 | 灰 | 尚未进入实际生产 |
| 处理中 | 蓝 | 当前有 AI / 图片 / VIDEO / 合并等任务进行中 |
| 异常 | 红 | 当前小说存在真实失败 / 阻塞，需要用户处理 |
| 待上传 | 青 / 蓝绿 | 媒体生产与合并已完成，等待上传121 |
| 上传中 | 蓝 | 正在执行121上传 / 提交 |
| 已完成 | 绿 | 121 已得到真实确认，整本流程真正完成 |
| 已取消 | 灰 | 当前这次相关 operation 已停止，不代表删除历史结果 |

### 18.2 当前阶段作为副文字展示

例如：

```text
小说A   [处理中]   AI推理中
小说B   [处理中]   人物场景图 2/5
小说C   [处理中]   视频 3/6
小说D   [处理中]   合并中
小说E   [待上传]   视频已合并
小说F   [上传中]   121提交中
小说G   [已完成]   121已确认
```

处理中主状态不因为阶段变化而不停改成大量不同主状态；真实阶段放在旁边显示。

### 18.3 “已手调”是辅助标记，不抢主状态

用户手动改过 Prompt、分镜、引擎 override、素材等时，可显示紫色辅助标记：

`[已手调]`

例如：

```text
[处理中] [已手调]
```

它不是主状态。

### 18.4 异常优先级最高

若一本书同时存在“已手调”和真实失败，主状态必须显示：

`[异常] [已手调]`

不能让紫色手调状态盖住红色异常。

异常应给出真实阶段 / 对象，例如：

`VIDEO04 生成失败`  
`画面图02失败`  
`121回读未确认`

### 18.5 红色只用于真实异常

禁止再出现“处理完成”却弹红色状态、成功状态长期以错误红色挂在列表、两行重复成功提示等表现。

正常完成 / 成功提示应该短暂反馈后消失；列表长期保留的是业务状态本身。

### 18.6 “已完成”必须代表真的完成

只有121真正确认成功后才进入 `已完成`。不能把 healthy、task_id、accepted_pending、queued/running、仅HTTP成功等当作整本“已完成”。

## 23. 已废弃 / 被新规则覆盖的旧思维

- 大一统“生产统一设置” → 拆成引擎配置 + AI推理。
- 画面提示词直接进视频 Prompt → 废弃。
- 有对象图仍重复注入对象 Prompt → 废弃。
- 音频比视频长不允许慢放 → 废弃。
- 状态中心 + 自由布局是主页面核心 → 改为水货式一行一本小说。
- 只支持失败 VIDEO 重试 → 改为支持选书并按失败阶段重试。
- Intake 后必须手动创建批次 → 废弃。
- 原文直转 / 爆款开头作为两个互斥大生产模式 → 废弃。
- 固定开头=单个视频时 AI 只生成一个分镜 Prompt → 废弃。
- 固定开头=多个视频需要另外填写数量 / 停止数量 → 废弃。
- 单分镜不能独立调整引擎配置 → 废弃。
- 画面图无图文字回退受基础设置控制 → 废弃。
- 取消操作 = 停掉整个作品所有任务 → 废弃。
- 手调状态作为主状态覆盖异常 → 废弃；手调仅是辅助标记，真实异常优先。
- 成功 / 处理完成使用红色长期展示 → 废弃；红色只表示真实异常。
