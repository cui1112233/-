## 1. 开发固定约束

- API / 后端：Go（Golang），以二进制服务为主。
- 管理端：React + Ant Design。
- 用户端：React + Ant Design。
- 数据库：MySQL；数据库迁移使用 Goose。
- 队列 / 非关系型状态 / 锁：Redis。
- 对象存储：TOS。
- 部署：Go embed 打包前端资源进入后端。
- 系统预设 Prompt：由后端/管理后台管理，运行时替换真实 Prompt。
- 开发前先走 Superpowers 头脑风暴 / 设计确认，再进入实现。

## 2. 新版总体方向

新版批量工厂直接参考“水货生产”的操作习惯：

`水货生产：一行一个分镜 → 批量工厂：一行一本小说`

批量工厂 V11 继续使用自己的业务数据和 API，不把水货生产内部业务逻辑硬绑进来；但 UI 组件、切换习惯、生产操作体验可以复用。

顶部主入口当前锁定：

`小说列表 / 引擎配置 / AI推理 / 批量操作 / 取消操作 / 任务/日志 / 上传121`

其中：

- 小说列表：对应水货生产的“分镜调整”入口。
- 引擎配置：保持原名。
- AI推理：保持原名，不改成“AI导演”。
- 批量操作：只承担真实媒体生成、重试、合并。
- 上传121：替换水货生产“导出剪映”的入口位置。
- “人物场景预设”不是全局顶部入口，而是单书工作区功能。
- 原先叫“资产/导演”的主列，新版直接叫“预设”。

## 3. 小说列表与内容范围（已确认核心语义）

小说列表中的每一本书有“内容范围”。

例如：`内容范围：5`

核心含义已经确认：**只取小说内容前 5 行进入这次后续生产，不是把全文上传/送入 AI。**

因此它不是 5 个分镜，也不是 5 秒，也不是 5 个字，而是输入裁剪规则：

```text
小说全文
↓
内容范围 = 5
↓
取前 5 行
↓
后续资产提取 / 剧本与分镜推理 / 视频 Prompt 等使用这段裁剪后的内容
```

### 3.1 与现有 v88 `maxTxt` 的区别

Git 核对发现：当前 `NovelFetchPage.jsx` 的 Legacy 代码仍存在 `maxTxt / 截取字数`，默认示例为 2000 字；它是“按字数截取”。新版批量工厂的“内容范围 = 5”是“按行取前 N 行”，两者不是一个语义，后续实现不能直接把 `maxTxt` 当成“内容范围”。

### 3.2 尚待确认

“前 5 行”到底按 TXT 物理行计数，还是忽略空白行、按前 5 个有效内容行/段落计数，下一轮确认。

## 4. 单书配置

每一本小说都有自己的三块能力：

- 人物场景预设
- 引擎配置
- AI推理

推荐数据继承模型：默认跟随全局/批次，只有用户真正修改的字段才形成当前书 override。

## 5. 单书 → 人物场景预设

这是水货生产同名能力在“一本小说”层面的直接对应，布局习惯：

`左侧 Prompt / 右侧图片`

负责当前这一本书实际产生的人物、场景、道具结果，包括：

- 查看/编辑/保存 Prompt
- 重新生成 Prompt
- 查看图片
- 生成人物/场景/道具图片
- 替换图片

职责边界：

`AI推理 → 资产设置 = 批量/全局生成资产 Prompt 的规则`

`单书 → 人物场景预设 = 当前书真正生成出来的资产 Prompt + 资产图片`

两者不能混为一块设置。

## 6. 引擎配置

引擎配置只负责模型与运行参数，不放 Prompt。

顶部两个 Tab：

`[模型配置] [发布统一]`

点击 Tab 后替换卡片内容，不把“发布统一”堆在模型配置下面。

### 6.1 模型配置

视频：

- 视频模型
- VIDEO 时长
- 画幅
- 匹配音频

图片：

- 图片模型

文本：

- 文本模型

### 6.2 API 配置边界

批量工厂不出现 API Key 输入框，不在这里编辑 personal_api 凭据。API 凭据由个人中心/管理端负责；批量工厂只选择当前账号已授权、已可用的模型。

### 6.3 Provider 能力层

业务层只负责决定“应该传什么”：

- 哪些参考图
- 哪些文本 Prompt
- 目标/请求时长
- 画幅
- 约束

供应商专用格式由 provider adapter / capability 层转换，包括参考图数量、时长档位、画幅、negative prompt 等。

禁止在业务数据里写死 `@图片1` 之类供应商语法。模型能力不兼容时必须显式处理/提示，不能静默丢参考图。

## 7. AI推理

AI推理只负责 Prompt 与 Prompt 相关推理规则；模型选择全部归引擎配置。

固定四个 Tab：

1. 资产设置
2. 约束设置
3. 视频设置
4. 画面设置

### 7.1 资产设置

- 人物场景提示词
- 范围
- 取消
- 确定生成

它是人物/场景/道具 Prompt 的全局/批量生成规则。

现有约束具体以剧本生成实际代码为准，包括基础设置、画面前缀、画质约束、画面限制、负面提示词等；只有启用的项参与最终编译。

### 7.3 视频设置

- 固定开头：当前只确认 `单个视频 / 多个视频`
- 视频提示词
- 范围
- 取消
- 确定生成

不要自行增加未确认模式。

### 7.4 画面设置

- 画面提示词
- 范围
- 取消
- 确定生成

### 7.5 AI推理预设

## 8. 分镜与 VIDEO 关系（已确认）

逻辑直接对齐“剧本生成”的分镜卡：**一个分镜就是一个 VIDEO 的生产标准，分镜与 VIDEO 是 1:1。**

```text
一本小说
├─ 分镜01 → VIDEO01
├─ 分镜02 → VIDEO02
├─ 分镜03 → VIDEO03
└─ ...
```

不是：

```text
VIDEO01
├─ Shot01
├─ Shot02
└─ Shot03
```

左右箭头是在切换分镜卡，也就是切换 VIDEO01 / VIDEO02 / VIDEO03 对应的生产单元。

切换分镜时必须同步切换：

- 当前预设
- 当前人物 / 场景 / 道具引用
- 视频提示词
- 画面提示词（如果有）
- 画面图片（如果有）
- 对应 VIDEO 结果
- 当前分镜任务状态

不能出现 Prompt 已切到分镜 3，但预设还停在分镜 2。

## 9. 分镜目标时长与实际 VIDEO 时长（已确认）

`VIDEO 时长 ≤10s` 的意思是单个分镜/VIDEO 的上限能力，不代表每个 VIDEO 都必须生成满 10 秒。

例如：

- 分镜01需要 6s → 目标 6s
- 分镜02需要 8s → 目标 8s
- 分镜03需要 10s → 目标 10s

建议数据层明确区分：

- `targetDurationSec`：AI / 业务希望该分镜多长
- `requestedDurationSec`：真正发给 provider 的时长参数
- `actualDurationSec`：provider 返回成品的真实时长

### 9.1 模型不严格输出目标时长

例如 Prompt/目标要求 6s，但模型最终返回 10s：接受这 10s，不裁剪当前单段，也不把当前单段强制压回 6s。

如果 provider 的参数本身只允许离散档位，例如只支持 5s / 10s，而目标是 6s，则按当前确认思路使用能覆盖目标的可用时长档位（例：10s）生成，仍不裁剪。

最终整体时长问题交给合成阶段的跟随音频/倍率能力处理。

## 10. 人物 / 场景 / 道具：有图不用词（硬规则）

每一个当前分镜引用的对象都独立判断：

| 分镜引用对象 | 对象图片存在 | 基础设置开启 | 最终输入 |
|---|---|---|---|
| 是 | 是 | 是 | **只传图片，不传该对象文字 Prompt** |
| 是 | 是 | 否 | **只传图片，不传该对象文字 Prompt** |
| 是 | 否 | 是 | 传该对象文字 Prompt |
| 是 | 否 | 否 | 什么都不传 |
| 否 | 任意 | 任意 | 什么都不传 |

适用于人物、场景、道具。

**基础设置只控制“没有对象图时，是否允许用对象文字 Prompt 回退”，不控制已有对象图是否上传。**

锁定示例：上传了女主图，就不要再把女主人物 Prompt 注入同一次生成。

## 11. 画面提示词与画面图片（硬规则）

画面提示词只负责生成画面图片：

`当前分镜视觉资产 + 画面提示词 → 画面图片`

视频生成时：

- 有画面图片 → 上传画面图片。
- 只有画面提示词、没有画面图片 → 完全忽略画面提示词。
- 画面提示词绝不能直接编译进视频 Prompt。

因此旧版如果存在 `visualPrompt → compiledPrompt → 视频模型` 的语义，新版必须废弃。

如果某分镜没有生成过画面提示词，主界面也不要强行展示“画面提示词” Tab，只显示视频提示词即可。

## 12. 系统自动判断文生视频 / 图生视频

不要让用户选择：

- 使用画面图片
- 直接使用人物场景参考图
- 文生视频 / 图生视频

系统根据当前分镜真实存在的媒体自动判断：

- 有画面图片 → 使用画面图片。
- 当前分镜引用的人物/场景/道具存在图片 → 同时使用这些相关图片。
- 某个对象没有图 → 只有基础设置允许时，才使用该对象文字 Prompt。
- 完全没有视觉图片 → 实际走纯文本视频路径。

## 13. 同一分镜允许多张相关参考图

例如当前分镜需要：

`女主 + 男主 + 客厅 + 手机`

如果四张对象图都存在，它们都属于当前分镜的相关视觉参考。

如果当前分镜另外还有画面图片，则业务层希望传递的视觉集合可以是：

`画面图片 + 女主图 + 男主图 + 客厅图 + 手机图`

不要由业务层擅自只保留其中一张。最终 provider 能否全部接收，由 capability / adapter 层处理。

## 14. 视频最终输入编译（当前锁定）

```text
当前分镜 / VIDEOxx
↓
读取当前分镜 presetRefs
↓
逐个对象判断
├─ 有图 → 图片 only
├─ 无图 + 基础设置 ON → 对象文字 Prompt
└─ 无图 + 基础设置 OFF → 不参与
↓
+ 当前分镜画面图片（如果已生成）
+ 当前分镜视频提示词
+ 生成阶段音频时长约束（如果开启）
+ 约束设置中其他启用规则
↓
绝不加入画面提示词
↓
解析有效引擎配置（全局/批次 → 单书 override）
↓
video provider adapter
↓
VIDEOxx
```

## 15. 跟随音频：两个独立能力（已确认）

两个能力是独立开关，可以：

- 两个都关
- 只开生成阶段
- 只开合成阶段
- 两个同时开

### 15.1 生成阶段按音频时长约束

读取真实音频长度，让 AI 在分镜规划阶段尽量以音频总时长为目标分配各分镜时长。

例如音频 28s，AI 可以规划：

`6 + 8 + 7 + 7 = 28s`

但它只是生成目标，不保证 provider 成品严格等于 28s。某个分镜目标 6s，provider 实际返回 10s，仍接受 10s，不裁剪当前单段。

### 15.2 合成阶段按音频时长匹配

合成时以所有 VIDEO 的 `actualDurationSec` 为准，计算：

`自动倍率 = 视频实际总时长 ÷ 音频实际时长`

例一：

`35s ÷ 28s = 1.25x` → 加速压缩，最终接近 28s。

例二：

`25s ÷ 28s = 0.892857x` → 允许慢放拉长，最终接近 28s。

新版明确允许：

- `> 1.0x` = 加速
- `= 1.0x` = 原速
- `< 1.0x` = 慢放

旧版“音频比视频长就异常、不自动慢放”的规则正式废弃。

### 15.3 用户可以手动覆盖倍率

自动倍率只是系统推荐值。

例如系统推荐 `1.42857x`，用户改成 `1.35x`，最终合成直接使用 `1.35x`；不是在自动倍率上再乘 `1.35`。

### 15.4 两阶段可以一起使用

例如：

```text
音频 28s
↓
生成阶段先让 AI 尽量规划为 28s
↓
provider 实际总视频 = 31s
↓
合成阶段自动建议 31 / 28 = 1.107x
↓
用户可接受 1.107x，也可手动改成其他倍率
```

## 16. 画面图片生成

当当前分镜需要人物/场景/道具时：

- 对象有图 → 以对象图作为参考，不重复注入同对象文字 Prompt。
- 对象没图 → 使用对应对象文字预设作为参考文本（最终是否还受“基础设置”开关约束，后续需要再确认图像生成链路的精确边界）。
- 再加上当前分镜的画面提示词生成画面图片。

批量“画面图”只处理真正有画面提示词的分镜。

## 17. 批量操作（已确认）

固定包含：

- 人物场景图
- 画面图
- 生视频
- 重试
- 合并

边界：

`AI推理 = 产生 Prompt / 规则`

`批量操作 = 真正消耗模型资源执行媒体任务`

具体：

- 人物场景图：根据资产 Prompt，用有效图片引擎生成人物/场景/道具图片。
- 画面图：当前分镜参考资产 + 画面提示词 → 画面图片。
- 生视频：执行第 14 节最终输入编译。
- 重试：支持用户自己勾选书。
- 合并：按分镜/VIDEO 正确顺序合并，不重新生成 Prompt/图片。

### 17.1 重试

不能只有“重试全部失败”。必须支持：

`勾选小说03 / 小说07 / 小说12 → 重试选中的3本`

推荐执行粒度：失败在哪个阶段，就只重试失败阶段，例如人物图、画面图、某个 VIDEO、合并；已经成功的步骤不重复消耗资源。

## 18. 合并

当前确认：

- 按分镜/VIDEO 顺序合并。
- 以实际成品 VIDEO 时长为依据。
- 合成阶段可以应用自动跟随音频倍率或用户手动倍率。
- 某个 VIDEO 被重新生成后，旧合并结果应该失效并允许重新合并。
- 原始生成 VIDEO 不因为重新合并而删除。

仍待继续确认：失败片段是否允许跳过、整书合并是否必须 all-or-nothing、输出命名、重复合并版本历史等。

## 21. 当前 v88 Git 核对结果（2026-09-11）

本轮已直接核对 v88 当前代码，得到以下事实，用于区分“现有代码”与“新版目标设计”：

### 21.1 V11 页面入口

`frontend/src/user/pages/BatchFactoryPageV11.jsx` 只是兼容入口，实际渲染权威页面：

`batch-factory-v11/BatchFactoryV11UiPage.jsx`

### 21.2 当前工作台仍是旧布局思路

`BatchFactoryV11Workbench.jsx` 当前仍包含：

- selectedBook / selectedVideo
- 状态中心/筛选
- 可拖拽/缩放/隐藏布局
- 原文 / Hook / Director / 人物场景道具 Prompt / VIDEO 方案
- visualPrompt 编辑

这些是现状，不代表新版继续照搬。新版已经决定改成“水货生产式、一行一本小说”的母版，所以后续实现需要明确哪些旧交互退休、哪些能力迁移。

### 21.3 当前代码仍存在 `visualPrompt` 直接编辑

当前 Workbench 仍把 VIDEO 的 `visualPrompt` 当“画面提示词”编辑，并存在最终 Prompt 预览链路。新版硬规则已经改变：**画面提示词只生成画面图片，永远不直接进入视频生成。**

因此现有 `visualPrompt / compiledPrompt` 相关语义后续必须审查，不能原样沿用。

### 21.4 当前设置层级包含单 VIDEO override

`BatchFactoryV11ScopedSettings.jsx` 当前实现的是：

`系统默认 → 批次 → 当前小说 → 单 VIDEO`

单 VIDEO 当前能覆盖：

- duration
- aspectRatio
- subtitlePolicy
- negativeMergeMode
- characterRefs / sceneRefs / propRefs
- 约束设置

新版目前只明确锁定了全局/批次与单书配置；是否继续保留“单 VIDEO / 分镜设置”这一最高覆盖层，仍待用户确认。

### 21.5 当前 BatchManager 显式创建批次

`BatchFactoryV11BatchManager.jsx` 当前设计为：小说获取先转入 Intake，用户检查设置，再明确“创建/开始”，且创建批次本身不会自动启动 Director。

这套批次管理能力可以作为新版参考，但入口和交互需重新确认。

### 21.6 “内容范围”在已核对 V11 主工作台文件里不是现成字段

已核对 `BatchFactoryV11UiPage.jsx`、`BatchFactoryV11Workbench.jsx`、`BatchFactoryV11ScopedSettings.jsx` 后，没有看到新版所说的“内容范围 = 前 N 行”的现成主工作台字段。

因此当前先按用户确认的新产品语义记录，后续实现时需要正式落到小说列表/数据模型，不应假定旧 V11 已经完整实现。

## 22. 已明确废弃 / 冲突的旧思维

- 旧“大一统生产统一设置” → 新版拆成“引擎配置 + AI推理”。
- 旧 `画面提示词 → 最终视频 Prompt` → 废弃。
- 旧“有资产图仍重复注入同对象文字 Prompt” → 废弃。
- 旧“音频比视频长就异常、不允许慢放” → 废弃；新版允许 `<1x`。
- 旧单书设置把模型、Prompt、发布等全部揉在一个大表单 → 新版按职责拆分。
- 旧状态中心主导页面 → 新版用水货生产式“一行一本小说”，但状态能力不能丢。
- 旧仅 VIDEO 级批量媒体任务 → 新版覆盖人物场景图、画面图、生视频、重试、合并。
