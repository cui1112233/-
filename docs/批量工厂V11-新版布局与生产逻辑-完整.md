## 2. 产品定位：批量工厂是“水货生产”的小说前贴版本（已确认）

- **水货生产**：主要做漫剧解说。
- **批量工厂**：主要做小说前贴。

两者在产品壳层、个人作品、工作台、预设 / Prompt / 图片 / 视频生产习惯上尽量对标和复用；小说获取、小说前贴、121 发布、多书批量等由批量工厂自己的业务逻辑负责。

核心映射：

`水货生产：一行一个分镜 → 批量工厂：一行一本小说`

不是复制水货的数据结构，而是复用成熟的作品生命周期和交互，再换成小说前贴业务。

顶部主入口：

`小说列表 / 引擎配置 / AI推理 / 批量操作 / 取消操作 / 任务/日志 / 上传121`

- 小说列表：对应水货生产“分镜调整”。
- 引擎配置：保持原名。
- AI推理：保持原名，不改成 AI导演。
- 批量操作：只负责实际媒体生成、重试、合并。
- 上传121：替换水货生产“导出剪映”的位置。
- 人物场景预设：不是全局顶部入口，是单书工作区。
- 原“资产/导演”主列：新版直接叫“预设”。

## 3. 小说获取 → 批量工厂 → 个人作品（已确认）

### 3.1 进入即创建作品并打开小说列表

废弃旧流程：

`Intake → 待建立批次 → 点击创建 V11 批次 → 工作台`

新版：

```text
小说获取
↓
进入批量工厂
↓
系统自动创建作品 / 文档
↓
直接进入小说列表
```

自动创建作品不等于自动执行 AI、生成图片、生成视频或上传121。

### 3.2 个人作品卡片

左上角显示生产模式标签：

- `批量工厂`
- `水货生产`

主标题才是文档名，例如：

```text
[批量工厂]
2026-09-11-001
```

文档名允许重命名。重命名只改显示名称，不改 projectId、bookId、任务关系、来源关系、121 发布绑定。

### 3.3 30 本小说 = 1 个批量工厂作品文档

默认按 30 本一档自动拆分：

- 1～30 本 → 1 个文档
- 31～60 本 → 2 个文档
- 61～90 本 → 3 个文档
- 91～120 本 → 4 个文档

100 本示例：

```text
100 本
↓
├─ 2026-09-11-001 → 30 本
├─ 2026-09-11-002 → 30 本
├─ 2026-09-11-003 → 30 本
└─ 2026-09-11-004 → 10 本
```

### 3.4 同一次拆分出来的多个文档

创建时复制同一套初始配置：

- 引擎配置
- AI推理配置
- 其他作品级统一设置

创建完成后各文档独立保存、独立修改，不再联动。

`001 修改 ≠ 自动修改 002 / 003 / 004`

实现层可保留隐藏 source/import group id 追踪同一次导入，但不作为用户可见交互。

## 4. 小说获取内容版本、内容范围、二次编辑、爆款、121发布（已确认）

这一层必须把“来源内容”和“视频生产内容”拆开，禁止为了制作前贴而破坏小说获取保存的完整内容。

### 4.1 小说获取传入的是“已经选定的完整内容版本”

小说获取本身可能存在不同内容结果，例如：

- 原文
- 去敏感化后的原文
- 不去敏感化的原文
- AI1 文
- AI2 文
- 以后小说获取继续增加的其它版本

批量工厂不重新决定使用哪个版本，而是接收小说获取本次实际送入的那个版本，并保留其完整内容。

建议概念：

- `sourceVariant`：本次来自小说获取的内容版本类型。
- `sourceContentFull`：该版本的完整内容，是不可被批量工厂二次编辑直接覆盖的来源真值。

### 4.2 内容范围 = 前 N 条有效正文，只决定前贴生产区

`内容范围：5`：忽略空白行，取前 5 条有效正文。  
`内容范围：10`：忽略空白行，取前 10 条有效正文。  
空行不计数。

```text
sourceContentFull
↓
按原始位置识别有效正文
↓
内容范围 N
↓
sourceFrontContent = 前 N 条有效正文
sourceRemainder = 第 N 条有效正文之后的剩余完整内容
```

小说列表里“原文/内容”的当前生产展示区，可以展示这个范围内的内容，而不是把完整来源正文真的裁掉。

### 4.3 支持二次编辑

用户可以直接编辑内容范围内展示的前贴文本，保存为独立工作文本：

`workingFrontContent`

它用于当前小说的视频生产，不覆盖 `sourceContentFull`。

### 4.4 “爆款”是前贴文本的 AI 改写动作

```text
当前前贴文本
↓ 点击【爆款】
AI生成爆款开头 / 爆款版本
↓
展示改写结果
↓
用户点击【替换】
↓
workingFrontContent = 爆款结果
```

如果用户不点击替换，当前工作文本保持不变。

因此“原文直转 / 爆款开头”不再是两个互斥的大生产模式；新版是：来源版本 + 内容范围 + 手动二次编辑 / 爆款候选替换。

### 4.5 “改文 / 不改文”控制的是121发布正文，不控制视频是否使用改写文本

无论开关是什么，只要用户已经二次编辑或接受爆款替换，`workingFrontContent` 都可用于视频生产。

#### 不改文

```text
视频生产：workingFrontContent
121正文：sourceContentFull
```

#### 改文

```text
视频生产：workingFrontContent
121正文：workingFrontContent + sourceRemainder
```

也就是只替换原来被内容范围覆盖的前 N 条有效正文，后面正文继续接小说获取保存的剩余完整内容。

### 4.6 爆款是否上传不再单独增加开关

- 爆款生成后未替换 → 不影响当前工作文本。
- 爆款替换成功 → 成为 `workingFrontContent`。
- 不改文 → 爆款内容只做视频，121仍传 `sourceContentFull`。
- 改文 → 爆款内容替换前贴段，并与 `sourceRemainder` 拼接上传121。

### 4.7 数据必须可逆，禁止破坏性覆盖来源正文

至少保留这些概念：

```text
sourceVariant
sourceContentFull
contentRangeN
sourceFrontContent
sourceRemainder
workingFrontContent
publishRewriteEnabled
publishContent
```

`publishContent` 在上传前根据开关计算，不覆盖 `sourceContentFull`。

### 4.8 与旧 maxTxt 区分

小说获取旧 `maxTxt / 截取字数` 是按字数；批量工厂 `内容范围：5 / 10 / ...` 是按有效正文行数，两者不是同一语义。

## 6. 引擎配置（只管模型 / 运行参数）

顶部 Tab：

`[模型配置] [发布统一]`

模型配置：

- 视频：视频模型 / VIDEO 时长 / 画幅 / 匹配音频
- 图片：图片模型
- 文本：文本模型

批量工厂不填写 API Key / personal_api 凭据；凭据由个人中心 / 管理端负责，批量工厂只选择账号已授权模型。

业务层只决定“应该传什么”；供应商语法、参考图上限、时长档位、画幅等由 provider adapter / capability 层转换。禁止业务数据写死 `@图片1`；不兼容必须显式提示，不能静默丢数据。

### 6.1 配置继承与单分镜 / 单 VIDEO Override（已确认）

保留单分镜 / 单 VIDEO 独立覆盖设置。

默认情况下，一个分镜继承当前小说 / 当前作品已经生效的引擎配置；只有用户对这个分镜明确修改的字段，才形成该分镜自己的 override。

当前已明确允许单分镜覆盖：

- 视频模型
- VIDEO 时长 / 时长上限
- 画幅

例如作品统一配置：

```text
视频模型：模型A
VIDEO时长：≤10s
画幅：9:16
```

用户切到分镜03 / VIDEO03 后，可以单独改成：

```text
VIDEO03
视频模型：模型B
VIDEO时长：≤15s
画幅：16:9
```

结果：

```text
VIDEO01 → 继续继承模型A / ≤10s / 9:16
VIDEO02 → 继续继承模型A / ≤10s / 9:16
VIDEO03 → 使用自己的模型B / ≤15s / 16:9
VIDEO04 → 继续继承模型A / ≤10s / 9:16
```

单分镜修改不能反向覆盖整本小说或作品统一设置。

生效优先级概念上为：

```text
作品统一配置
↓
单书 override（若有）
↓
单分镜 / 单VIDEO override（若有）
↓
得到 effectiveEngineConfig
```

未被单分镜覆盖的字段继续向上继承，不复制整套配置造成后续难以维护。

是否还允许单分镜覆盖“匹配音频”等其它字段，后续再单独确认；本轮只锁定视频模型、VIDEO时长、画幅三项。

## 8. 固定开头（单个视频 / 多个视频语义已确认）

固定开头与“爆款”完全不是一回事：

- **爆款**：改当前前贴文字内容。
- **固定开头**：控制最终哪些分镜被真正转成视频，以及首个视频的目标格式 / 时长。

### 8.1 单个视频：所有分镜 Prompt 正常生成并保留，只执行 VIDEO01

无论内容范围是 10 行还是 50 行，AI 仍然正常分析全部当前生产文本，并产出它原本应有的全部分镜 Prompt。

```text
分镜01 Prompt
分镜02 Prompt
分镜03 Prompt
分镜04 Prompt
```

若：

```text
固定开头 = 单个视频
VIDEO格式/时长 = 10s
```

媒体阶段：

```text
分镜01 Prompt → VIDEO01（10s目标）
分镜02 Prompt → 保留，不执行视频生成
分镜03 Prompt → 保留，不执行视频生成
分镜04 Prompt → 保留，不执行视频生成
```

如果选择15s，则仍只执行VIDEO01，只是目标改为15s。

锁定：**AI推理层完整生成并保存分镜；“单个视频”只在媒体执行层限制为 VIDEO01。**

### 8.2 多个视频：正常逻辑，按当前生产文本正常得到的全部分镜执行

不填写固定数量，也不增加额外停止条件。

```text
当前生产文本
↓
AI正常分析
↓
得到几个有效分镜
↓
就执行几个 VIDEO
```

例如得到4个分镜：

```text
分镜01 → VIDEO01
分镜02 → VIDEO02
分镜03 → VIDEO03
分镜04 → VIDEO04
```

得到7个就生产VIDEO01～VIDEO07；得到2个就生产VIDEO01～VIDEO02。

最终区别：

```text
单个视频 = AI照常得到全部分镜，媒体层只执行VIDEO01
多个视频 = AI照常得到全部分镜，媒体层执行全部分镜/VIDEO
```

├─ 分镜02 → VIDEO02

## 10. VIDEO 目标时长 / 请求时长 / 实际时长（硬规则）

`≤10s / ≤15s` 是单个 VIDEO 的能力上限，不是必须生成满。

区分：

- `targetDurationSec`：AI / 业务目标
- `requestedDurationSec`：真正发给 provider
- `actualDurationSec`：provider 成品真实时长

目标6s、模型输出10s → 接受10s，不裁剪当前单段。模型仅支持固定档位时，由 adapter 选择可用档位；实际时长仍按真实结果记录。

## 11. 人物 / 场景 / 道具：有图不用词（硬规则）

| 当前分镜引用对象 | 对象图存在 | 基础设置开启 | 最终输入 |
|---|---|---|---|
| 是 | 是 | 是 | 只传图片，不传该对象文字 Prompt |
| 是 | 是 | 否 | 只传图片，不传该对象文字 Prompt |
| 是 | 否 | 是 | 传该对象文字 Prompt |
| 是 | 否 | 否 | 什么都不传 |
| 否 | 任意 | 任意 | 什么都不传 |

这里的“基础设置”规则针对**最终视频生成链路中的文字回退**；基础设置不控制已有图片上传，也不控制第16章“画面图片生成”链路的资产文字补齐。

---

## 12. 画面提示词永远不直接进入视频生成（硬规则）

`画面提示词` 只用于生成 `画面图片`。

视频生成：

- 有画面图片 → 上传画面图片
- 只有画面提示词、没有画面图片 → 忽略画面提示词
- 绝不把画面提示词编译进视频 Prompt

旧 `visualPrompt → compiledPrompt → 视频模型` 语义必须废弃 / 重构。

---

## 13. 系统自动判断文生 / 图生

不增加用户选择“文生视频 / 图生视频”。系统按当前分镜已有资产自动决定：

- 有画面图片 → 使用
- 当前分镜引用的人物 / 场景 / 道具有图 → 使用相关图
- 某对象无图 → 仅基础设置允许时使用该对象文字 Prompt
- 无视觉图 → 实际走纯文本视频

同一分镜允许多张相关参考图，例如：

`画面图片 + 女主图 + 男主图 + 客厅图 + 手机图`

超过模型上限时由 capability / adapter 显式处理，业务层不能擅自静默丢图。

## 15. 跟随音频：两个独立能力（已确认）

两个都关、单独开任意一个、两个同时开都允许。

### 15.1 生成阶段按音频时长约束

AI按真实音频总长规划分镜目标时长；provider 实际输出可以不同，不按单段强裁。

### 15.2 合成阶段按音频时长匹配

`自动倍率 = 视频实际总时长 ÷ 音频实际时长`

- >1.0x：加速
- =1.0x：原速
- <1.0x：允许慢放拉长

用户手动修改倍率时，直接覆盖自动推荐值，不叠乘。

TTS / 音频主要用于时长和节奏，不默认混入最终视频音轨。

## 16. 画面图片生成（已确认）

画面图是独立于最终视频 Prompt 编译的一条生成链路。

对当前分镜引用的人物 / 场景 / 道具逐个判断：

- 对象有对应图片 → 使用该图片；按照“有图不用词”，不重复注入同一对象的文字 Prompt。
- 对象没有对应图片，但有对应资产文字 Prompt → **直接使用该资产 Prompt 补齐视觉信息。**
- 对象既没有图片也没有文字 Prompt → 该对象无法提供视觉约束，不能凭空伪造。
- 再叠加当前分镜的 `画面提示词`。
- 最终交给当前有效图片模型生成 `画面图片`。

例如当前分镜需要“女主 + 卧室”，两者都没有图，但都有资产 Prompt：

```text
女主人物 Prompt
+
卧室场景 Prompt
+
当前分镜画面提示词
↓
图片模型
↓
当前分镜画面图片
```

### 16.1 画面图的无图文字回退不受“基础设置”控制

这一点已确认：**画面图生成时，只要当前分镜确实引用该对象、该对象没有图片、但存在对应资产 Prompt，就使用对应资产 Prompt。**

`约束设置 → 基础设置` 不控制这条回退逻辑。

基础设置只负责最终视频生成阶段的文字回退：

```text
画面图生成：
对象有图 → 用图
对象无图但有Prompt → 用Prompt补齐
不看基础设置开关

最终视频生成：
对象有图 → 用图，不用该对象Prompt
对象无图 → 是否使用该对象Prompt，由基础设置决定
```

因此不能因为用户关闭了最终视频的“基础设置”，就导致画面图生成缺失必要的人物 / 场景 / 道具信息。

### 16.2 批量“画面图”的执行范围

批量操作里的“画面图”只处理**实际存在画面提示词**的分镜。没有画面提示词的分镜，不因为批量按钮而凭空生成画面图。

## 21. 当前 v88 Git 现状与新版冲突

- `BatchFactoryPageV11.jsx` 是兼容入口；实际旧 V11 UI 在 `batch-factory-v11/BatchFactoryV11UiPage.jsx` 一带。
- 旧工作台仍有状态筛选、拖拽/缩放/隐藏、Hook/Director、visualPrompt 等旧逻辑；这些是现状，不代表新版继续沿用。

- 现有 scoped settings 已有 `系统默认 → 批次 → 当前小说 → 单VIDEO` override 的旧基础；新版已确认继续保留“单分镜 / 单VIDEO override”能力，但具体 UI 和字段必须按本文件新版规则收口，不能原样继承旧混合设置。
- 旧 BatchManager 的手动创建批次与新版自动创建个人作品冲突，应退出必经流程。
- 水货已有 project / 个人作品 / studio 生命周期，批量工厂优先对标复用。

## 22. 已废弃 / 被新规则覆盖的旧思维

- 大一统“生产统一设置” → 拆成引擎配置 + AI推理。
- “画面提示词直接进视频 Prompt” → 废弃。
- “有对象图仍重复注入对象 Prompt” → 废弃。
- “音频比视频长不允许慢放” → 废弃。
- “状态中心 + 自由布局是主页面核心” → 改为水货式一行一本小说。
- “只支持失败 VIDEO 重试” → 改为支持选书并按失败阶段重试。
- “Intake 后必须手动创建批次” → 废弃。
- “原文直转 / 爆款开头是两个互斥大生产模式” → 改为来源版本 + 内容范围 + 二次编辑 / 爆款候选 + 改文 / 不改文发布决策。
- “固定开头=单个视频时 AI 只生成一个分镜 Prompt” → 废弃；现规则是所有分镜 Prompt 正常生成并保留，媒体执行只跑 VIDEO01。
- “固定开头=多个视频需要另外填写生成数量 / 停止数量” → 废弃；多个视频就是正常逻辑，AI正常得到多少分镜就执行多少个 VIDEO。
- “单分镜不能独立调整引擎配置” → 废弃；已确认保留单分镜 / 单VIDEO override。
- “画面图生成的无图资产文字回退受基础设置开关控制” → 废弃；画面图链路无图时只要有对应资产 Prompt 就使用，基础设置只影响最终视频链路。
