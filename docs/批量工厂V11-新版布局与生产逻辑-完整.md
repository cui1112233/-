- 管理端：React + Ant Design。
- 用户端：React + Ant Design。

## 2. 新版总体方向

新版批量工厂直接参考“水货生产”的操作习惯：

`水货生产：一行一个分镜 → 批量工厂：一行一本小说`

批量工厂 V11 继续使用自己的业务数据和 API，不把水货生产内部业务逻辑硬绑进来；但 UI 组件、切换习惯、生产操作体验可以复用。

顶部主入口当前锁定：

`小说列表 / 引擎配置 / AI推理 / 批量操作 / 取消操作 / 任务/日志 / 上传121`

其中：

- 小说列表：对应水货生产的“分镜调整”入口。
- 引擎配置：保持原名。
- AI推理：保持原名，不改成“AI导演”。
- 批量操作：只承担真实媒体生成、重试、合并。
- 上传121：替换水货生产“导出剪映”的入口位置。
- “人物场景预设”不是全局顶部入口，而是单书工作区功能。
- 原先叫“资产/导演”的主列，新版直接叫“预设”。

## 3. 小说获取原文与批量工厂“内容范围”（已确认）

### 3.1 小说获取保存的原文不因批量工厂而改变

小说获取已经得到并保存的原文是来源真值。进入批量工厂以后，**不能因为“内容范围”而改写、截断或覆盖小说获取保存的原文。**

例如小说获取里某本书当前保存的是约 4000 字：

```text
小说获取原文 = 4000 字
↓
进入批量工厂
↓
原文仍然保持 4000 字
```

批量工厂的“内容范围”只决定**这次拿多少有效正文去做视频**，不改变源内容。

### 3.2 内容范围 = 前 N 条有效正文行

例如：

`内容范围：5`

含义：忽略空白行，取小说原文前 5 条有内容的正文行，作为本次视频生产输入。

`内容范围：10`

含义：忽略空白行，取小说原文前 10 条有内容的正文行，作为本次视频生产输入。

示意：

```text
小说获取完整原文（保持不变）
↓
过滤空白行
↓
内容范围 = 5
↓
取前 5 条有效正文
↓
仅这 5 条进入本次批量工厂视频生产链路
```

空白行不计数。

### 3.3 内容范围只影响视频生产输入

裁剪后的生产文本用于当前批量工厂这一轮的：

- 资产提取
- 剧本/分镜推理
- 视频提示词生成
- 画面提示词生成（如果用户选择生成）
- 后续对应的人物/场景/道具、画面图与视频生产

它不是“重新保存一份截断小说”，也不是“把小说获取原文替换成前 5 行”。

### 3.4 与旧 `maxTxt / 截取字数` 区分

当前 v88 的 Legacy `NovelFetchPage.jsx` 仍能看到 `maxTxt / 截取字数` 这类按字数截取的旧逻辑。新版批量工厂的“内容范围 = 5 / 10”是按**有效正文行数**取前 N 行，两者不是同一个字段语义，后续实现不能直接复用 `maxTxt` 充当新版内容范围。

### 3.5 121 上传使用完整来源内容，不使用生产裁剪文本

最终发布到 121 时，上传的是：

```text
批量工厂最终视频
+
小说获取已经保存的完整内容
```

例如：

```text
小说获取原文 = 4000 字
批量工厂内容范围 = 5
↓
只用前 5 条有效正文做视频
↓
得到最终视频
↓
上传121：最终视频 + 原来的完整 4000 字内容
```

**不能把“前 5 行生产文本”当作最终 121 上传正文。**

小说内容上传到 121 的具体网络/提交逻辑，继续复用小说获取已经存在的 121 上传链路；批量工厂主要新增的是把“最终视频”与该书原有完整内容在发布阶段正确绑定到同一本书。

## 4. 单书配置

每一本小说都有自己的三块能力：

- 人物场景预设
- 引擎配置
- AI推理

推荐数据继承模型：默认跟随全局/批次，只有用户真正修改的字段才形成当前书 override。

## 5. 单书 → 人物场景预设

这是水货生产同名能力在“一本小说”层面的直接对应：

`左侧 Prompt / 右侧图片`

负责当前书实际产生的人物、场景、道具结果，包括查看、编辑、保存和重新生成 Prompt，以及查看、生成、替换对应图片。

职责边界：

`AI推理 → 资产设置 = 批量/全局生成资产 Prompt 的规则`

`单书 → 人物场景预设 = 当前书真正生成出来的资产 Prompt + 资产图片`

两者不能混为一块设置。

## 6. 引擎配置

引擎配置只负责模型与运行参数，不放 Prompt。

顶部两个 Tab：

`[模型配置] [发布统一]`

点击 Tab 后替换卡片内容，不把“发布统一”堆在模型配置下面。

### 6.1 模型配置

视频：

- 视频模型
- VIDEO 时长
- 画幅
- 匹配音频

图片：

- 图片模型

文本：

- 文本模型

### 6.2 API 配置边界

批量工厂不出现 API Key 输入框，不在这里编辑 personal_api 凭据。API 凭据由个人中心/管理端负责；批量工厂只选择当前账号已授权、已可用的模型。

### 6.3 Provider 能力层

业务层只负责决定“应该传什么”：参考图、文字 Prompt、目标/请求时长、画幅和约束。

供应商专用格式由 provider adapter / capability 层转换，包括参考图数量、时长档位、画幅、negative prompt 等。

禁止在业务数据里写死 `@图片1` 之类供应商语法。模型能力不兼容时必须显式处理/提示，不能静默丢参考图。

## 7. AI推理

AI推理只负责 Prompt 与 Prompt 相关推理规则；模型选择全部归引擎配置。

固定四个 Tab：

1. 资产设置
2. 约束设置
3. 视频设置
4. 画面设置

### 7.1 资产设置

- 人物场景提示词
- 范围
- 取消
- 确定生成

它是人物/场景/道具 Prompt 的全局/批量生成规则。

### 7.2 约束设置

必须直接复用“剧本生成”现有约束设置 UI 与逻辑，不另造 Batch Factory 专用约束体系。

现有约束具体以剧本生成实际代码为准，包括基础设置、画面前缀、画质约束、画面限制、负面提示词等；只有启用项参与最终编译。

### 7.3 视频设置

- 固定开头：当前只确认 `单个视频 / 多个视频`
- 视频提示词
- 范围
- 取消
- 确定生成

不要自行增加未确认模式。

### 7.4 画面设置

- 画面提示词
- 范围
- 取消
- 确定生成

画面提示词默认可以不选择、不生成。

### 7.5 AI推理预设

右上角：齿轮 + `保存预设`。

支持单模块“确定生成”、保存/重命名预设，以及基于保存预设“统一生成”四块 AI 推理。

“范围”下拉最终选项还未锁定，后续再确认。

## 8. 分镜与 VIDEO 关系（已确认）

逻辑直接对齐“剧本生成”的分镜卡：**一个分镜就是一个 VIDEO 的生产标准，分镜与 VIDEO 是 1:1。**

```text
一本小说
├─ 分镜01 → VIDEO01
├─ 分镜02 → VIDEO02
├─ 分镜03 → VIDEO03
└─ ...
```

不是 VIDEO 内再嵌套多个 Shot。

左右箭头是在切换分镜卡，也就是切换 VIDEO01 / VIDEO02 / VIDEO03 对应的生产单元。

切换分镜时必须同步切换：

- 当前预设
- 当前人物 / 场景 / 道具引用
- 视频提示词
- 画面提示词（如果有）
- 画面图片（如果有）
- 对应 VIDEO 结果
- 当前分镜任务状态

## 9. 分镜目标时长与实际 VIDEO 时长（已确认）

`VIDEO 时长 ≤10s` 的意思是单个分镜/VIDEO 的上限能力，不代表每个 VIDEO 都必须生成满 10 秒。

例如：

- 分镜01需要 6s → 目标 6s
- 分镜02需要 8s → 目标 8s
- 分镜03需要 10s → 目标 10s

建议数据层区分：

- `targetDurationSec`：AI / 业务希望该分镜多长
- `requestedDurationSec`：真正发给 provider 的时长参数
- `actualDurationSec`：provider 返回成品的真实时长

如果 Prompt/目标要求 6s，但模型最终返回 10s：接受这 10s，不裁剪当前单段，也不把当前单段强制压回 6s。

如果 provider 只允许离散档位，例如 5s / 10s，而目标是 6s，则使用能覆盖目标的可用档位（例如 10s）生成，仍不裁剪。

最终整体时长问题交给合成阶段的跟随音频/倍率能力处理。

## 10. 人物 / 场景 / 道具：有图不用词（硬规则）

| 分镜引用对象 | 对象图片存在 | 基础设置开启 | 最终输入 |
|---|---|---|---|
| 是 | 是 | 是 | **只传图片，不传该对象文字 Prompt** |
| 是 | 是 | 否 | **只传图片，不传该对象文字 Prompt** |
| 是 | 否 | 是 | 传该对象文字 Prompt |
| 是 | 否 | 否 | 什么都不传 |
| 否 | 任意 | 任意 | 什么都不传 |

适用于人物、场景、道具。

**基础设置只控制“没有对象图时，是否允许用对象文字 Prompt 回退”，不控制已有对象图是否上传。**

锁定示例：上传了女主图，就不要再把女主人物 Prompt 注入同一次生成。

## 11. 画面提示词与画面图片（硬规则）

画面提示词只负责生成画面图片：

`当前分镜视觉资产 + 画面提示词 → 画面图片`

视频生成时：

- 有画面图片 → 上传画面图片。
- 只有画面提示词、没有画面图片 → 完全忽略画面提示词。
- 画面提示词绝不能直接编译进视频 Prompt。

因此旧版如果存在 `visualPrompt → compiledPrompt → 视频模型` 的语义，新版必须废弃。

如果某分镜没有生成过画面提示词，主界面也不要强行展示“画面提示词” Tab，只显示视频提示词即可。

## 12. 系统自动判断文生视频 / 图生视频

不要让用户选择“使用画面图片 / 直接使用人物场景参考图 / 文生视频 / 图生视频”。

系统根据当前分镜真实存在的媒体自动判断：

- 有画面图片 → 使用画面图片。
- 当前分镜引用的人物/场景/道具存在图片 → 同时使用这些相关图片。
- 某个对象没有图 → 只有基础设置允许时，才使用该对象文字 Prompt。
- 完全没有视觉图片 → 实际走纯文本视频路径。

## 13. 同一分镜允许多张相关参考图

例如当前分镜需要：

`女主 + 男主 + 客厅 + 手机`

如果四张对象图都存在，它们都属于当前分镜相关视觉参考。

如果当前分镜另外还有画面图片，则业务层希望传递的视觉集合可以是：

`画面图片 + 女主图 + 男主图 + 客厅图 + 手机图`

不要由业务层擅自只保留其中一张。最终 provider 能否全部接收，由 capability / adapter 层处理。

## 14. 视频最终输入编译（当前锁定）

```text
当前分镜 / VIDEOxx
↓
读取当前分镜 presetRefs
↓
逐个对象判断
├─ 有图 → 图片 only
├─ 无图 + 基础设置 ON → 对象文字 Prompt
└─ 无图 + 基础设置 OFF → 不参与
↓
+ 当前分镜画面图片（如果已生成）
+ 当前分镜视频提示词
+ 生成阶段音频时长约束（如果开启）
+ 约束设置中其他启用规则
↓
绝不加入画面提示词
↓
解析有效引擎配置（全局/批次 → 单书 override）
↓
video provider adapter
↓
VIDEOxx
```

## 15. 跟随音频：两个独立能力（已确认）

两个能力是独立开关，可以两个都关、只开生成阶段、只开合成阶段、或两个同时开。

### 15.1 生成阶段按音频时长约束

读取真实音频长度，让 AI 在分镜规划阶段尽量以音频总时长为目标分配各分镜时长。

例如音频 28s，AI 可以规划：`6 + 8 + 7 + 7 = 28s`。

它只是生成目标，不保证 provider 成品严格等于 28s。某个分镜目标 6s，provider 实际返回 10s，仍接受 10s，不裁剪当前单段。

### 15.2 合成阶段按音频时长匹配

合成时以所有 VIDEO 的 `actualDurationSec` 为准，计算：

`自动倍率 = 视频实际总时长 ÷ 音频实际时长`

例如：

- `35s ÷ 28s = 1.25x` → 加速压缩到接近 28s。
- `25s ÷ 28s = 0.892857x` → 允许慢放拉长到接近 28s。

新版明确允许：

- `> 1.0x` = 加速
- `= 1.0x` = 原速
- `< 1.0x` = 慢放

旧版“音频比视频长就异常、不自动慢放”的规则正式废弃。

### 15.3 用户可以手动覆盖倍率

自动倍率只是系统推荐值。

例如系统推荐 `1.42857x`，用户改成 `1.35x`，最终合成直接使用 `1.35x`；不是在自动倍率上再乘 `1.35`。

### 15.4 两阶段可以一起使用

```text
音频 28s
↓
生成阶段先让 AI 尽量规划为 28s
↓
provider 实际总视频 = 31s
↓
合成阶段自动建议 31 / 28 = 1.107x
↓
用户可接受 1.107x，也可手动改成其他倍率
```

## 16. 画面图片生成

当当前分镜需要人物/场景/道具时：

- 对象有图 → 以对象图作为参考，不重复注入同对象文字 Prompt。
- 对象没图 → 使用对应对象文字预设作为参考文本（最终是否还受“基础设置”开关约束，后续继续确认图像生成链路的精确边界）。
- 再加上当前分镜的画面提示词生成画面图片。

批量“画面图”只处理真正有画面提示词的分镜。

## 17. 批量操作（已确认）

固定包含：

- 人物场景图
- 画面图
- 生视频
- 重试
- 合并

边界：

`AI推理 = 产生 Prompt / 规则`

`批量操作 = 真正消耗模型资源执行媒体任务`

具体：

- 人物场景图：根据资产 Prompt，用有效图片引擎生成人物/场景/道具图片。
- 画面图：当前分镜参考资产 + 画面提示词 → 画面图片。
- 生视频：执行第 14 节最终输入编译。
- 重试：支持用户自己勾选书。
- 合并：按分镜/VIDEO 正确顺序合并，不重新生成 Prompt/图片。

### 17.1 重试

不能只有“重试全部失败”。必须支持：

`勾选小说03 / 小说07 / 小说12 → 重试选中的3本`

推荐执行粒度：失败在哪个阶段，就只重试失败阶段；已经成功的步骤不重复消耗资源。

## 18. 合并

当前确认：

- 按分镜/VIDEO 顺序合并。
- 以实际成品 VIDEO 时长为依据。
- 合成阶段可以应用自动跟随音频倍率或用户手动倍率。
- 某个 VIDEO 被重新生成后，旧合并结果应该失效并允许重新合并。
- 原始生成 VIDEO 不因为重新合并而删除。

仍待继续确认：失败片段是否允许跳过、整书合并是否必须 all-or-nothing、输出命名、重复合并版本历史等。

## 19. 上传121（已确认内容来源边界）

上传121占据水货生产“导出剪映”的入口位置。

发布配置进入：

`引擎配置 → 发布统一`

### 19.1 上传内容

对每一本书，上传121的业务组合是：

```text
该书批量工厂最终视频
+
该书小说获取保存的完整原文/内容
```

批量工厂“内容范围”只影响视频怎么做，不影响最终上传正文。

### 19.2 复用小说获取现有正文上传逻辑

小说获取已经具备“把内容上传/提交到121”的既有链路。新版批量工厂不重新发明一套正文提交协议；后续实现应优先复用/调用小说获取现有 121 内容提交能力，再把批量工厂最终视频正确绑定进去。

后续仍需核对现有 Git 中 121 的精确接口、浏览器桥接、状态回读和视频字段，确保不是复制两套提交逻辑。

### 19.3 仍待确认的 121 协议细节

- 最终真实 API / 浏览器桥接合同
- 视频字段与文件命名
- `{bookId}.mp4 + 完整内容` 的具体请求形式
- “请求已受理”与“真正发布成功”的状态区别
- accepted_pending / confirmed / submitted 状态映射
- 回读确认
- 上传失败重试
- 发布统一的全部字段

## 20. 小说获取 → 批量工厂（来源数据边界已确认）

小说获取是上游，保存完整来源内容。批量工厂不重新抓小说，也不再次让用户填写 bookId。

来源至少包括：

- sourceTaskId
- bookId
- 书名
- 平台
- 完整 TXT / 原文
- metadata

进入批量工厂后，应同时保留两个概念：

```text
sourceContent = 小说获取完整原文（不可被内容范围覆盖）
productionContent = 根据“内容范围”从 sourceContent 过滤空白行后取前 N 条有效正文
```

这样后续不会把“制作视频用的前 N 行”和“最终121需要上传的完整内容”混在一起。

当前 v88 `BatchFactoryV11BatchManager.jsx` 已体现 Intake 接收 `sourceTaskId / Book ID / 标题 / 平台 / TXT / 来源元数据`，并强调批量工厂不重新抓小说；但新版“内容范围 → productionContent”的数据层仍需正式补齐。

## 21. 当前 v88 Git 核对结果（2026-09-11）

### 21.1 V11 页面入口

### 21.7 Legacy 小说获取存在 `maxTxt`，但不是新版内容范围

当前 Legacy `NovelFetchPage.jsx` 能看到按字数截取的 `maxTxt`。它与“批量工厂按有效正文行数选择 5 / 10”不是同一语义，后续不能混用。

## 22. 已明确废弃 / 冲突的旧思维

- 旧“大一统生产统一设置” → 新版拆成“引擎配置 + AI推理”。
- 旧 `画面提示词 → 最终视频 Prompt` → 废弃。
- 旧“有资产图仍重复注入同对象文字 Prompt” → 废弃。
- 旧“音频比视频长就异常、不允许慢放” → 废弃；新版允许 `<1x`。
- 旧单书设置把模型、Prompt、发布等全部揉在一个大表单 → 新版按职责拆分。
- 旧状态中心主导页面 → 新版用水货生产式“一行一本小说”，但状态能力不能丢。
- 旧仅 VIDEO 级批量媒体任务 → 新版覆盖人物场景图、画面图、生视频、重试、合并。
- 旧只支持失败 VIDEO 重试 → 新版必须支持选书 + 失败阶段精确重试。
- 旧 `visualPrompt` 作为视频编译输入 → 与新版硬规则冲突，后续必须重构。
- 把“内容范围”理解成修改/截断小说获取原文 → 废弃。内容范围只生成 `productionContent`，完整 `sourceContent` 必须保留。
- 把“内容范围生产文本”上传到121替代完整小说内容 → 废弃。121正文来源仍是小说获取保存的完整内容。
