- 管理端：React + Ant Design。
- 用户端：React + Ant Design。

- 开发前先走 Superpowers 头脑风暴 / 设计确认，再进入实现。

## 2. 产品定位：批量工厂是“水货生产”的小说前贴版本（已确认）

用户已明确：批量工厂本质上可以视为水货生产的一个兄弟版本 / 生产模式。

- **水货生产**：主要做漫剧解说。
- **批量工厂**：主要做小说前贴。

因此两者在产品壳层、个人作品、项目进入方式、工作台切换习惯、预设 / Prompt / 图片 / 视频生产体验上，应尽量对标和复用水货生产已经成熟的逻辑；但小说前贴特有的业务规则、小说获取来源、121 发布、批量多书生产等仍由批量工厂自己的业务逻辑负责。

核心映射：

`水货生产：一行一个分镜 → 批量工厂：一行一本小说`

不能理解为“完全复制水货数据结构”，而应理解为：**优先复用成熟交互和作品生命周期，再替换成小说前贴的业务数据与生产链路。**

当前顶部主入口锁定：

`小说列表 / 引擎配置 / AI推理 / 批量操作 / 取消操作 / 任务/日志 / 上传121`

其中：

- 小说列表：对应水货生产里的“分镜调整”。
- 引擎配置：保持原名。
- AI推理：保持原名，不改成“AI导演”。
- 批量操作：只负责真实媒体生成、重试、合并。
- 上传121：替换水货生产“导出剪映”的位置。
- “人物场景预设”不是全局顶部入口，而是单书工作区功能。
- 原先叫“资产/导演”的主列，新版直接叫“预设”。

## 3. 小说获取 → 批量工厂 → 个人作品生命周期（已确认）

### 3.1 进入批量工厂后直接进入小说列表

新版不再保留旧 V11 的：

`Intake → 待建立批次 → 用户点击创建批次 → 才进入工作台`

用户从小说获取把内容送入批量工厂以后：

```text
小说获取
↓
进入批量工厂
↓
系统自动创建对应作品 / 文档
↓
直接进入小说列表
```

**不再要求用户额外点击“创建 V11 批次”。**

### 3.2 自动创建作品 / 文档，并放入“个人作品”

行为对标水货生产：进入生产工作流时自动形成可持续保存的作品 / 项目文档，该作品应进入统一的 **个人作品** 体系。

用户以后可以从个人作品重新打开，不依赖一次性的临时页面状态。

自动创建只表示：

- 建立作品 / 项目记录；
- 保存来源与小说列表关系；
- 打开批量工厂工作台。

**自动创建作品不等于自动执行 AI、资产生成、图片生成、视频生成或上传121。** 这些仍由用户后续设置并主动触发。

### 3.3 个人作品卡片：生产模式标签 + 文档名 + 可重命名

个人作品中的每个作品卡片，左上角显示生产模式标签，用于区分同一个作品库里的不同生产方式：

- `批量工厂`
- `水货生产`

标签下面 / 主标题位置才显示真正的作品文档名，例如：

```text
[批量工厂]
2026-09-11-001
```

或：

```text
[水货生产]
我的漫剧作品
```

文档名允许用户重命名。重命名只改变作品显示名称，不能改变内部 projectId、bookId、任务关系、来源关系或 121 发布绑定。

### 3.4 批量工厂标准粒度：30 本小说 = 1 个作品文档

“100 本小说”只是一种举例，不是批量工厂单文档的标准容量。

新版正式规则：**一般按 30 本小说组成 1 个批量工厂作品文档。**

例如：

- 1～30 本 → 1 个文档；
- 31～60 本 → 2 个文档；
- 61～90 本 → 3 个文档；
- 91～120 本 → 4 个文档。

如果小说获取一次实际转入 100 本：

```text
100 本
↓
自动拆分
├─ 2026-09-11-001 → 30 本
├─ 2026-09-11-002 → 30 本
├─ 2026-09-11-003 → 30 本
└─ 2026-09-11-004 → 10 本
```

每个文档都作为个人作品里的独立卡片存在，均带 `批量工厂` 标签，并均允许独立重命名。

用户不需要手动先创建这些文档；小说获取进入批量工厂时，系统按 30 本一档自动切分并创建。

### 3.5 同一次拆分出来的多个文档：初始配置一致，后续独立修改

如果同一次小说获取转入的数据被拆成多个批量工厂文档，例如 100 本拆成 4 个文档，则创建时这些文档继承同一套初始配置，包括当前适用的：

- 引擎配置；
- AI推理配置；
- 其他作品级统一设置。

但创建完成后，各文档成为独立作品：

```text
001 修改引擎配置
≠ 自动修改 002 / 003 / 004
```

也就是说：**同批创建时复制同一套初始配置，之后各文档独立保存、独立修改，不互相联动。**

这样既方便一次导入多本时快速建立一致基线，又避免后续用户只想调整某一个 30 本文档时影响其它文档。

### 3.6 与当前 v88 水货代码的对标依据

当前 v88 的水货生产已经采用 `project / 个人作品 / studio` 思路：个人作品里展示 project 卡片，点击后进入作品内部工作台；批量工厂新版应优先沿用这种作品生命周期，而不是继续旧 BatchManager 的手动“建批次仪式”。

实现层可考虑保留一个不可见的来源分组 ID，把同一次导入拆出的多个文档关联起来用于排查 / 追踪，但这属于实现建议，不作为用户可见交互要求。

## 4. 小说获取原文与批量工厂“内容范围”（已确认）

### 4.1 小说获取保存的完整内容永远不因批量工厂改变

小说获取已经得到并保存的原文是来源真值。进入批量工厂以后，不能因为“内容范围”而改写、截断或覆盖小说获取保存的原文。

例如：

```text
小说获取完整原文 ≈ 4000 字
↓
进入批量工厂
↓
完整原文仍然 ≈ 4000 字
```

概念上建议区分：

- `sourceContent`：小说获取保存的完整来源内容；
- `productionContent`：当前批量工厂根据“内容范围”临时得到的生产文本。

### 4.2 内容范围 = 前 N 条有效正文行

`内容范围：5` = 忽略空白行，取前 5 条有内容的正文行做本次视频。

`内容范围：10` = 忽略空白行，取前 10 条有内容的正文行做本次视频。

空白行不计数。

```text
sourceContent 完整原文
↓
过滤空白行
↓
内容范围 = N
↓
取前 N 条有效正文
↓
productionContent
```

### 4.3 内容范围只影响视频生产链路

`productionContent` 用于本次：

- 资产提取；
- 剧本 / 分镜推理；
- 视频提示词生成；
- 画面提示词生成（如用户启用）；
- 人物 / 场景 / 道具；
- 画面图；
- VIDEO 生成。

它不是重新保存一份截断小说，更不能覆盖小说获取保存的完整内容。

### 4.4 与旧 maxTxt 区分

当前 v88 Legacy 小说获取代码仍能看到 `maxTxt / 截取字数`，它是按字数截取。新版批量工厂“内容范围 = 5 / 10”是按**有效正文行**取前 N 行，二者不是同一语义，不能直接复用 `maxTxt` 当新版内容范围。

### 4.5 上传121必须使用完整来源内容

最终上传121：

```text
批量工厂最终视频
+
小说获取保存的完整 sourceContent
```

例如：

```text
sourceContent = 4000 字
内容范围 = 5
↓
只用前5条有效正文做视频
↓
得到最终视频
↓
上传121 = 最终视频 + 完整4000字内容
```

**绝不能把前 5 / 10 行 productionContent 当作最终121正文。**

小说内容上传到121的网络 / 提交逻辑优先复用小说获取已经存在的121链路；批量工厂新增的核心是把最终视频与同一本书的完整内容正确绑定。

## 5. 单书配置（已确认结构）

每一本小说都有自己的：

1. 人物场景预设
2. 引擎配置
3. AI推理

推荐继承模型：默认跟随全局 / 当前作品统一设置，仅用户真正修改的字段形成单书 override。

### 5.1 单书 → 人物场景预设

直接对标水货生产同名能力：

`左侧 Prompt / 右侧图片`

负责当前书真正生成出来的人物、场景、道具：

- 查看 / 编辑 / 保存 Prompt；
- 重新生成 Prompt；
- 查看图片；
- 生成图片；
- 替换图片。

职责边界：

`AI推理 → 资产设置 = 批量/全局生成资产 Prompt 的规则`

`单书 → 人物场景预设 = 当前书实际资产 Prompt + 资产图片`

## 6. 引擎配置（只管模型 / 运行参数）

顶部两个 Tab：

`[模型配置] [发布统一]`

点击后替换卡片内容，发布统一不是堆在模型配置下面。

### 6.1 模型配置

视频：

- 视频模型
- VIDEO 时长
- 画幅
- 匹配音频

图片：

- 图片模型

文本：

- 文本模型

### 6.2 API 凭据边界

批量工厂不出现 API Key 输入，不在这里配置 personal_api 凭据。API 凭据由个人中心 / 管理端配置；批量工厂只选择当前账号已经授权可用的模型。

### 6.3 Provider 能力层

业务层只决定：

- 应该传哪些参考图；
- 应该传哪些文本 Prompt；
- 目标 / 请求时长；
- 画幅；
- 约束。

供应商专用参数格式由 provider adapter / capability 层转换。

禁止在业务数据里写死 `@图片1` 等供应商语法；如果模型不支持所需参考图数量、时长档位或参数，必须显式处理 / 提示，不能静默丢数据。

固定四个 Tab：

1. 资产设置
2. 约束设置
3. 视频设置
4. 画面设置

### 7.1 资产设置

- 人物场景提示词
- 范围
- 取消
- 确定生成

这是全局 / 批量人物、场景、道具 Prompt 生成规则。

必须直接复用“剧本生成”现有约束设置 UI 与逻辑，不另造 Batch Factory 专用体系。

实际约束以现有剧本生成代码为准，包括基础设置、画面前缀、画质约束、画面限制、负面提示词等；只有启用项参与最终编译。

### 7.3 视频设置

- 视频提示词
- 范围
- 取消
- 确定生成

不要自行增加未确认模式。

### 7.4 画面设置

- 画面提示词
- 范围
- 取消
- 确定生成

### 7.5 AI推理预设

右上角：齿轮 + 保存预设。

支持：

- 单模块确定生成；
- 保存预设；
- 重命名；
- 保存后的“统一生成”。

## 8. 分镜与 VIDEO：1:1（硬规则）

**一个分镜就是一个 VIDEO 的生产标准。不存在 VIDEO 下再嵌套多个 Shot 的额外层。**

```text
一本小说
├─ 分镜01 → VIDEO01
├─ 分镜02 → VIDEO02
├─ 分镜03 → VIDEO03
└─ ...
```

左右箭头切换分镜卡，也就是切换 VIDEO01 / VIDEO02 / VIDEO03 对应生产单元。

切换分镜时必须同步切换：

- 当前预设；
- 当前人物 / 场景 / 道具引用；
- 视频提示词；
- 画面提示词（若有）；
- 画面图片（若有）；
- VIDEO 结果；
- 当前任务状态。

不能出现 Prompt 已切换到分镜3，但预设还停在分镜2。

如果某分镜从未生成画面提示词，则主界面不显示“画面提示词” Tab，只显示视频提示词。

## 9. VIDEO 目标时长、请求时长、实际时长（已确认）

`VIDEO 时长 ≤10s` 表示单个分镜 / VIDEO 的能力上限，不表示每个都必须生成10秒。

例如：

- 分镜01目标6s → 尽量生成6s；
- 分镜02目标8s → 尽量生成8s；
- 分镜03目标10s → 生成10s。

数据层建议明确区分：

- `targetDurationSec`：AI / 业务希望时长；
- `requestedDurationSec`：实际发给 provider 的时长参数；
- `actualDurationSec`：provider 返回成品真实时长。

如果目标6s而模型最终输出10s：接受10s，不裁剪当前单段。

如果模型参数只支持5s / 10s，而目标6s：选择可以覆盖目标的10s生成，不裁剪。

整体时长误差交由后续合成阶段处理。

## 10. 人物 / 场景 / 道具：有图不用词（硬规则）

| 当前分镜引用对象 | 对象图存在 | 基础设置开启 | 最终输入 |
|---|---|---|---|
| 是 | 是 | 是 | **只传图片，不传该对象文字 Prompt** |
| 是 | 是 | 否 | **只传图片，不传该对象文字 Prompt** |
| 是 | 否 | 是 | 传该对象文字 Prompt |
| 是 | 否 | 否 | 什么都不传 |
| 否 | 任意 | 任意 | 什么都不传 |

适用于人物、场景、道具。

**基础设置只控制“无图时是否允许文字 Prompt 回退”，绝不控制已有图片是否上传。**

锁定示例：上传女主图后，同一次生成不再重复注入女主人物 Prompt。

---

## 11. 画面提示词永远不直接进入视频生成（硬规则）

画面提示词只负责：

`当前分镜视觉资产 + 画面提示词 → 画面图片`

视频生成时：

- 有画面图片 → 上传画面图片；
- 只有画面提示词、没有画面图片 → 完全忽略该画面提示词；
- 画面提示词绝不能直接编译进视频 Prompt。

因此旧 `visualPrompt → compiledPrompt → 视频模型` 的语义在新版中必须废弃 / 重构。

---

## 12. 系统自动判断文生 / 图生，不给用户增加模式选择

不增加：

- 使用画面图片 / 直接使用人物场景参考图；
- 文生视频 / 图生视频。

系统根据当前分镜实际已有资产自动判断：

- 有画面图片 → 使用；
- 当前分镜引用的人物 / 场景 / 道具有图 → 使用这些相关图；
- 某对象无图 → 仅在基础设置允许时用该对象文字 Prompt；
- 没有任何视觉图片 → 实际走纯文本视频路径。

---

## 13. 同一分镜允许多张相关参考图

例如分镜需要：

`女主 + 男主 + 客厅 + 手机`

如果这些对象图都存在，全部是该分镜的相关视觉参考。

如果同时还有画面图片，业务层的视觉集合可以是：

`画面图片 + 女主图 + 男主图 + 客厅图 + 手机图`

不要由业务层擅自只保留一张。模型支持上限由 provider capability / adapter 处理。

## 14. 视频最终输入编译（已锁定）

```text
当前分镜 / VIDEOxx
↓
读取当前分镜 presetRefs
↓
逐个对象判断
├─ 有图 → 图片 only
├─ 无图 + 基础设置 ON → 对象文字 Prompt
└─ 无图 + 基础设置 OFF → 不参与

↓
解析有效引擎配置（作品/全局 → 单书 override）
↓
video provider adapter
↓
VIDEOxx
```

## 15. 跟随音频：两个独立能力（已确认）

两个能力可以两个都关、只开一个、或两个同时开。

### 15.1 生成阶段按音频时长约束

读取真实音频长度，让 AI 在分镜规划阶段尽量按音频总长分配目标时长。

例如音频28s，可规划：

`6 + 8 + 7 + 7 = 28s`

但 provider 最终可以输出不同实际时长；某分镜目标6s、实际10s，接受10s，不裁剪当前单段。

### 15.2 合成阶段按音频时长匹配

以 VIDEO 的 `actualDurationSec` 总和与真实音频时长计算：

`自动倍率 = 视频实际总时长 ÷ 音频实际时长`

例如：

- 35 / 28 = 1.25x → 加速压缩；
- 25 / 28 = 0.892857x → 允许慢放拉长。

新版允许：

- `>1.0x` 加速；
- `=1.0x` 原速；
- `<1.0x` 慢放。

旧“音频比视频长就异常、不允许慢放”正式废弃。

### 15.3 用户可以手动覆盖倍率

自动倍率只是推荐值。

系统推荐1.42857x，用户改1.35x，则最终直接用1.35x，不是在自动倍率上再乘1.35。

### 15.4 TTS / 音频边界

音频主要作为时长 / 节奏约束，不默认自动混入最终视频音轨。

## 16. 画面图片生成

当前分镜生成画面图片时：

- 对象有图 → 使用对象图，不重复注入同对象文字 Prompt；
- 对象没图 → 可以使用对应对象文字预设作为参考文本；
- 再加当前分镜画面提示词 → 画面图片。

批量“画面图”只处理真正有画面提示词的分镜。

仍待确认：图像生成链路里“对象无图 → 文字 Prompt 回退”是否同样受基础设置开关控制。

## 21. 当前 v88 Git 核对结果（用于区分现状与目标）

### 21.1 V11 权威页面

`BatchFactoryPageV11.jsx` 只是兼容入口，当前实际渲染权威页在 `batch-factory-v11/BatchFactoryV11UiPage.jsx`。

### 21.2 当前旧工作台仍有大量旧布局逻辑

`BatchFactoryV11Workbench.jsx` 仍包含 selectedBook / selectedVideo、状态筛选、拖拽 / 缩放 / 隐藏、原文 / Hook / Director、人物场景道具 Prompt、VIDEO 方案以及 visualPrompt 编辑。

这些是现状，不代表新版继续照搬。

### 21.3 当前 `visualPrompt` 语义与新版硬规则冲突

旧工作台把 visualPrompt 直接作为 VIDEO 画面提示词并进入最终 Prompt 预览。新版已锁定：画面提示词只用于画面图片，不能直接进入视频生成，因此后续必须重构该链路。

### 21.4 当前设置层仍有单 VIDEO override

现有 `BatchFactoryV11ScopedSettings.jsx` 是：

`系统默认 → 批次 → 当前小说 → 单 VIDEO`

单 VIDEO 当前可覆盖 duration、aspectRatio、subtitlePolicy、negativeMergeMode、characterRefs / sceneRefs / propRefs、约束等。

新版是否继续保留单分镜 / 单 VIDEO 设置最高覆盖层，仍待确认。

### 21.5 当前旧 BatchManager 的“手动创建批次”与新版目标冲突

现有 `BatchFactoryV11BatchManager.jsx` 使用 小说获取 Intake → 用户手动创建 V11 批次；新版已经确认改为：**小说获取进入后按 30 本一档自动建立个人作品 / 项目记录并直接进入小说列表。**

因此旧“待建立批次 / 创建 V11 批次”不应继续作为新版必经交互。

### 21.6 水货生产已经有“个人作品 / project / studio”产品壳

当前 v88 水货生产以项目为核心：个人作品展示 project 卡片，点击项目进入内部工作台。批量工厂作为小说前贴版本，后续设计优先对标该生命周期，而不是另造孤立的历史批次入口。
