# 批量工厂 V11｜新版布局与生产逻辑

> 状态：设计确认中
> 主线：v88
> 原则：后续实现全部写入 v88，v88 作为总分支再发布公网；不要回写旧 v78。

## 1. 开发固定约束

- API / 后端：Go（Golang），以二进制服务为主。
- 管理端：React + Ant Design。
- 用户端：React + Ant Design。
- 数据库：MySQL，迁移使用 Goose。
- 队列 / 非关系型状态 / 锁：Redis。
- 对象存储：TOS。
- 部署：Go embed 打包前端资源到后端。
- 系统预设 Prompt：后端/管理后台管理，运行时替换真实 Prompt。
- 开发前先走 Superpowers 头脑风暴 / 设计确认，再进入实现。

## 2. 新版总体方向

新版批量工厂直接参考“水货生产”的操作习惯：

`水货生产：一行一个分镜 → 批量工厂：一行一本小说`

批量工厂 V11 继续使用独立业务数据/API，不把水货生产内部业务强行复用；但 UI 组件、交互模式可以复用。

顶部主入口暂定：

`小说列表 / 引擎配置 / AI推理 / 批量操作 / 取消操作 / 任务/日志 / 上传121`

其中：

- 小说列表：对应水货生产的“分镜调整”。
- 引擎配置：保持原名。
- AI推理：保持原名，不改成“AI导演”。
- 批量操作：用于真正消耗模型资源的媒体任务。
- 上传121：替换水货生产“导出剪映”的位置。
- “人物场景预设”不是全局顶部入口，而是单书工作区功能。

## 3. 小说列表与内容范围

小说列表中的每一本书允许配置“内容范围”。

例如：`内容范围：5`

含义不是5个分镜，也不是5秒，而是：**仅使用小说原文前5行作为本次后续处理输入，不把整篇全文送入后续AI/生产链路。**

因此内容范围属于输入裁剪规则。当用户选择5时，后续资产提取、剧本/分镜推理、视频Prompt等都应该基于该书裁剪后的前5行内容，而不是全文。

待后续继续核对 v88 现有 Git 实现中的字段名、默认值、是否支持更多范围模式。

## 4. 单书配置

每一本小说都有自己独立的：人物场景预设 / 引擎配置 / AI推理。

推荐采用“默认继承全局，仅修改项形成单书 override”的方式。

### 4.1 单书 → 人物场景预设

这是水货生产同名功能在单书层的直接对应：`左侧 Prompt / 右侧图片`。

负责当前书实际产生的人物、场景、道具：查看Prompt、编辑Prompt、保存Prompt、重新生成Prompt、查看图片、生成图片、替换图片。

`单书 → 人物场景预设` = 当前书的实际资产结果。

它与 `AI推理 → 资产设置` 不是一回事。

## 5. 引擎配置

引擎配置只负责模型与运行参数，不放Prompt。

顶部两个Tab：`[模型配置] [发布统一]`。

### 5.1 模型配置

视频：视频模型 / VIDEO时长 / 画幅 / 匹配音频。

图片：图片模型。

文本：文本模型。

### 5.2 API配置边界

这里不出现API Key输入或personal_api凭证编辑。API凭证由个人中心/管理端配置；批量工厂只选择已经可用的模型。

### 5.3 Provider能力层

业务层只决定本次应该传哪些图、哪些文本、时长、画幅。供应商专用格式由provider adapter负责，包括参考图数量、时长档位、画幅、negative prompt等。

不能在业务数据里写死诸如`@图片1`的供应商语法。如果模型不支持所需参考图数量或参数，必须显式处理/提示，不允许静默丢图。

## 6. AI推理

AI推理只负责Prompt与Prompt相关推理规则。模型选择全部归引擎配置。

固定四个Tab：资产设置 / 约束设置 / 视频设置 / 画面设置。

### 6.1 资产设置

人物场景提示词 / 范围 / 取消 / 确定生成。它是全局/批量层的人物、场景、道具Prompt生成规则。

### 6.2 约束设置

必须直接复用“剧本生成”现有约束设置UI与逻辑，不另造一套。包含实际现有实现中的基础设置、画面前缀、画质约束、画面限制、负面提示词等；只有启用的约束参与最终编译。

### 6.3 视频设置

固定开头（单个视频 / 多个视频）+ 视频提示词 + 范围 + 确定生成。不要发明未确认模式。

### 6.4 画面设置

画面提示词 + 范围 + 确定生成。画面提示词默认可以不选/不生成；如果某分镜没生成过画面提示词，界面上不强行出现该Tab。

### 6.5 AI推理预设

右上角齿轮 + 保存预设。支持保存、重命名、单模块生成和“统一生成”。

## 7. VIDEO与分镜关系（已确认）

采用与剧本生成分镜卡一致的思维：**一个分镜就是一个VIDEO的生产标准。**

```text
一本小说
├─ 分镜01 → VIDEO01
├─ 分镜02 → VIDEO02
├─ 分镜03 → VIDEO03
└─ ...
```

不是VIDEO内再嵌套多个Shot。左右箭头是在切换分镜卡。

切换分镜时，同步切换：当前预设、人物/场景/道具、视频提示词、画面提示词（若有）、画面图片（若有）、对应VIDEO结果、当前分镜任务状态。

## 8. 分镜目标时长与实际VIDEO时长

VIDEO时长是“上限/目标能力”，不是要求每个分镜都生成满额。

例如`VIDEO时长：≤10s`：分镜01需要6s就希望生成6s；分镜02需要8s就希望8s；分镜03需要10s就10s。

建议数据层区分：

- `targetDurationSec`：AI/业务希望该分镜多长。
- `requestedDurationSec`：真正发给provider的请求时长。
- `actualDurationSec`：provider最终返回的真实时长。

如果提示词要求6s但模型最终输出10s：接受10s，不自动裁剪，也不把当前单段强制压成6s。后续总体时长由合成阶段跟随音频/倍率处理。

## 9. 人物/场景/道具：有图不用词（硬规则）

| 分镜引用对象 | 对象图片存在 | 基础设置开启 | 最终输入 |
|---|---|---|---|
| 是 | 是 | 是 | 只传图片，不传该对象文字Prompt |
| 是 | 是 | 否 | 只传图片，不传该对象文字Prompt |
| 是 | 否 | 是 | 传该对象文字Prompt |
| 是 | 否 | 否 | 什么都不传 |
| 否 | 任意 | 任意 | 什么都不传 |

适用于人物、场景、道具。基础设置只控制无图时是否允许文字Prompt回退，不控制已有图片是否上传。

硬规则：**上传了女主图，就不要再把女主人物Prompt注入同一次生成。**

## 10. 画面提示词与画面图片（硬规则）

画面提示词只负责生成画面图片：`画面提示词 + 当前分镜需要的视觉资产 → 画面图片`。

视频生成时：有画面图片就上传画面图片；只有画面提示词但没有画面图片则完全忽略画面提示词；画面提示词绝不能直接编译进视频Prompt。

旧版若存在`visualPrompt → compiledPrompt → 视频模型`路径，新版必须废弃这一语义。

## 11. 视频生成不让用户选择“文生/图生”

不要增加“使用画面图片 / 直接使用人物场景参考图 / 文生视频 / 图生视频”等选项。系统根据当前分镜实际已有资产自动判断。

例如当前分镜需要`女主 + 男主 + 客厅 + 手机`，这些图片都存在且还有画面图片，则业务层希望提供`画面图片 + 女主图 + 男主图 + 客厅图 + 手机图`。具体provider能否全部接收由adapter/capability层处理。

## 12. 视频最终输入编译

```text
当前分镜
↓
读取当前分镜 presetRefs
↓
逐个预设对象判断
├─ 有图 → 图片 only
├─ 无图 + 基础设置 ON → 对象文字 Prompt
└─ 无图 + 基础设置 OFF → 不参与
↓
+ 当前分镜画面图片（如果已生成）
+ 当前分镜视频提示词
+ 生成阶段音频时长约束（如果开启）
+ 约束设置中其他启用规则
↓
绝不加入画面提示词
↓
解析全局引擎配置 + 单书 override
↓
video provider adapter
↓
VIDEOxx
```

## 13. 跟随音频：两个独立能力（已确认）

两个能力可以都关、只开其一、或两个同时开启。

### 13.1 生成阶段按音频时长约束

让AI在分镜规划阶段参考真实音频长度。例如音频28s，AI尽量让各分镜目标时长合计接近28s。

它只是生成目标，不保证provider最终严格输出该时长。比如分镜目标6s、provider实际返回10s，则接受10s，不裁剪当前单段。

### 13.2 合成阶段按音频时长匹配

根据所有VIDEO实际总时长和音频真实长度计算最终合成倍率：`自动倍率 = 视频实际总时长 ÷ 音频实际时长`。

例：35s / 28s = 1.25x，加速压缩到接近28s。

反例：25s / 28s = 0.892857x，允许慢放拉长到接近28s。

新版明确允许：>1.0x加速；=1.0x原速；<1.0x慢放。

旧版“音频比视频长就异常、不自动慢放”的规则作废。

### 13.3 用户可手动覆盖倍率

自动计算只是推荐值。系统算1.42857x，用户改成1.35x，则最终直接使用1.35x，不是把两者相乘。

## 14. 批量操作

固定包含：人物场景图 / 画面图 / 生视频 / 重试 / 合并。

- 人物场景图：根据资产Prompt用有效图片引擎生成角色/场景/道具图。
- 画面图：只处理有画面提示词的分镜，根据当前视觉资产 + 画面提示词生成画面图片。
- 生视频：执行最终输入编译后调用有效视频模型。
- 重试：必须支持用户自己勾选书；推荐失败在哪一步就只重试哪一步。
- 合并：按分镜/VIDEO正确顺序合并；某VIDEO重生成后旧合并结果应失效并允许重新合并。

## 18. 已明确废弃/冲突的旧思维

- 旧“大一统生产统一设置”：拆成引擎配置 + AI推理。
- 旧`画面提示词 → 最终视频Prompt`：废弃。
- 旧“有资产图仍重复注入同对象文字Prompt”：废弃。
- 旧“音频比视频长不允许慢放”：废弃；新版允许<1x。
- 旧单书设置杂糅模型、Prompt、发布参数：拆分职责。
- 旧状态中心主导页面：新版改走水货生产式一行一本小说，但状态能力不能丢。
- 旧仅VIDEO级批量媒体任务：新版覆盖人物场景图、画面图、视频、重试、合并。
- 旧只支持失败VIDEO重试：新版支持选书 + 失败阶段精确重试。
