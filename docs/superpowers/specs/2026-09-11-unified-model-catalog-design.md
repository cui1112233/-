# V88 统一模型目录设计

## 已确认目标

个人中心将模型配置改为管理者账号级的统一目录。模型只配置一次；小说获取、小说面板、剧本生成、批量工厂、水货生产和人物/场景生图等业务步骤只选择已经注册的模型，不再分别保存模型名称或密钥。

目录严格分为文本、视频、图片三类：

- 文本模型只出现在文本步骤的下拉框，例如小说获取、小说面板、剧本的人物/场景提取和剧本生成、批量工厂的文本编排、水货生产的 AI 分镜/提示词生成。
- 视频模型只出现在视频步骤的下拉框，例如剧本分镜视频生成、批量工厂视频生产、水货生产视频任务。H3 是视频模型。
- 图片模型只出现在图片步骤的下拉框，例如剧本人物/场景 AI 生图、批量工厂图片资产生成、水货生产图片任务。
- 121 是目标网站或登录配置，不是模型，不进入目录。

目录不提供任何内置、默认或隐式可用模型。新管理者的文本、视频、图片目录都为空；只有管理者亲自添加并启用某一类型的模型，该类型才会在所有对应业务步骤的下拉框中出现。三类目录彼此独立：添加图片模型不会使文本或视频下拉框出现任何选项，反之亦然。

“目录初始为空”不表示 API 配置页面没有预设入口。API 配置展示系统支持的**平台预设模型卡**，但所有卡在管理者配置成功并主动启用前都不进入可用目录，也不出现在任何业务下拉框。

模型由每位管理者独立维护自己的名称、供应商、模型 ID、Base URL 和 API Key。成员永远不可读取、编辑或导出 API Key。

## 可见性与授权

成员可见模型的规则为：`管理者已启用的模型 ∩ 成员拥有的对应功能权限`。

例如，成员拥有视频生成权限时，视频下拉框直接展示管理者全部已启用的视频模型；没有图片生成权限时，图片模型不会提供给该成员。管理者新增、启用或停用模型后，成员在下次展开下拉框、页面重新获得焦点或重新打开页面时必须重新取得最新目录，无需重新登录。

停用正在被成员页面选择的模型时，提交接口必须拒绝该模型，并要求重新选择；已完成任务与历史记录仍显示当时的模型快照。

## 数据模型

新增账号归属的 `model_catalog` 记录；每条模型只属于一个管理者账号：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定主键，所有业务选择与任务记录使用它 |
| `owner_user_id` | 管理者账号归属 |
| `kind` | `text`、`video` 或 `image` |
| `display_name` | 下拉框和任务历史中的显示名，例如 `GPT-5.4`、`H3` |
| `provider_type` | OpenAI Compatible、H3 适配器、图片适配器等 |
| `model_id` | 上游服务的模型标识 |
| `base_url` | 非密钥的供应商地址 |
| `credential_ciphertext` | 加密后的 API Key；API 响应绝不返回原文 |
| `capabilities` | 类型内能力，例如图生视频、参考图、最大时长 |
| `enabled` | 是否可用于新任务 |
| `created_at` / `updated_at` | 审计与目录刷新依据 |

同一管理者下，`kind + display_name` 必须唯一。删除采用受保护删除：仍被默认设置、待执行任务或业务配置引用时，先提示停用；只有解除引用后才允许删除。

## 接口与页面

个人中心新增“统一模型管理”页，以三个分组（文本模型、视频模型、图片模型）显示已启用或已保存的模型表格。每个分组有两种入口：平台预设模型卡和“添加自定义模型”。

### 平台预设模型

平台预设模型由系统维护适配器、请求格式、固定模型标识及能力；管理者不能修改这些技术参数，只填写该模型必要的凭据或完成必要配对，然后主动启用。首版视频预设卡包括：

| 预设 | 管理者操作 | 系统固定能力 |
| --- | --- | --- |
| `YD2.0 Mini（图生）` | 填写并保存 YD API Key，再启用 | YD 视频请求格式与图生能力 |
| `MiniMax H3 多图生视频` | 填写并保存 H3 API Key，再启用 | H3 工作流、最多 9 张参考图、分辨率和时长约束 |
| `本地豆包执行器` | 完成执行器配对，再启用 | 本地执行器视频投递能力 |

后续接入新的专用供应商时，只向平台预设目录注册一张卡及其适配器，不要求业务页面新增硬编码分支。预设卡配置完成但未启用时，也不返回给业务选择接口。

### 自定义模型

“添加自定义模型”采用用户提供的布局：模型类型、API 格式、Base URL、模型 ID、显示名、API Key、能力和启用状态。它用于没有平台预设适配器的模型，例如 GPT、Gemini、DeepSeek 或图片服务。API Key 仅在新增或替换时提交，读取时只返回是否已保存。

提供两类目录接口：

1. 管理接口：当前管理者可创建、编辑、启用、停用或受保护删除自己的模型。
2. 选择接口：根据当前登录用户、所属管理者与请求的 `kind` 返回可用模型。该接口仅返回 `id`、显示名、类型、能力与更新时间，不返回密钥或可编辑供应商配置。

所有业务步骤改用选择接口。一个页面可以同时有文本、图片、视频多个模型下拉框，但每一个下拉框必须声明自己的任务类型，只请求并显示该类型的最新模型；提交时服务端再次按登录用户、权限、管理者归属、类型、启用状态校验模型 ID，不能信任前端缓存。

当某类型没有任何已启用模型时，该类型的下拉框显示为空，生成按钮保持不可提交，并显示“尚未添加可用的文本/图片/视频模型，请让管理者前往统一模型管理添加”的提示。系统绝不自动改用另一类型模型、旧全局配置或固定供应商模型。

## 业务步骤矩阵

| 业务 | 文本模型 | 图片模型 | 视频模型 |
| --- | --- | --- | --- |
| 小说获取 | 获取、清洗、改写等文本步骤 | 不适用 | 不适用 |
| 小说面板 | 大纲、人物、场景、提示词等文本步骤 | 人物/场景参考图生成 | 后续分镜视频步骤（启用时） |
| 剧本生成 | 人物/场景提取、剧本生成与改写 | 人物/场景 AI 生图 | 每个分镜的视频生成，例如 H3 |
| 批量工厂 | 文本编排、导演稿、提示词步骤 | 图片资产/首帧步骤 | 批量视频生产 |
| 水货生产 | AI 分镜、提示词和分析步骤 | 素材、人物、场景图片任务 | 分镜视频任务 |

这张表是“步骤需要什么模型”的规则，不是要求每一次操作都必须同时选三种模型。页面只在用户进入对应步骤时显示该步骤需要的下拉框；一个步骤只能接受同类型模型。

## 迁移与兼容

现有个人中心的单文本、单视频、单图片配置迁入目录，每一类生成一条对应记录。旧字段在过渡版本内只用于回滚读取，不再作为新任务配置来源。原有水货生产模型目录不直接存入账号私有密钥；如需复用其中的能力描述，以适配器元数据方式迁移，避免两套目录同时成为事实来源。

旧任务和历史批次继续保留已写入的模型 ID、名称和版本快照，不能因新目录改造而改变已提交任务的执行含义。

## 失败处理与安全

- 不允许将 API Key 放入浏览器状态、日志、错误消息或任务记录。
- 模型被停用、删除或无权限时，返回明确业务错误而不是回落到其他模型。
- 上游调用使用目录记录解析后的适配器；服务端验证模型类型与业务类型匹配。
- 管理者更新模型后，成员缓存最多仅持续到下一次下拉框展开或窗口焦点恢复；接口响应带 `updated_at`，用于避免无谓刷新。

## 验收标准

1. 新管理者的三类模型下拉框均为空；管理者可分别添加多个文本、视频和图片模型，同名同类不可重复。
2. 管理者只添加图片模型时，它出现在剧本生成、批量工厂、水货生产等所有图片步骤；文本和视频下拉框仍为空，且对应生成不可提交。
3. 管理者添加 `GPT-5.4` 这类文本模型后，它只出现在所有文本步骤，不会出现在视频或图片步骤；添加 H3 这类视频模型后同理。H3 带参考图能力时，剧本视频生成可以正确识别其能力。
4. 管理者在成员页面打开期间新增或停用模型，成员下次展开该下拉框即可看到更新；无需重新登录。
5. 成员无法通过页面、接口或日志获得管理者 API Key。
6. 服务端拒绝跨管理者、跨类型、已停用或未授权模型 ID。
7. 旧单模型配置可迁入，旧任务和历史记录不受影响。
