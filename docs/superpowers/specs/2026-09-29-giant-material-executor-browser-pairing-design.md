# 巨量素材执行器本机浏览器配对设计

## 背景与决定

Windows x64 的手写 Win32 配对窗口已连续出现“点击绑定无响应”和“窗口未响应”的真实用户反馈。该窗口无法在 macOS 上完成等价交互验收，继续修补会持续把不确定性带给用户。

决定保留独立的 Windows `GiantMaterialExecutor.exe`、设备配对协议、DPAPI 凭证、后台 OCR agent 和 127.0.0.1:17861 回环服务；移除 EXE 内嵌的配对窗口。EXE 启动回环服务后自动打开默认浏览器的本机配对页。

## 方案比较

1. 继续维护手写 Win32 UI：安装包最小，但已经多次出现线程与消息队列问题，且无法在当前开发机完成真实交互验收；不采用。
2. EXE 启动本机浏览器配对页：浏览器负责输入、点击、错误展示；EXE 仍是常驻处理器，不引入 Electron/WebView 运行时；采用。
3. 引入 Electron/Tauri 窗口：体验更接近桌面管理台，但会增加运行时、构建和 Windows 签名复杂度；当前不采用。

## 架构

```text
双击 GiantMaterialExecutor.exe
        ↓
127.0.0.1:17861 启动（仅本机监听）
        ↓
默认浏览器打开 /setup
        ↓
用户填写控制服务地址 + 配对码
        ↓
POST /v1/pair（同源、本机）
        ↓
保存地址和设备凭证 → 后台 agent 心跳/领取 OCR 任务
```

`GET /setup` 返回内嵌、无第三方资源的 HTML/CSS/JavaScript。页面每秒读取本机状态，并在按钮点击后立即显示“正在绑定”，成功或失败显示可读结果。`POST /v1/pair` 接受 `code` 和可选 `publicURL`；地址先经主程序校验和持久化，再调用既有公网配对接口。

页面只在 `127.0.0.1:17861` 提供。浏览器页面和 API 同源，不读取或上传浏览器 Cookie；公网地址只用于执行器后续访问平台控制 API。已有网页 Origin 的 loopback 访问保持原有 nonce 保护。

Windows 通过系统默认浏览器打开本机 URL。无法自动打开时，执行器日志记录完整的本机配对地址，用户仍可手动打开它。

## 验收

- 双击 EXE 后默认浏览器打开本机配对页，不显示或依赖 Win32 配对窗口。
- 点击“绑定”立即进入可见的提交状态；错误会回显，不能静默无反应。
- 成功配对后凭证与控制服务地址保存，重启仍自动连接。
- 回环服务保持仅绑定 `127.0.0.1`；现有远程网页 loopback nonce 边界不放宽。
- Go 全量测试、Windows x64 交叉编译、ZIP 完整性和本地下载地址均通过；最终真实 Windows 点击验收由用户完成。
