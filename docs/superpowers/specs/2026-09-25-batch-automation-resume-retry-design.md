# 批量工厂：自动化续跑与阶段重试

## 目标

让“立即执行”“定时启动”和“继续自动化”使用同一套可恢复执行器。自动化只处理每本书尚未完成的阶段；出现可恢复错误时自动重试；不可恢复错误和重试耗尽后保留明确原因，等待用户处理。

## 已确认语义

- “继续自动化”不重新生成已成功的正文、资产、导演卡、最终 VIDEO、视频、成片或已确认上传。
- 它读取该书持久化的阶段记录，找到最后一个失败或尚未完成的阶段，仅从那里恢复。
- 每本书独立推进；一本书失败、等待供应商或被阻塞，不停止同批其他书。
- 已提交给供应商的任务只回读，不重复提交。
- 需要用户干预的错误（未配置模型、鉴权/权限错误、无效输入）立即标为“需要处理”，不盲目重试。
- 可恢复错误（网络、限流、服务端暂时错误、供应商短暂不可用）按 30 秒、2 分钟、5 分钟自动重试三次。三次都失败后保留失败阶段与最后错误，等待用户点击“重试失败步骤”或修正配置后“继续自动化”。

## 实现范围

1. 统一自动化执行器的恢复入口：`resume` 不把所有非就绪书笼统改为待处理，而是保留每本书当前/失败阶段与已完成阶段证据。
2. 自动化调度在恢复时优先读取阶段摘要、视频任务和合成任务：
   - 成功阶段跳过；
   - 在途阶段回读；
   - 失败阶段调用现有单阶段重试适配器；
   - 缺失阶段走正常缺失补全路径。
3. “继续自动化”与日志明确显示：续跑起点、自动重试次数、下次重试时间、需要用户处理的原因。
4. 不改变单书“重试失败步骤”的语义；它仍只针对当前书。批量“继续自动化”只接续未完成书。

## 不在范围内

- 不自动替用户选择模型、账号、组织或发布目录。
- 不覆盖人工编辑后的提示词、导演卡、视频候选或已上传作品。
- 不把一次失败当作重新抓取整本小说或重新提交全部视频。

## 验收与测试

- 一个书籍资产已成功、导演阶段失败：继续自动化只调用导演阶段。
- 一个书籍视频任务仍在运行：继续自动化只回读，不创建新视频任务。
- 一个书籍合成成功待上传：继续自动化从上传或等待确认继续，依执行模式决定是否上传。
- 可恢复错误连续失败三次后转为需要处理；未配置模型立即需要处理且零次自动重试。
- 批量内一本失败不影响另一本到达完成状态。
- 前端日志显示准确的恢复阶段和重试状态。
