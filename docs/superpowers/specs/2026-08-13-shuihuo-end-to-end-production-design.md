# 水货生产全链路打通设计

## 目标

以 ai-video 的“原文到视频”工作流为基准，在一战晟铭水货生产模块中实现可理解、可操作、可真实验证的闭环：原文、分镜、资产候选、资产绑定、提示词、图片、图生视频和导出。

验收不是接口可访问，而是使用现有真实文本、图片和 Vidu 视频模型，在一个短样本项目中完成实际生成并保存生成素材。

## 现状与断点

### 已具备

- 项目创建、原文保存、人工/智能分段、确认分段。
- 用户隔离的项目资产、媒体、主图、任务队列、图片/视频模型目录。
- 图片与图生视频任务 worker，视频任务强制要求分镜存在主图片。
- 智能分段和资产候选的版本化提示词存储。
- 分镜编辑、手工上传素材、角色模板、默认配置和任务中心。

### 当前断点

1. 文本模型适配器直接向 OpenAI 兼容根地址发送 `{ "prompt": "..." }`，但当前文本模型端点需要 `/chat/completions`、`model` 和 `messages` 格式，因此智能分段与资产分析可能返回笼统的调用失败。
2. 资产分析 API 返回候选，但前端未渲染候选、编辑候选、单个/批量采纳，因此候选不能进入正式项目资产。
3. 分镜完整描述、分镜资产匹配、图片提示词、视频提示词缺少可执行的后端分析路由和默认提示词预设。
4. 当前工作台直接暴露许多操作，缺乏按依赖顺序引导，首次用户无法判断下一步应该点击哪里。
5. ZIP 下载、合并视频和剪映草稿导出尚未实现。

## 真实流程

1. 创建项目并输入原文。
2. 选择文本模型，运行智能分段；编辑候选后确认分镜。
3. 运行资产分析；审阅人物、场景、道具候选，逐个或批量采纳为项目资产。
4. 在分镜内使用自动匹配或人工绑定资产。
5. 选择文本模型，批量为分镜生成图片提示词；允许用户编辑后保存。
6. 选择图片模型，提交单段或批量图片任务；在每个分镜中选择主图片。
7. 选择文本模型，批量为分镜生成视频提示词；允许用户编辑后保存。
8. 选择 Vidu 视频模型，按主图片提交图生视频任务。
9. 使用媒体下载、ZIP、视频合并或剪映草稿导出获取成果。

## 文本模型兼容设计

### 端点规范

`text_completion` 模型支持两种明确模式，由模型定义的参数或 adapter 配置确定：

- `openai_chat`：端点若为 `https://host/v1` 或 `https://host/v1/`，服务端补齐 `/chat/completions`；请求体为 `{ "model": "模型名", "messages": [{"role":"user","content":"渲染后的提示词"}], "temperature": 0.2 }`。
- `prompt_json`：保留既有 `{ "prompt": "..." }` 调用，用于明确配置为此协议的内部模型。

现有 `TEXT_CREDENTIAL=https://api.gpt.ge/v1/` 必须按 `openai_chat` 处理。模型名来自服务端模型定义的安全参数，浏览器不传入模型名、端点或凭据。

### 响应与错误

文本适配器继续兼容 `choices[0].message.content`、`choices[0].text`、`content`、`output`、`text` 与直接 JSON 数组。失败时记录服务端安全错误分类：凭据解析、端点无效、网络、HTTP 状态、响应格式；向浏览器映射为可行动提示，不包含密钥、DSN、响应原文或内部网络地址。

## 提示词预设

提示词继续使用 `prompt_definitions`、`prompt_versions` 和项目快照。默认启用下列 `shuihuo-production` 预设：

| purpose | 参数 | 输出 |
|---|---|---|
| `segmentation` | `novel_text` | `[{"text":"原文分段"}]` |
| `assets` | `novel_text` | `[{"category":"character|scene|prop","name":"...","prompt":"..."}]` |
| `storyboard` | `novel_text` | `[{"text":"原文","subtitle":"原文字幕","description":"镜头画面"}]` |
| `asset_match` | `segment_text`,`project_note` | `[{"segmentId":1,"assetNames":["..."]}]` |
| `image_prompt` | `segment_text`,`project_note` | `[{"segmentId":1,"prompt":"..."}]` |
| `video_prompt` | `segment_text`,`project_note` | `[{"segmentId":1,"prompt":"..."}]` |

所有预设严格要求只输出 JSON 数组、没有 Markdown；图片提示词包含主体、场景、动作、构图、镜头、光线和风格，但不得编造未在原文或已绑定资产中出现的核心剧情；视频提示词包含主体动作、镜头运动、时长内可执行动作和稳定性约束。

`project_note` 由服务端根据已绑定资产和项目配置生成，包含名称、类别、视觉提示词与用户设定的图片/视频前后缀；不包含密钥或绝对文件路径。

## 分析与写入 API

- 保留智能分段为候选返回，人工确认后才替换正式分镜。
- 资产分析返回候选；新增“采纳候选” API，支持验证分类、名称、提示词并一次采纳 1–50 项，写入当前用户项目资产。候选不会自动覆盖人工资产。
- 新增分镜资产匹配候选 API；用户确认后才调用现有分镜资产绑定接口。
- 新增图片提示词和视频提示词候选 API；用户可以单项或批量应用，只有未锁定提示词允许被批量覆盖。
- 每次文本分析保存所使用的提示词版本快照、模型版本和项目归属。

## 前端交互

### 生产向导

水货项目首次打开默认显示 7 步向导：

1. 原文
2. 分镜
3. 资产候选
4. 资产绑定
5. 图片提示词与图片
6. 视频提示词与视频
7. 导出

每步显示：当前状态、必需条件、一个主按钮、可选的“进入高级编辑”按钮。完成条件来自项目和媒体真实数据，不能只依赖前端状态。

### 高级工作台

保留现有六列编辑器：内容、角色/资产、图片提示词、图片、视频提示词、视频。工作台增加“返回生产向导”入口。没有主图时视频按钮显示明确原因；未选提示词/模型时生成按钮显示下一步所需操作。

### 资产候选弹窗

“人物场景预设 → 分析候选”调用完成后，在同一弹窗显示分类卡片。每项可修改名称、类别、提示词；支持单个采纳、选择多项采纳和全部采纳。采纳成功后刷新资产列表，并提示用户回到分镜绑定资产。

## 导出边界

本轮首先验证到真实图片和真实图生视频生成成功。完成该验收后，独立实施：视频 ZIP 下载、视频合并、剪映草稿导出。导出任务必须走受控任务队列、验证项目所有权、仅引用对象存储中的媒体；浏览器不能提交任意服务器路径。

## 验收

1. 真实文本模型成功生成智能分段候选和资产候选。
2. 至少采纳一个人物、一个场景或道具，并绑定到分镜。
3. 真实文本模型为至少一个分镜生成图片提示词和视频提示词。
4. 真实图片模型成功生成图片，结果存储并可预览，用户可将其设为主图。
5. 真实 Vidu 图生视频任务完成并保存视频媒体。
6. 所有任务显示状态、失败原因、重试入口；错误信息不泄露密钥、数据库连接或内部地址。
7. 新用户可只通过向导完成上述流程，不需要理解工作台的内部按钮。
8. 运行 Go 相关测试、前端生产构建、网关健康检查和一次真实短样本链路。
