# 多书城分组新建批量 — 设计文档

日期：2026-09-27
状态：待用户评审

## 一、要解决的问题

现在"新建批量"弹窗一次只能选一个书城：选书城 → 粘贴书 → 获取 → 创建。
如果一批书来自多个书城（知乎 3 本、点众 4 本、黑岩 2 本），用户必须建多个批量，无法统一跑自动化。

目标：一个弹窗里按书城分组录入，最后创建成 **1 个批量、9 本书**，每本书各带各的书城标记，一步跑完全自动流程（抓正文 → AI 分析 → 分镜 → 视频 → 合成 → 上传 121）。

## 二、交互设计

### 2.1 弹窗布局（改造后）

```
作品名称：[________________]

书城：[七猫付费 ▼]   输入格式：[智能识别 ▼]   列顺序预设：[...▼]

小说列表（当前书城的草稿）：
┌─────────────────────────────────────┐
│ 737092  雪尽风软归良人                │
│ 687404  老公狠心将怀孕秘书...          │
└─────────────────────────────────────┘
[添加书城]

已添加的书：
[七猫付费 ×6 ×]  [知乎付费 ×3 ×]  [点众付费 ×4 ×]

[立即执行]  [开始定时]  [定时任务]
内容范围：5 行      内容截取：4000 字
```

变化点：
- 原"自定义列顺序"输入框 → 替换为**已添加标签区**（只显示标签，不再有列顺序文本框；列顺序仍由"列顺序预设"控制）
- 原"获取并创建""获取内容"两个按钮 → 替换为**添加书城**一个按钮
- "立即执行 / 开始定时 / 定时任务"保留

### 2.2 状态模型（前端）

弹窗内维护一个"书城分组"列表：

```js
groups = [
  { platformId: '3', platformName: '七猫付费', inputText: '737092 ...\n687404 ...' },
  { platformId: '15', platformName: '知乎付费', inputText: '...' },
]
```

输入框、书城下拉框只编辑"当前草稿"。草稿通过"添加书城"落进 groups。

### 2.3 操作规则

1. **添加书城**
   - 校验：当前选了书城、输入框里至少解析出 1 个有效书 ID（ID 规则：行首连续 6–25 位数字）
   - 同书城已存在 → **合并**：把新行并入该组，按书 ID 去重（同 ID 保留信息更全的一行，规则沿用后端 ParseManualBookList 的合并逻辑）
   - 新书城 → 新增一组
   - 成功后：清空输入框、保持书城下拉不变（方便连续加同书城）、标签区刷新
2. **点标签文字（如"七猫付费 ×6"）→ 回填编辑**
   - 该组 inputText 回到输入框，书城下拉切到该书城，该标签进入"编辑中"高亮态
   - 编辑中点"添加书城"= 用输入框内容**整体替换**该组，并退出编辑态；若输入框为空则移除该组
   - 编辑中切换书城下拉或点别的标签 → 弹提示"请先完成当前修改：点添加书城保存，或点 × 放弃"
3. **点标签 ×**：删除整组。唯一例外：某组处于"编辑中"时，该组自己标签上的 × 表示"放弃修改"（恢复输入框为空、退出编辑态，不删组）；编辑中其他标签的操作一律被第 2 条的拦截规则挡住
4. **立即执行**：见 2.4
5. **开始定时**：同立即执行，只是带定时启动时间

### 2.4 立即执行的完整链路

1. 校验：作品名称非空、groups 至少 1 组、每组至少 1 个有效书 ID
2. **按书城分组抓正文**：对每个 group 调一次现有 `/api/batch-factory/v12/fetch-originals`（带各自的 platform + bookIds），各走各的书城接口
3. **创建 1 个批量**：调用手动录入接口（见三），一次提交 9 本书，每本带各自书城
4. **抓不到正文的书**：照样创建进批量，列表里显示"原文尚未获取"标红；抓到正文的书正常继续
5. 创建成功后自动启动自动化（runMode=full_submit，autoPublish），AI 分类只对有正文的书执行（现有后端本就跳过无正文的书），全流程跑到上传 121
6. 失败的书用户事后在书列表点"获取正文"单独重试，不影响其他书

### 2.5 错误与边界

- 某书城整组抓取接口报错（非单本失败）：提示"知乎付费分组抓取失败，可重试"，该组书仍创建进批量标红
- 重复书 ID 跨书城出现（同 ID 出现在两个书城）：视为两本不同的书，都创建（不同书城可能撞 ID）
- 标签区为空时点立即执行：提示"请先添加至少一个书城的书"
- 单次提交总量上限 50 本（沿用现有后端限制），超出则在添加时累计计数并在提交时拦截提示

## 三、后端改动

### 3.1 Go：手动录入接口支持多书城分组

文件：`backend/internal/batchfactoryv11/manual_intake.go`、`backend/internal/httpapi/batch_factory_v11_slice1.go`

`ManualIntakeInput` 增加可选字段：

```go
Groups []ManualIntakeGroup `json:"groups,omitempty"`

type ManualIntakeGroup struct {
    PlatformID   string `json:"platformId"`
    PlatformName string `json:"platformName"`
    InputText    string `json:"inputText"`
}
```

解析逻辑：
- Groups 非空时：对每个 group 用其自己的 PlatformID/PlatformName/InputText 调 `ParseManualBookList`，结果按组顺序拼接
- Groups 为空时：完全走旧逻辑（顶层 platformId + inputText），**旧客户端零影响**

每个 group 内的解析、去重、列顺序规则与现在完全一致，只是平台信息按组取值。

### 3.2 正文抓取：不改后端

`/api/batch-factory/v12/fetch-originals` 已支持 `{platform, bookIds, maxTxt}` 单组抓取，前端按组多次调用即可。

### 3.3 Node 中转：透传 groups

`routes/batch-factory-v11.js` 中创建批量的请求体原样转发给 Go，无需专门解析；确认透传不被白名单过滤即可。

## 四、前端改动

文件：`frontend/src/user/pages/shuihuo/BatchFactoryCreateModal.jsx`（主要）
辅助：`batchFactoryManualFetch.js`（新增分组解析/合并纯函数）、`shared/api/batchFactoryV11.js`（提交体支持 groups）

1. 新增 groups 状态、当前编辑组状态
2. 输入区与标签区交互（2.3 全部规则）
3. "添加书城"按钮替代旧两个按钮
4. submit 改造：按组抓正文 → 带 groups 创建 → 自动化启动
5. 定时模式同样走 groups

## 五、测试计划

**Go 单元测试**（`manual_intake_test.go`）：
- 三个书城分组提交 → 9 本书顺序、各自 platformName 正确
- 同组重复 ID 去重
- groups 为空时旧路径行为不变（回归）
- 某组 platformId 为空 → 该组报错

**前端纯函数测试**（`batchFactoryManualFetch.test.js`）：
- 分组合并去重、回填替换、空组移除
- 跨组同 ID 共存

**手动验收**（服务器）：
- 七猫 6 本 + 知乎 3 本 + 点众 4 本一次创建成功，列表书城列显示正确
- 标签回填改数量（×3 → ×4）
- 故意填错 1 个 ID，批量照建，错书标红，其余正常进自动化

## 六、不做的事（范围外）

- 不改书列表、自动化编排、121 上传的任何现有行为
- 不做标签拖拽排序（按添加顺序显示即可）
- 不删除旧的单书城接口路径和字段
