# 分镜卡 @人物 / @场景引用设计

## 目标

让用户在 `/script` 的单条分镜提示词中输入 `@名称`，把当前剧本左侧已提取的人物或场景的主图补充为该分镜的视频参考图。行为参考即梦的显式引用，但不新增跨剧本或全站资产搜索。

## 范围与非目标

- 仅匹配当前剧本 `extractInfo.characters` 和 `extractInfo.scenes`。
- 只使用已选定的主图；没有主图的对象不产生参考图。
- 保留现有“提示词正文包含实体名称时自动带主图”的识别规则。
- 不改资产库、模型配置、视频生成 API 或数据库结构。
- 不改变 `@名称` 原文；它继续随提示词发送给视频模型。

## 交互

1. 每张分镜卡增加“编辑提示词”操作，打开该卡当前文本的编辑框；保存后只替换对应卡片文本，不影响其他分镜。
2. 编辑框提供“@人物”和“@场景”快捷插入菜单，菜单只列出当前剧本左侧已提取的对象；点击会在光标位置插入 `@名称`。
3. 用户也可以直接手动输入，例如：`@林溪在@公司办公室推开门。`；手动输入和菜单插入采用完全相同的解析规则。
4. 分镜卡重新显示时，参考图区除原有自动识别的素材外，增加所有成功匹配的 `@名称` 主图。
5. 同一张图无论被正文名称和 `@名称` 同时命中，都只显示一次。
6. 用户继续使用现有的整卡参考图开关与单张图开关；这些开关同样作用于 `@` 补充的图片。
7. 只有 `@名称` 未匹配当前人物/场景或对象无主图时，卡片在参考图区给出非阻塞的“未匹配素材”提示；仍允许生成视频。

## 解析与数据流

在 `scriptVideoReferences` 新增纯函数，用于从分镜文本提取 `@名称`。解析规则如下：

- `@` 后读取连续的中文、英文、数字、下划线和连字符；以空白、标点或下一个 `@` 结束。
- 名称必须与当前人物或场景的展示名称完全相同，避免模糊匹配把错误资产送给模型。
- 解析结果按出现顺序去重，并标注命中实体、缺少实体、或缺少主图。

`collectShotReferenceDescriptors` 将合并两类来源：

1. 原有的正文名称自动匹配；
2. `@名称` 显式匹配。

合并后依据图片 URL 去重，继续尊重每张卡已有的禁用状态。`collectShotReferenceImages` 和 `buildScriptVideoPayload` 保持现有契约：H3 最多发送 9 张 `imageUrls`，其他模型保持既有请求结构。

## 组件边界

- `frontend/src/user/pages/scriptVideoReferences.js`：解析、实体解析、参考图合并与去重；不依赖 React。
- `frontend/src/user/components/ShotOutputCards.jsx`：使用解析结果呈现参考图及未匹配提示，不承担匹配逻辑。
- `frontend/src/user/pages/ScriptPage.jsx`：管理单卡编辑框、当前光标处的快捷插入，并复用已有卡片位置工具将编辑结果写回完整剧本正文；生成视频仍使用编辑后的卡片正文作为 `prompt`。

因为剧本正文和历史记录原本就会保存，重新打开历史后可从正文中的 `@名称` 重新计算引用，无需另一套卡片引用状态或数据库字段。

## 异常与边界

- 空 `@`、仅标点后的 `@`、未知名称、以及没有主图的实体均不抛错。
- 同名人物和场景若同时存在，两个主图均可加入；界面标签必须包含实体类型，避免歧义。
- 参考图全局关闭或图片被逐张关闭时，显式引用也不应绕过用户的关闭选择。
- 视频请求仍由服务端保留现有 URL 校验、模型参数校验和 H3 图片数限制。

## 验证

新增或扩展 `scriptVideoReferences.test.js`，覆盖：

- `@人物`、`@场景` 与中英文/数字名称解析；
- 与正文自动识别合并后按 URL 去重；
- 未知名称和无主图实体只产生提示数据、不产生图片；
- 卡片关闭、单图关闭与 H3 九张上限不回归。
- 单卡编辑只替换目标分镜；菜单插入和手动输入都能写入同样的 `@名称` 文本。

扩展分镜卡组件测试，确认成功匹配的引用标签和未匹配提示被渲染。最后运行定向前端测试、相关 Node 路由测试以及前端构建。
