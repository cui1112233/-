# 暗色星空主题与聊天式输入框设计

## 目标

统一优化 qiantie 的暗色界面：登录后默认使用暗色主题，暗色页面显示低亮度、缓慢流动的星点；导航区域有轻量星空层；剧本生成输入框采用聊天式布局，同时保留现有表单提交、人物场景提取和剧本生成流程。

## 设计边界

- 星空背景只在 `data-theme="dark"` 下显示，浅色主题不显示。
- 星空由 CSS 实现，不新增图片、Canvas 或持续 JavaScript 动画。
- 星点使用低透明度白色/淡蓝色，缓慢平移，避免闪烁和影响正文可读性。
- 导航层只增加局部纹理和轻微边缘光，不改变现有导航结构、收起行为或设置入口。
- 输入框视觉参考聊天输入组件：渐变外框、透明文本区、底部操作栏、辅助图标按钮和生成按钮。
- 辅助按钮提供可见的非破坏性交互提示；不虚构附件上传、语言切换等后端能力。
- 生成按钮继续触发表单 `onFinish`，现有校验、加载、成功和失败状态保持不变。
- 响应式布局必须保证窄屏下输入框、工具栏和生成按钮不溢出。

## 实现方案

### 全局主题层

在 `global.css` 中为暗色 `body` 增加固定的伪元素星点层和低强度动画，并将主体内容置于相对定位层之上。导航侧栏增加独立的纹理伪元素，避免星点被页面内容覆盖。尊重 `prefers-reduced-motion`，减少动画或禁用平移。

### 剧本输入组件

在 `ScriptPage.jsx` 中将小说文本的 `Input.TextArea` 包装为现有 Ant Design Form.Item 内的聊天输入容器。文本域仍由 `Form.Item name="novelText"` 管理；附件、扩展和语言按钮只作为视觉/提示入口，不改变数据提交协议；提交按钮使用原有表单提交行为。

### 验证

- `npm --prefix frontend run build`
- 通过当前 in-app browser 检查暗色剧本页的 DOM、截图和控制台错误。
- 切换浅色主题确认星点隐藏。
- 检查输入框文本输入、表单校验、生成按钮 loading 状态和窄屏布局。

## 风险与处理

- 固定伪元素可能遮挡点击：设置 `pointer-events: none` 并控制层级。
- 动画过亮或过快：使用低透明度、长周期和 `prefers-reduced-motion` 降级。
- 输入框改造破坏 Ant Design Form 绑定：保留 `Form.Item` 的 `name` 和受控 `Input.TextArea`，不另建独立状态。
- 未接入的辅助能力：不让按钮伪装成已完成上传/分析功能，点击只显示轻量提示。
