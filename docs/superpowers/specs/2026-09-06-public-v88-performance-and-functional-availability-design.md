# 公网 V88 性能与全功能可用性设计

**日期：** 2026-09-06
**目标：** 在不破坏现有业务、正式数据和公网入口的前提下，修复公网静态资源传输慢、版本身份漂移和功能不可用问题，完成当前 V88 功能线的可追溯发布与全功能验收。

## 1. 当前现场与问题定义

公网入口为 `http://115.190.156.223:3000/`。现场证据显示：

- `/` 和 `/api/build-info` 的 TTFB 约 0.1 秒，入口和后端首页计算不是主要瓶颈。
- `/novel-panel/workbench/app.js` 原始约 1.55MB，gzip 后约 455KB，公网实测传输约 3.0–4.1 秒。
- 小说面板工作台由一个大单体 `app.js` 加载多个功能脚本，首屏下载了非首屏能力。
- 当前公网 `/api/build-info` 仍返回 `v78.3.0.3`，但批量工厂 bundle 已包含 `/api/batch-factory/v11`、provider、director 等 V11/V88 线能力。
- 因此当前公网存在“版本元数据仍为 V78、功能代码已进入 V88/V11 线”的身份不一致，不能直接视为已验收的 V88 正式发布。

## 2. 目标与非目标

### 目标

1. 以当前公网实际功能线 V88 为验收目标，覆盖现有入口和 V11 batch/provider/director 工作流。
2. 让版本元数据、Git revision、镜像 digest、实际 served bundle 指向同一候选版本。
3. 降低小说面板首屏传输量和重复下载，保持 API、登录态、保存、历史、导出、上传和长任务行为不变。
4. 在隔离候选环境完成全入口、认证态、持久化、重启恢复和浏览器回归后，才允许公网切换。

### 非目标

- 不重写 V88/V11 业务逻辑。
- 不在验收前修改公网 `:3000`、旧容器、正式数据卷或 MySQL 正式数据。
- 不把未验收的 V88 候选功能伪装成已完成能力。
- 不通过删除镜像、清理卷或强制重置工作树解决问题。

## 3. 发布隔离与版本身份

当前工作树存在用户未提交改动，候选构建必须使用干净的隔离 worktree；不得混入 `data/`、锁文件、计划文档或其他无关修改。

候选发布前记录：

- Git commit 和 ancestry；
- OCI image digest 与 revision；
- `/api/build-info` 返回值；
- 首页、批量工厂、小说面板关键 bundle 的 SHA-256；
- Compose 服务、容器 ID、正式数据卷 ID。

版本身份契约要求 `/api/build-info` 不再硬编码旧 V78 标识，而是由候选发布元数据生成，并与实际 served bundle 和镜像 revision 一致。身份不一致时，候选只能继续诊断，不得发布。

## 4. 性能设计

### 4.1 静态资源交付

- 工作台 JS/CSS 使用发布版本或内容 hash URL。
- HTML 保持短缓存，避免入口更新后无法生效。
- 带 hash 的 JS/CSS 使用 `public, max-age=31536000, immutable`。
- `/api/*`、草稿、历史、用户数据、上传和 AI/视频任务继续禁止缓存。
- Nginx 为 `/novel-panel/workbench/` 增加独立静态规则，启用 gzip、响应缓冲和连接复用；API 和流式请求继续使用原有长超时与非缓存策略。

### 4.2 工作台渐进拆分

保留现有 DOM ID、全局函数、bridge API 和接口数据结构，不重写业务。将资源按边界拆为：

- 首屏核心：页面初始化、原文输入、基础分镜；
- 历史、保存、恢复和导出；
- AI 分析、人物卡和关系图；
- 精品图片、素材和高级设置；
- 诊断与运行状态。

非首屏模块在用户进入对应能力时加载。加载失败时显示可重试错误，并保留其他模块；候选构建缺少拆分资源时回退到旧版完整入口。

## 5. 功能与错误处理

验收必须覆盖首页、剧本生成、小说获取、小说面板、水货生产、Agent、批量工厂、批量工厂预览、设置、配音、历史、问题日志、个人中心和退出登录。

V88/V11 专项覆盖：

- batch intake、TXT/MD 导入和批次创建；
- batch 列表、详情、状态更新和重启恢复；
- provider/director 任务创建、轮询、失败回执和重试；
- 视频生成、合并、上传和发布边界；
- 设置快照、权限和持久化。

所有写入流程使用隔离候选数据和受控测试配置。任何 API 错误必须在 UI 显示可理解的失败原因、重试入口和当前任务状态，不得静默伪成功。

## 6. 验证与发布门禁

### 自动验证

- 相关 Node 测试、前端构建和静态资源契约测试通过；
- 所有 HTML 引用的资源返回 200，无缺失 chunk；
- 版本元数据、bundle hash、Git revision 和镜像 digest 相互匹配；
- Nginx 配置语法、gzip、缓存和缓冲契约通过。

### 浏览器与业务验证

- 匿名页面、登录态页面、iframe 和会话续期通过；
- 关键保存、恢复、导出、上传、任务状态和重启恢复通过；
- 浏览器控制台无新增致命错误；
- V88/V11 provider/director 链路在候选环境完成真实受控闭环。

### 性能目标

- 首页和轻量 API TTFB 保持在 0.2 秒级；
- 小说面板首屏关键资源压缩后控制在 200KB 级别；
- 工作台首屏在当前测量网络下控制在 1.5–2 秒；
- 路由切换不重复下载已缓存的版本化资源。

### 发布与回滚

发布前备份线上 Compose/Nginx 配置，保留旧镜像、旧容器和正式卷。只替换必要服务，禁止 `docker compose down -v`。出现核心入口失败、版本身份漂移、资源 404、保存/恢复/导出失败、性能较基线恶化超过 20%，或非预期容器/卷变化时立即回滚。

如果远端运维访问仍不可用，只完成候选验证，不宣称公网已发布。
