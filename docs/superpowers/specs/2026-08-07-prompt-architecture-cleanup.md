# Prompt 架构清理与场次约束设计文档

## 背景

剧本模式输出场次过多（用户输入生成 8 场），根因是 prompt 层面存在两类问题：

1. **指令归属错位**：剧本专属的执行规则（对白分级、△画面规则）错误地放在通用规则中，而通用规则中包含与执行模式冲突的条款（禁止OS）
2. **场次定义缺失**：模型将同一场景内的镜头切换（△段落）错误拆分为独立场次，缺少明确的场次边界定义和防拆机制

## 架构原则

```
通用规则.md   = 大脑（思考原则）
  ↓
爆款开头.md / 连续开头.md  = 决策层（叙事策略）
  ↓
剧本模式.md / 剧情模式.md / 画布模式.md  = 执行层（检查 + 输出）
```

## 冲突审查结论

| # | 疑似冲突 | 结论 |
|---|---------|------|
| 1 | `从第一句开始` vs 炸雷前置 | **不存在**。爆款开头是在第一句前可选前置钩子，原文起点不变 |
| 2 | `禁止OS` vs V.O./O.S. | **存在**。通用规则删掉禁止OS那行 |
| 3 | 时长定义混乱 | **不存在**。30s=叙事总长，10s/15s=视频切片单位 |
| 4 | 场景/场次/镜头混用 | **存在**。剧本模式统一定义三层术语 |
| 5 | `不能无中生有` vs 路径B创生 | **不存在**。创生是强化不是例外 |

### 剧本模式.md — 重写

新结构：

```
# 剧本模式输出格式

## 一、场次定义（铁律）
## 二、场次防拆禁止项
## 三、输出前场次自检（强制）
## 四、对白括号 A/B/C 分级  ← 从通用规则搬入
## 五、△ 画面描述规则      ← 从通用规则搬入
## 六、输出格式模板          ← 保留现有
```

#### 一、场次定义（铁律）

```
场次 = 同一连续空间 + 同一段连续时间
场景 = 场次的头部信息（地点·内/外·时间 + 出场人物）
镜头 = △ 段落，同一场次内的画面单元

一场内可以有任意多个 △（镜头）。
镜头之间可以切镜、跳轴、人物进出、平行事件——只要空间没变且时间连续，仍然是一场。

换场次的唯一条件：空间变了，或者时间线发生了不可跳过的事件段落断裂（跳到另一个时刻/另一天）。
```

#### 二、场次防拆禁止项

| 错误做法 | 正确做法 |
|---------|---------|
| 同一空间内因切镜而建新场次 | 用"切镜"标注在△段落内过渡 |
| 同一空间内因人物进出而建新场次 | 人物进出是同一场内的调度 |
| 同一空间内因情绪转折而建新场次 | 情绪转折用△段落衔接 |
| 同一空间内因快闪/OS/VO而建新场次 | 快闪、OS、VO 都是△段落内的元素 |

反例对照：
```
❌ 1-7 厨房 △小姨拿手机 → 1-8 门口 △修理工按门铃（同一连续事件）
✅ 全部在 1-7 内，两个△段落之间自然衔接

✅ 6-1 清水村（早上王志离开）→ 6-3 清水村（之后苏家拆墙）
   ——时间线断裂，合理换场
```

#### 三、输出前场次自检（强制）

输出完成后，对每个 `X-N → X-(N+1)` 的边界逐一回答：

> "新建这一场，是因为空间变了，还是时间线发生了不可跳过的事件段落断裂？"

答"否" → 必须合并回前一场。然后重新输出。

#### 四、对白括号 A/B/C 分级

从通用规则.md 原样搬入，内容不变。

#### 五、△ 画面描述规则

从通用规则.md 原样搬入，内容不变。

#### 六、输出格式模板

保留现有格式模板和标注规则（V.O./O.S./▲ 等），删除原有的 `场次数量约束` 表格及 `{10s或15s}` 占位符。
```
