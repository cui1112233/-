# 批量工厂主入口收口

## 目标

`/shuihuo-production` 与 `/batch-factory` 显示同一个批量工厂主工作台；小说获取交接也进入该工作台和对应批次。用户不再经过旧水货生产项目库、漫剧工作台或运行依赖条才能使用批量工厂。

## 已确认的边界

- 水货生产与小说获取是同一批量工厂的两个入口，不是两套生产链。
- 批次列表、统一配置、自动生产、单书配置、资产、导演分镜、配音、VIDEO、合并、上传均由同一 `BatchFactoryNovelList` 工作台承载。
- 小说获取携带的 `intake` 仍按现有规则创建或追加到批次，并在交接后直接打开该批次。
- 旧水货漫剧项目、项目库、资产弹窗及运行依赖读取不删除，但不在这两个批量工厂入口执行或显示。
- 不迁移、不删除任何批次、小说、资产、自动化预设或历史工作数据。

## 设计

新增一个只负责批量工厂入口状态的页面容器。它只读取批量列表、当前批次及小说获取交接；选择或新建批次后，渲染现有 `BatchFactoryNovelList`。创建批次的弹窗和自动化启动继续复用已存在的 `BatchFactoryNovelList` 与批量 API，不复制生产逻辑。

`/shuihuo-production` 和 `/batch-factory` 都路由到该容器，因此两条地址的页面结构、可选视频提示词、统一配置与单书工作台完全一致。旧 `ShuihuoProductionPage` 保留为历史兼容组件，避免破坏漫剧项目路径；它不再担任批量工厂入口。

## 错误处理

- 批量列表读取失败时显示批量工厂级错误和重试，不再混入旧水货项目失败。
- 小说获取交接失败时只报告交接失败，保留当前批次列表和可继续手工新建的能力。
- 不读取旧 `getProductionHealth`，所以未配置的旧模型/依赖不会遮挡或禁用批量工厂。

## 验收

1. 两个地址导入相同入口容器，且均不引用旧水货项目库、`CommentaryWorkbench` 或运行依赖条。
2. 两个地址均可展示批次列表、创建批次并打开 `BatchFactoryNovelList`。
3. 小说获取 `intake` 交接创建/追加批次后，仍在同一容器打开对应批次。
4. 源码回归测试、相关前端测试与构建通过；浏览器在 `127.0.0.1:5173` 验证两条入口视觉一致。
