# 巨量素材：正文获取优先方式开关

日期：2026-10-01  
状态：用户已确认设计，待评审后进入实现计划  
范围：水火生产 → 新建批量 → 书城选择“巨量获取”时的“立即执行”方式选择。

## 目标

让用户在创建巨量素材批量时，决定正文优先从哪里取得：

- **默认模式**：先用视频滚屏 OCR；OCR 失败后，自动按书城和 Book ID 直接抓取原文。
- **直接原文模式**：不启动 OCR，先按书城和 Book ID 直接抓取原文；失败后停下并由用户决定重试或改用 OCR。

两条路径永远不能并行写同一本书的正文，也不能覆盖已经成功保存的正文。

## 已确认前提

巨量素材 ID 先由青语素材查询解析，得到：书名、书城、平台 Book ID、视频地址及视频时长。

这一步不是 OCR。OCR 只从视频画面读取正文；书城正文获取只依赖已解析出的书城和 Book ID。

如果青语解析没有返回有效书城或 Book ID，不能走书城正文接口；页面必须说明“缺少书城或 Book ID”，并只保留 OCR（有视频时）或失败状态。

## 界面与交互

### 新建批量弹窗

书城选“巨量获取”后，在“立即执行”旁增加一个开关：

```text
优先直接获取原文  [关闭 / 开启]
```

- 默认**关闭**，并显示说明：`先读取视频滚屏；失败后自动通过书城获取正文。`
- 开启时显示说明：`跳过视频 OCR，优先通过书城和 Book ID 获取正文；失败后可手动改用 OCR。`
- 该开关只作用于本次创建的这批书，不修改账号全局偏好，也不影响普通书城批量。

### 执行后状态

| 方式 | 第一动作 | 成功 | 失败 |
|---|---|---|---|
| 开关关闭 | 派发滚屏 OCR | 正文回填，进入正常 AI 判断和制作流程 | 自动尝试书城正文获取 |
| 开关开启 | 直接请求书城正文 | 正文回填，进入正常 AI 判断和制作流程 | 不自动启动 OCR；状态显示失败原因 |

直接原文模式失败后，小说列表“内容”位置显示两个明确按钮：

- `重试获取原文`：再次使用同一书城和 Book ID。
- `改用滚屏 OCR`：用户确认后才创建/派发视频 OCR 任务。

若默认 OCR 模式失败、自动书城兜底也失败，则显示相同两个按钮：`重试获取原文` 与 `重新读取滚屏`。

## 数据与后端行为

### 读取方式持久化

每本巨量占位书在既有 `sourceMetadata` 中保存：

```json
{
  "sourceMode": "giant_material",
  "originalReadStrategy": "ocr_first | direct_first",
  "originalReadStage": "pending | ocr | direct | completed | failed",
  "originalReadError": "可展示的最后一次失败原因"
}
```

使用已有 JSON 元数据，不增加新的全局开关或独立业务表。这样刷新页面、关闭弹窗、执行器重连后仍能判断当前书该走哪一步。

### 写入保护

1. 任何正文写入先检查该书正文是否已非空；非空则返回当前结果，不覆盖。
2. 同一本书的 OCR、书城取文用同一“正文读取”租约/幂等键串行化；第二条请求只返回进行中的状态。
3. 只有正文实际写入成功，才触发 AI 判断与后续自动制作。
4. 成功记录来源：`巨量素材 · <巨量ID> · 滚屏OCR` 或 `巨量素材 · <巨量ID> · 书城直取`，保留可追溯性。

### 路径细节

**OCR 优先（默认）**：解析 → 登记占位书 → 派发执行器 OCR → 成功回填；OCR 失败后由服务端调用现有书城取文能力。书城取文成功即结束，失败则记录两段失败原因。

**直接原文优先**：解析 → 登记占位书 → 调用现有书城取文能力。成功即结束，且不创建 OCR 任务。失败时不自动消耗执行器；用户手动点“改用滚屏 OCR”才派发任务。

## 错误与边界

| 情况 | 用户看到的结果 |
|---|---|
| 青语解析失败 | 该 ID 标红，不能创建；不影响其余 ID |
| 无书城或 Book ID | 明确提示无法书城直取；如有视频则可选 OCR |
| 书城接口失败 | 保留失败原因与重试按钮，不伪造正文 |
| OCR 失败但书城直取成功 | 状态为“已通过书城获取正文”，正常继续制作 |
| 用户点击改用 OCR 时无在线执行器 | 任务保持等待并显示“等待执行器”，不假报失败 |
| 多条 ID 中部分失败 | 成功书照常继续，失败书各自可重试，不阻塞整批 |

## 验收

1. 新建巨量批量时，开关默认关闭，文案与实际 OCR 优先行为一致。
2. 默认模式制造 OCR 失败：系统自动书城取文；成功后书卡有正文且进入正常流程。
3. 开启直接原文：无 OCR 任务被创建；书城成功后正文回填。
4. 开启直接原文且书城失败：显示失败原因和“重试获取原文 / 改用滚屏 OCR”，OCR 在用户点击前不启动。
5. 同一本书并发点击不会覆盖已保存正文，也不会启动两份制作流程。
6. 普通书城批量、既有巨量 OCR 优先流程及多 ID 导入回归通过。

## 明确不做

- 不把书城直取当作所有巨量 ID 都必然可用的能力。
- 不从视频 OCR 推断书名、书城或 Book ID。
- 不同时运行 OCR 与书城正文抓取。
- 不改变设置页的 Windows/macOS 执行器优先平台开关。
