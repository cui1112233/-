# V88 小说获取批次隔离与渐进式处理设计

## 目标

修复公网小说获取中“今天混入历史任务、当前批次数量膨胀、新任务排在后面、输入后长时间不可见、处理进度不逐本反馈”的流程问题，同时明确并保留定时任务的自动上传闭环。

## 已确认根因

1. 任务日期筛选优先使用 `updatedAt`，旧任务在今天被处理或提交后会被误算为今天；默认无日期查询还会把历史未完成任务混入列表。
2. V2 批次在完成时使用全量任务列表重建 `taskIds`，导致一次输入的 8 本被扩展为历史任务总数（例如 11 本）。
3. 相同 Book ID 复用持久化任务记录，任务索引按更新时间排序；处理阶段更新旧任务时间后，新批次不能稳定保持输入顺序。
4. 队列启动后，任务元数据要等分类阶段结束才保存；抓取默认并发为 1，阶段进度在整批完成后才汇报，造成“输入后不显示”和“处理很慢”的体验。
5. 定时调度器会以 `scheduled=true` 启动队列。执行器在网站提交启用且 121 会话可用时自动上传，否则保留待上传/失败状态。

## 设计

### 1. 批次边界与日期

- 创建批次时固定保存本次解析后的 `taskIds` 和输入顺序。
- 批次完成时只更新该批次原有 `taskIds` 的 `taskStates`，不得从全量任务列表覆盖批次成员。
- 当前批次视图严格按批次 `taskIds` 渲染，数量、排序和状态均来自该批次。
- 任务日期筛选使用批次创建日期或任务首次进入批次的时间，不使用后续处理产生的 `updatedAt`。
- “今天”只显示今天的批次；历史未完成任务通过单独的历史/未完成筛选查看，不再混入“今天”。
- 对重复 Book ID，当前批次仍可显示该书，但沿用已有正文和版本状态，并在批次状态中标明“复用已有任务”。

### 2. 渐进式队列

- 输入解析成功后立即创建批次并写入轻量级排队任务元数据，前端立刻显示本批次书目和“排队中”。
- 每本任务在分类、原文、规则/敏感词、AI 改文、上传阶段更新自身状态；前端轮询现有任务接口即可逐本显示。
- 阶段报告按单本任务完成即时写入，不再等待整批阶段结束才汇总。
- 保留停止、暂停、失败重试和失败队列语义；停止只阻止未开始步骤，已完成内容保留。
- 抓取并发改为配置驱动，默认使用受控的小并发值；AI 并发继续遵守现有模型和限流配置，避免公网内存峰值。
- 当前批次列表按输入顺序显示，历史任务列表按批次创建时间倒序显示。

### 3. 定时上传状态

- 定时任务默认 `auto_submit=true`，到时由后台调度器启动队列，不依赖浏览器保持打开。
- 网站提交启用且会话可用：改文完成后自动上传，并保存成功/待确认回执。
- 网站提交未启用、会话失效、超时或上传失败：任务停在“待上传”或“失败”，显示原因并支持人工重试；不伪造成功。
- 定时任务管理继续保留查看、取消、删除和刷新入口，并显示“自动上传/需人工提交”预期状态。

## 接口与数据变更

- 扩展批次记录的任务状态字段，保留 `batchId`、首次进入批次时间和输入序号。
- `GET /api/batch-rewrite/tasks` 的日期查询改为按批次/首次进入时间过滤；当前批次查询显式传入批次 ID 或成员集合。
- 队列状态增加可读的当前阶段/当前任务信息；保持现有 `/process/queue/status` 和 `/process/jobs/:id` 兼容。
- 不删除已有任务数据，不覆盖原文、AI 文案、上传回执或知识库配置。

## 验证标准

- 新增 8 本时当前批次始终显示 8 本，旧批次不混入；输入顺序稳定。
- 点击“今天”不显示昨天已完成任务；历史未完成通过独立入口可见。
- 输入解析完成后立即能看到排队任务，随后逐本显示处理状态和失败原因。
- 定时任务在有效 121 会话下自动上传；无会话/失败时进入待上传或失败队列并可重试。
- 现有小说获取定向测试保持通过，并新增批次隔离、日期过滤、渐进状态和定时上传回归。

## 非目标

- 不改变现有公网 UI 的总体布局。
- 不修改 `master`、V78 生产分支、Go 服务、数据库表结构或线上数据卷。
- 不在本次改动中提高到无上限并发，也不绕过 121 登录/会话校验。
