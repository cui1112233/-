# CM 宠物交互修复设计

## 目标

让 CM 在所有 qiantie 功能页作为稳定的全局入口：用户可以可靠地移动宠物、打开对话、请求当前页面分析，并在完整 Agent 工作区继续同一条对话。CM 不应遮挡关键操作，也不应把轻微拖动误判为点击。

## 范围

本次覆盖：

- 宠物的拖拽、点击、收起、边界避让与位置持久化。
- 悬浮对话的打开、关闭、分析当前页、发送、加载、失败与跳转 Agent 工作区。
- 剧本、小说面板、配音、水货生产、历史、设置和 Agent 工作区的页面上下文摘要。
- 宠物任务与完整 Agent 工作区间的同一任务连续性。
- 浏览器级交互验证与针对状态机、上下文和定位算法的自动测试。

不在本次范围内：

- 改动 CM 的 Stacky 视觉资源或名称。
- 让 CM 自动写入、删除或提交用户数据。
- 为水货生产、小说面板或配音增加新的业务生成能力。

## 当前问题

当前精灵节点同时承担点击、双击和拖拽。轻微移动可能吞掉点击，双击又会先触发点击，导致打开面板与自动请求产生竞争。对话框和宠物分开定位，边角、缩放和小屏下无法以完整浮层尺寸做避让。

宠物创建独立任务，但不能继续进入完整 Agent 工作区的同一任务。共享布局只提供页面名称，除剧本页外没有可靠的页面数据摘要；CM 因此不能针对水货项目、配音卡片或小说面板给出具体建议。

## 交互设计

### 宠物控制

- 宠物主体只负责打开或关闭悬浮对话。
- 单独提供可见但不抢眼的拖拽把手；只有从把手开始的指针操作才移动宠物。
- 移动超过 8px 才算拖拽。拖拽结束后不触发点击。
- 删除双击自动分析。对话面板内提供明确的“分析当前页”图标按钮，并带悬停提示。
- 继续保留收起和唤醒。位置按视口尺寸裁切保存；收起后保持当前位置。

### 悬浮对话

- 面板与宠物使用同一个 `PetOverlayController` 计算布局。
- 布局计算输入包括：宠物矩形、面板尺寸、气泡尺寸、视口安全边距和顶部栏安全区。
- 优先在宠物左/右侧打开；两侧均不足时在上方打开；所有结果均裁切到安全区域内。
- 面板显示当前任务的完整可滚动消息历史，而不是固定四条。
- 发送区显示明确的加载状态；失败消息提供“重试”且不清空用户输入。
- 面板操作包括：分析当前页、关闭、在 Agent 工作区继续。后者导航到 `/agent?task=<id>`。

### 任务连续性

- 每个已登录账号保存一个 CM 当前任务 ID；退出登录、任务被删除或返回 404 时清除该引用并创建新任务。
- 宠物发送、面板加载、完整 Agent 工作区都读取同一任务 ID。
- Agent 工作区支持 `task` 查询参数，加载时选中该任务，确保“继续”不会创建新聊天。
- 任务消息仍由后端按账号隔离，页面上下文仅作为本次模型请求的临时数据，不写入任务记录。

## 页面上下文契约

新增统一的 `PagePetContext` 数据格式：

```js
{
  page: '水货生产',
  pagePath: '/shuihuo-production',
  summary: '当前项目：雨夜车站；已确认 6 个分段；图片任务 2 个进行中。',
  entities: { projectId: '...', selectedSegmentId: '...' },
  actions: ['检查分段', '检查任务状态']
}
```

- 共享布局始终提供 `page`、`pagePath` 和无业务数据时的基础摘要。
- 业务页面可以补充 `summary`、少量 ID 和可执行建议，不上传整份项目、私密凭据或无关媒体二进制。
- 剧本页保留当前已有的原文、人物场景和剧本结果上下文，但由统一契约组装并限长。
- 水货生产页提供当前项目名、确认分段数量、资产数量、任务状态摘要和当前视图。
- 配音页提供卡片数、默认声音和是否已有音频；小说面板仅提供当前项目或文档标题及当前工作阶段。
- 后端将 `summary`、`entities` 和 `actions` 显式拼入临时页面上下文，并继续执行现有长度上限。

## 组件边界

### `PetOverlayController`

负责读取和写入宠物位置、拖拽把手状态、视口变化和浮层布局。它不发网络请求，也不理解业务页面。

### `PetConversation`

负责当前任务 ID、消息加载、发送、重试、分析当前页和跳转完整 Agent。它通过页面上下文事件读取数据，但不解析各页面业务对象。

### `PagePetContext`

负责发布和合并当前页面摘要。页面组件只调用该接口，不直接操作宠物或任务。

## 错误处理

- 创建或读取任务失败：显示中文错误，保留已输入内容；允许重试。
- 任务不存在：清除本地任务引用，提示后创建新任务。
- 上游模型失败、超时或返回空内容：保留用户消息和输入，显示可重试状态；不伪造成功回复。
- 页面缺少业务数据：CM 明确说明只能提供该页面的通用建议，不声称已读取项目内容。
- 在拖拽、请求和页面切换并发时，使用请求序号或 `AbortController` 忽略过期加载结果。

## 验收与测试

自动测试：

- 纯函数测试覆盖拖拽阈值、所有边角的面板布局和小屏裁切。
- 组件测试覆盖拖拽不打开、单击打开、分析按钮只发一次请求、任务 404 后恢复。
- 路由测试覆盖临时上下文限长、账号隔离和任务连续性。

浏览器验证：

- 桌面和移动尺寸下将宠物拖到四个角，验证宠物、气泡和面板都不越界。
- 从剧本、配音、水货生产、小说面板分别发起“分析当前页”，验证回复引用对应的页面摘要。
- 从宠物点击“在 Agent 工作区继续”，验证 URL 带任务 ID、同一消息历史可见且可继续发送。
- 验证收起、唤醒、退出登录和重新登录不会泄露另一账号的任务或位置状态。

## 实施顺序

1. 提取并测试宠物位置和面板布局纯函数。
2. 将拖拽移至独立把手，移除双击自动分析，完成浮层交互状态机。
3. 引入账号级 CM 当前任务引用和 Agent 工作区深链。
4. 接入统一页面上下文，再逐页补充摘要。
5. 补自动测试和真实浏览器交互验证。
