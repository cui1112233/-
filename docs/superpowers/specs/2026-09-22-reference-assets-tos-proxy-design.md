# 人物参考图 TOS 访问修复设计

## 目标

修复剧本页面上传人物图片后一直显示“主图加载中”的问题，同时继续把图片保存到火山引擎 TOS。

## 已确认原因

当前上传和 AI 生图流程已经先把图片写入当前用户的本地参考图目录，再同步到 TOS。同步成功后，接口优先返回 TOS 的临时签名地址。

公网页面直接使用这个 TOS 地址读取图片时会失败，因此前端预览加载器一直拿不到图片内容。

## 方案

### 1. 新图片统一返回站内地址

上传接口和 AI 生图接口继续执行 TOS 同步，但返回值中的 `url` 改为现有的站内参考图地址：

`/api/novel-panel/reference-assets/file/:assetType/:assetId/:variant`

浏览器访问站内地址时，后端从当前用户的本地参考图缓存读取图片。TOS 仍作为外部持久化副本保存，不改变现有 TOS 上传逻辑。

### 2. 旧图片兼容读取

对于已经保存到人物数据中的旧 TOS URL，新增受限的 TOS 代理读取流程：

- 只允许访问配置中的 TOS Endpoint 或对应桶域名。
- 不允许把任意外部 URL 当作代理目标，避免形成服务器代请求风险。
- 代理优先从 TOS URL 中解析对象 key，并使用服务端 TOS 凭据重新生成短期签名地址。
- TOS 对象不存在、链接过期或读取失败时返回明确的图片读取错误。
- 前端将失败状态显示为“旧图片无法读取，请重新上传”，不再永久显示加载中。

### 3. 前端加载状态

人物图片面板继续使用现有的 blob 预览方式，但增加失败状态区分：

- 成功：显示图片。
- 加载中：显示“主图加载中”。
- 失败：显示“图片读取失败，请重新上传”。

上传接口返回站内地址后，新上传图片会直接走站内地址，不再依赖浏览器直接访问 TOS。

## 影响范围

- `routes/novel-panel.js`：上传和生图接口返回地址调整；增加受限旧 TOS 读取入口。
- `lib/novel-panel/premium-store.js`：提供站内地址和 TOS 对象读取所需的安全校验。
- `lib/novel-panel/tos-reference-assets.js`：补充 TOS 对象读取/签名能力，保留现有上传能力。
- `frontend/src/user/components/EntityImagePanel.jsx`：增加预览失败状态。
- `frontend/src/user/components/entityImagePreviewLoader.js`：保留逐图失败，不阻塞其他图片显示。

不修改图片存储位置，不删除已有本地缓存，不删除 TOS 对象，不新增 GitHub Actions，不修改其他媒体上传流程。

## 错误处理

- 上传图片格式、大小不合规：继续由现有上传接口返回中文错误。
- TOS 同步失败：继续返回上传失败，避免把未同步成功的图片地址保存到人物数据。
- 站内缓存不存在但旧 TOS 地址可解析：尝试从 TOS 重新读取。
- 旧 TOS 对象不存在或无权限：返回可识别错误，前端提示重新上传。
- 未配置 TOS：保留现有本地参考图功能，不因可选 TOS 配置缺失而让上传流程崩溃。

## 测试

增加或调整以下测试：

1. 上传接口在 TOS 同步成功后仍返回站内参考图地址。
2. AI 生图接口在 TOS 同步成功后仍返回站内参考图地址。
3. 站内图片接口可以返回本地缓存图片。
4. 旧 TOS URL 只允许访问配置的 TOS 域名。
5. 非法外部 URL 被代理接口拒绝。
6. TOS 对象读取失败时返回明确错误。
7. 前端图片预览在单张图片失败时显示失败状态，不影响其他缩略图。

## 验收标准

- 上传 PNG、JPG、WebP 人物图片后，人物主图可以正常显示。
- 页面网络请求中不再要求浏览器直接读取新上传图片的 TOS 临时 URL。
- TOS 中仍能找到对应的人物参考图对象。
- 已保存的旧 TOS 图片能正常读取时继续显示。
- 旧图无法读取时页面明确提示重新上传，不再无限转圈。
- 现有 AI 生图、人物资料保存和视频参考图流程不回归。
