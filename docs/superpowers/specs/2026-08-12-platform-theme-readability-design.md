# 全平台主题可读性设计

## 目标

在不改变一战晟铭既有页面结构、导航、业务流程和模块视觉语言的前提下，修复用户端、管理端和小说面板工作台在深色与浅色主题切换后出现的低对比文字、错误表面色和浮层主题脱离问题。

本次以“阅读可用”为验收重点：正文、辅助文字、输入值、占位文字、按钮、禁用态、表格、提示框、弹窗、抽屉、下拉、确认框和通知在两种主题下都必须可辨识。

## 已确认范围

- 用户端：首页、剧本生成、小说面板容器、Agent 工作区、历史、配音、设置和水货生产。
- 管理端：概览、账户治理、系统预设词、Agent Skill、提示词策略和水货生产模型目录。
- 小说面板 iframe：工作台的编辑器、卡片、表单、弹窗、通知和现有主题同步链路。
- Ant Design 组件及其 portal 浮层：`Modal`、`Drawer`、`Select`、`Dropdown`、`Popconfirm`、`Tooltip`、`message`、`Alert`、`Table`、`Tag`、`Upload`、`Segmented`、`Empty` 和禁用按钮。

## 非目标

- 不改变任一页面的业务数据、权限、模型、任务或项目逻辑。
- 不改变水货生产、管理端和小说面板的既有布局、导航信息架构或品牌主色。
- 不新增独立主题状态；平台主题仍以 `localStorage['yizhan-theme']` 和根元素 `data-theme` 为唯一来源。
- 不用一页的颜色规则覆盖另一页的视觉语言。

## 根因

当前主站的 Ant Design 全局 token 在多个局部页面主题之间共用。局部页面可以通过容器 CSS 变量改变正文和卡片，但 Ant Design 的浮层默认挂载在 `body` 下，不在页面容器内，无法继承局部变量。

结果是同一个组件可能产生“深色文字落在深色表面”或“浅色文字落在浅色表面”的组合。截图中的水货生产信息提示框即属于该类问题：页面已经是深色工作台，而 `Alert`/输入控件仍受到全局与默认表面的混合影响。

小说面板有主站到 iframe 的主题消息同步，且工作台已有变量层；但工作台残留的硬编码颜色和弹层选择器仍需要与平台语义令牌逐项核对。

## 架构

### 1. 语义主题令牌

在 `frontend/src/shared/styles/global.css` 中维护平台公共令牌，覆盖以下语义：

- 页面背景、主要表面、弱表面、输入表面。
- 主文字、辅助文字、弱文字、占位文字。
- 普通边框、强调边框、焦点态。
- 主按钮、默认按钮、危险按钮和禁用态。
- 信息、成功、警告、错误提示表面与对应文字。

深色和浅色主题只替换令牌值。公共组件以语义令牌渲染，禁止用只适合单一主题的固定浅灰或深灰文字补丁。

模块仍可定义自身的强调色和表面变量：水货生产保留绿色制作台，管理端保留蓝灰信息台，小说面板保留现有工作台风格。它们的变量必须映射到可读的主文字、辅助文字、表面和边框层级。

### 2. 浮层主题边界

每个存在独立视觉变量的模块，在挂载期间将唯一主题标记添加到 `document.body`，卸载时移除。管理员布局已经采用 `admin-theme-active` 模式；水货生产采用同样的生命周期边界。

这些标记负责给挂载到 `body` 的组件提供主题样式，包括：

- Modal/Drawer 的内容、头部、底部、标题、关闭按钮。
- Input、TextArea、Password、Select、Segmented、Upload 与其占位文字、箭头和输入值。
- Select 下拉项、Dropdown 菜单、Popconfirm、Tooltip、Message/Notification。
- Alert、Empty、Table、Tag、Pagination、普通/危险/禁用 Button。

全局 portal 规则必须按“当前挂载模块”限定，避免水货生产的绿色令牌覆盖管理端或普通用户端弹层。

### 3. Ant Design 全局主题

`frontend/src/shared/styles/theme.js` 只承载平台的基础 token。它必须补齐两种主题对应的文本、容器、输入、边框、禁用和状态 token，或由包裹各入口的 `ConfigProvider` 按 `data-theme` 切换 token。

页面级 CSS 只处理模块的视觉差异与 portal 边界，不能再依赖模糊的 `rgba` 背景作为唯一表面色。全局 token 与 CSS 覆盖冲突时，以“可读性和模块隔离”为准，删除冲突的硬编码选择器。

### 4. 小说面板 iframe

保留 `NovelPanelPage` 向 iframe 发出 `{ type: 'qiantie-theme-sync', theme }` 的现有安全协议；不改变 iframe sandbox、Bearer API 桥接和消息内容边界。

工作台 `public/novel-panel/workbench/style.css` 将完成变量审计：正文、辅助文字、输入、卡片、模态框、提示、按钮和选中态必须使用已定义的 `--bg`、`--surface`、`--surface-soft`、`--ink`、`--muted`、`--line` 等语义变量，或补充等价变量。仅在无法替换的第三方/遗留节点上使用局部覆盖。

## 数据流与主题状态

1. `UserLayout` 读取和更新唯一平台主题状态，写入根元素 `data-theme`。
2. 用户端、管理端和水货生产从根主题获得对应 CSS 令牌。
3. 存在独立表面系统的页面，在 mounted 后给 `body` 添加模块标记，使其 portal 浮层继承相同令牌；unmount 后清理标记。
4. 小说面板接收父站主题消息并设置 iframe 根元素 `data-theme`；其内部 CSS 用变量重新计算颜色。
5. 浏览器审计在每条路由的深色、浅色状态下读取可见控件的计算前景色与背景色，发现低对比组合即修复来源选择器，不用遮罩或透明度隐藏问题。

## 错误处理与兼容

- 主题值只允许 `dark` 与 `light`；非法或缺失值回退到深色。
- 浮层激活标记必须在组件卸载时移除，路由切换后不得残留并污染其他模块。
- 若两个独立模块因导航过渡短暂并存，后挂载模块拥有其自身浮层；不使用未限定的全局 `.ant-modal-content` 覆盖。
- iframe 主题消息继续只接受父窗口、固定消息类型和白名单主题值；不在主题消息中传递账号、Token、项目或模型信息。
- 失败提示必须保持文字与背景可读，不能用主题错误掩盖真实错误信息。

## 测试与验收

### 自动测试

- 静态主题契约测试：验证根主题变量、两套主题值、模块 portal 标记、浮层选择器和 iframe 主题同步协议存在。
- 前端构建：`npm --prefix frontend run build`。
- 既有 Node 路由与页面契约测试继续通过；新增测试只覆盖主题可读性边界，不引入业务 mock。

### 浏览器审计

以已登录会话逐页检查用户端和管理端路由；每页至少进行一次深色与浅色切换。检查正文、辅助文字、输入值、placeholder、按钮、禁用按钮、表格、Alert、Tag、Empty。

对包含触发器的页面再检查 Modal、Drawer、Select dropdown、Dropdown、Popconfirm、Tooltip 和 message。对小说面板，确认父站切换后 iframe 不刷新即可同步，并检查工作台内编辑器、卡片和对话框。

验收时，关键文本和控件标签与其实际背景达到普通文本可读水平；若计算样式或截图显示同色/近似色组合，则不能通过。所有按钮文字不得被背景吞没，禁用态仍需清晰表达“不可操作”。

## 实施顺序

1. 先建立主题令牌和静态审计测试，证明现状缺少页面/portal/iframe 覆盖。
2. 修复用户端公共控件和普通 portal。
3. 修复管理端 portal 边界并保持管理员视觉隔离。
4. 完成水货生产的 Alert、表格、编辑器和所有 portal 状态。
5. 审计并修复小说面板 iframe 内硬编码表面。
6. 运行构建、契约测试与双主题浏览器回归，并记录未能触发的受权限或无数据限制状态。
