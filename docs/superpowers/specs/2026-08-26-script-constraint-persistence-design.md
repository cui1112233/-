# 剧本生成约束与基础设定持久化设计

## 目标

所有剧本输出模式统一由本次的子开关决定是否允许输出完整人物与场景设定。`基础设定（人物/场景）` 关闭时，AI 不接收完整人物/场景卡，模式提示词不再要求独立人物/场景区块，最终卡片也不补入该区块。

`后续剧本输出约束` 不再是本次输出的总门禁。它只决定本次选中的子开关是否保存为下一次生成的默认值。

## 交互语义

| 操作 | 本次生成 | 下次生成 |
| --- | --- | --- |
| 单独打开基础设定 | 输出人物/场景设定 | 不沿用，生成后恢复默认关闭 |
| 单独打开画质等子约束 | 应用对应约束 | 不沿用，生成后恢复默认关闭 |
| 打开后续剧本输出约束，并开启任意子约束 | 应用当前子约束 | 保存整套选择并自动恢复 |
| 关闭基础设定 | 不传人物/场景卡；不输出独立人物/场景块 | 若持久化已开启，保存为关闭 |

人物称谓、剧情动作和原文已明确的地点仍可出现在时间轴中。这些是剧情正文，不属于“完整人物/场景设定”区块。

## 实现边界

1. 前端将本次约束草稿与已持久化的默认约束分开。生成请求总是发送本次草稿。
2. 服务端仅在本次 `baseSetup.enabled` 为真时，向 AI 输入完整人物与场景卡；否则只发送小说原文。
3. 五种格式提示词删除无条件要求人物/场景设定的描述，改为“仅在收到基础设定时输出该块”。
4. 最终分镜卡仅在本次 `baseSetup.enabled` 为真时补入基础设定；同时清理模型擅自输出的独立人物/场景块，防止绕过开关。
5. 无持久化选择的生成完成后，清空本次子开关；启用持久化时，保存当前选择并作为下一次草稿初值。

## 验收与发布

1. 增加前后端契约测试：基础设定关闭时，所有模式均不发送人物/场景卡且最终卡无独立人物/场景块；开启时保留。
2. 运行受影响的 Node 测试、`npm --prefix frontend run build` 和 `git diff --check`。
3. 只暂存本次源代码、测试和设计文档，执行单独 Git 提交并 `git push` 到当前分支；不混入运行数据、凭据或其他未提交功能。
4. 执行 `bash scripts/deploy-test-docker.sh up`，再执行 `bash scripts/deploy-test-docker.sh health`。
5. 验证 `http://10.0.101.164:3000/script` 与 API 健康可访问；不将 HTTP 成功等同于真实付费模型调用成功。

## 非目标

- 不删除小说正文中为叙事必要而出现的人名、动作或地点。
- 不迁移历史已生成内容。
- 不改变短剧、剧情、画布、分镜、Q 版等模式的时间轴与格式协议，除人物/场景设定门禁外。
