# 小说面板完整接入与系统预设词治理设计

## 目标

将原“视频画面提示词工具”完整接入 qiantie，导航名称改为“小说面板”。它是从小说原文到人物、分镜、时间轴、配音和导出的详细生产台；现有“剧本生成”继续保留为快速 10/15 秒输出工具。

小说面板不启动 Windows EXE，不依赖旧工具的本机端口，也不打开外部工具页面。所有操作均在 qiantie 的统一导航、登录和账号体系中完成。

同时建立系统预设词库、主账号治理、局部授权和账号申请机制，使系统预设词能提供多个可选方案，同时保持真实规则、权限和审计安全。

## 已确认范围

### 导航与工作台

用户端导航保留两个不同职责的入口：

| 导航项 | 定位 |
| --- | --- |
| 剧本生成 | 快速版：已有的连续开头、爆款开头、10/15 秒和画布/剧本/剧情输出。 |
| 小说面板 | 详细版：原视频画面提示词工具的完整生产工作台。 |

小说面板使用 qiantie 的左侧导航、登录状态、账号信息和主题。进入内容区后保留原工具的顶部工具栏、面板顺序、按钮语义和生产步骤；不复制原工具的独立浏览器启动、窗口管理和 EXE 运行逻辑。

### 小说面板完整功能

下列能力均属于第一版完整接入范围：

1. 整段小说原文输入、文本处理、项目命名、保存和历史项目。
2. 内容类型与统一视觉风格判断、人工锁定和优化。
3. 强制人物名单、人物共性要求、人物卡生成、单卡重试、人物关系图、称呼映射和场景选角。
4. 不可遗漏内容、镜头节奏、提示词密度和案例逻辑约束。
5. 整段原文生成分镜/画面、逐条补充意见和单条重生成。
6. 时间轴镜头卡、按秒数分段并合并、复制和 TXT 导出。
7. 配音生成、试听、下载、音色、风格、语速和音调设置。
8. AI 指令中心：指令分组、协议锁说明、指令编辑、AI 修改建议、AI 改写、错误纠正、当前项目保存、默认预设和实际发送预览。

原工具的业务字段、镜头时间格式、人物身份字段和 JSON 层级保持兼容。原工具中依赖 Windows 启动器、独立浏览器配置、根目录日志和 EXE 的部分不迁入。

## 页面与数据架构

### 页面边界

- 用户端新增 `/novel-panel`，由用户端 React 入口承载。
- 用户端导航顺序为：首页、剧本生成、小说面板、Agent 工作区、历史项目、配音、设置。
- 小说面板内容作为受作用域保护的工作台模块挂载，避免原工具样式覆盖 qiantie 的导航、登录和其他页面。
- 当用户在小说面板时，保留其内部完整顶部栏和原有主面板布局；窄屏只做原工具已有语义的可用性适配，不将复杂工作台压缩成信息缺失的卡片页。

### 后端边界

- qiantie Express 后端新增小说面板的受鉴权 API 域，例如 `/api/novel-panel/*`。
- 该 API 域负责项目、人物、关系、风格、分镜、时间轴、配音、导出和指令处理。
- AI 调用使用 qiantie 统一设置中心的服务配置，不再请求旧工具的 `127.0.0.1:8818`。
- 原视频工具的纯浏览器质量闸门迁入后，必须在任何状态写入、历史保存和外层同步之前执行。

### 用户数据

小说面板数据按当前登录账号隔离，建议数据根为：

```text
data/users/<username>/novel-panel/
  projects/<project-id>.json
  outputs/<project-id>.txt
  settings.json
  instruction-overrides.json
```

旧视频工具数据只迁移给主账号 `choushiyiguai`。迁移仅读取原目录，不删除或覆盖原文件；重复执行不生成重复项目。其他账号始终以空白小说面板开始。

## 统一设置

设置中心统一管理所有工作台共享的 API 地址、密钥和默认模型。小说面板保留原工具独有参数，但作为统一设置页面中的“小说面板”分组，包括生成超时、配音音色、风格、语速和音调。

共享配置变更必须明确提示会影响哪些工作台。小说面板独有参数不得改变快速剧本生成和独立配音页面的运行结果。

## 写入保护与失败行为

小说面板沿用原视频工具的安全写回原则：

1. 整段生成和单条重生成均在写入前进行结构、原文覆盖、可展示性、人物名单和变化检查。
2. AI 返回 JSON 不完整、原文覆盖不足、人物名单冲突、规则污染或单条重生成没有实际变化时，保留已有有效分镜，不覆盖状态。
3. 失败接口返回明确的未应用状态；外层人物同步、历史保存和后置操作必须识别该状态并跳过。
4. 人物卡按单卡隔离重试；某张失败不清空已经成功的人物卡。
5. 网络错误、超时、解析失败和取消操作只能保留现有项目并提示原因，不能回滚无关数据或跨账号写入。

## 系统预设词库

### 用户选择模型

系统预设词库提供多个可选项，采用“一个基础预设词 + 多个兼容补充项”模型：

- 基础预设词决定一次生成的整体叙事与生成逻辑。
- 补充项只负责已声明的专项方向，例如视觉风格、镜头节奏、人物一致性或特定题材约束。
- 系统保存预设所属模块、用途、兼容关系、版本、状态和说明。
- 用户仅可见名称、用途、适用模块、效果说明和兼容性；真实系统预设词正文不下发到普通用户浏览器。
- 后端在生成时组合已选基础预设词和补充项，并检查冲突、重复和不适用组合。

### 指令中心与预设词的关系

原工具的 AI 指令中心仍完整保留，但访问能力受权限控制：

- 普通账号可选择系统预设词，并维护自己的项目级补充要求；不能读取、复制或编辑真实系统预设词正文。
- 有授权的预设词管理员仅能在被授权的模块和能力范围内处理预设词。
- 主账号可以查看、编辑、发布、恢复和审计所有预设词。
- 无论谁编辑预设词，都不能改变 API 路径、请求/响应字段、JSON 层级、时间格式和人物身份字段等协议锁内容。

## 权限与账号治理

### 主账号

`choushiyiguai` 是唯一主账号，拥有不可转授的最高管理权：

- 审批账号申请、启用或停用账号、重置账号密码。
- 授予和收回管理员权限。
- 管理全部系统预设词和版本回滚。
- 查看全部审计记录。

### 可授予角色

权限采用“能力 + 范围”两层模型，而不是单一管理员开关：

| 角色 | 可授予能力 | 范围 |
| --- | --- | --- |
| 账号管理员 | 审批申请、启用/停用、重置密码 | 不含预设词权限。 |
| 预设词草稿管理员 | 新建和编辑草稿、请求发布 | 仅授权的模块，例如仅小说面板。 |
| 预设词发布管理员 | 审核、发布、回滚已授权模块的版本 | 仅授权的模块。 |
| 普通账号 | 使用生产工具、管理自己的项目和个人补充要求 | 仅本人数据。 |
| 申请中账号 | 提交账号申请、查看申请状态 | 无生产与管理权限。 |

主账号可为同一人组合多项局部权限。局部预设词管理员不能管理其他模块、不能处理账号，也不能扩大自身权限。

### 账号申请

- 未登录用户可以提交账号申请，包含必要的账号名称和申请说明。
- 申请状态为待审、已通过、已拒绝或已撤回。
- 申请中账号不能调用任何生产 API。
- 主账号或账号管理员审批后创建或激活账号，并记录审批结果。

### 审计

下列行为必须记录操作者、时间、对象、操作结果、前后版本或前后权限：预设词草稿、发布、回滚、授权、收回、账号申请审批、账号启用/停用和密码重置。审计记录只有主账号可完整查看。

## 分阶段实施顺序

1. 建立角色、权限、账号申请和审计的后端保护；任何管理页面在此之前不得开放真实管理操作。
2. 建立系统预设词目录、版本、兼容检查和后端组合接口。
3. 建立小说面板的按用户项目存储、旧工具数据迁移和统一设置分组。
4. 将原视频工具完整工作台接入 `/novel-panel`，保留布局与功能顺序，移除 EXE/独立窗口依赖。
5. 迁入并连接质量闸门，确保所有分镜写回都在状态变更前校验。
6. 扩展管理端：账号申请、账号权限、预设词库、版本与审计页面。
7. 做页面、权限、迁移、生成、失败保护和回归验收。

## 验收标准

1. 导航中同时存在快速版“剧本生成”和详细版“小说面板”，职责清楚且无外部跳转。
2. 小说面板完整覆盖原工具确认的八类功能，布局与操作顺序保持一致。
3. 不启动 EXE，不依赖旧工具本机端口；AI 调用由 qiantie 后端完成。
4. 旧数据只迁移给 `choushiyiguai`，保留源文件，可重复迁移且不重复；不同账号数据互不可见。
5. 所有整段和单条分镜写回在质量闸门通过前不得覆盖已有有效结果。
6. 普通账号只能选择预设词元信息，不能获取真实系统预设词正文。
7. 基础预设词和补充项的冲突组合被后端拒绝，兼容组合真实影响生成。
8. 账号管理员不能管理预设词；局部预设词管理员不能越过授权模块或自我提权；无权限调用管理 API 返回拒绝。
9. 每次预设词发布、回滚、授权、收回和账号审批都有可查询审计记录。
10. 现有快速剧本生成、历史、配音、登录和数据隔离流程不发生回归。

## 非目标

- 本设计不删除现有快速剧本生成页面。
- 本设计不复用旧 Windows EXE、启动脚本或独立浏览器配置。
- 本设计不让普通用户查看或导出真实系统预设词。
- 本设计不把主账号最高权限转授给其他账号。
