# 独立 Windows 巨量素材执行器设计

日期：2026-09-29  
状态：待用户确认

## 1. 目标与边界

新增一个独立的“巨量素材执行器”，优先支持 Windows x64，不写入、不改造现有豆包本地执行器。执行器的职责是领取巨量素材 OCR 任务，在用户电脑上完成视频读取、中文 OCR、滚屏去重和正文整理，再把结果回传给公网批量工厂。

用户安装包只包含轻量执行器本体。OCR 模型不打进安装包，第一次使用“获取 OCR”时才下载到本地缓存；后续任务复用已下载模型。

不在本阶段实现：

- macOS 版本；
- 直接把永久青语 Token 放进用户电脑；
- 修改豆包本地执行器的任务协议或安装包；
- 让用户手动打开 F12、复制 Token 或执行任意命令；
- 把完整 MP4 长期保存到用户电脑或公网服务器。

## 2. 推荐架构

```text
公网网页
  │ 输入巨量素材 ID、创建任务、显示状态
  ▼
公网任务 API
  │ 青语素材查询、一次性任务凭证、书名/Book ID 关联
  ▼
Windows 巨量素材执行器
  │ 本地领取任务
  │ 首次运行下载 OCR 模型
  │ 临时工作进程执行 FFmpeg + OCR + 滚屏整理
  ▼
公网任务 API
  │ 接收正文、统计、错误和分类阶段状态
  ▼
批量工厂小说列表
```

公网服务负责青语授权和任务协调；执行器只接收短期任务凭证与受限素材信息。执行器不接触永久青语管理 Token。

## 3. 执行器形态

第一版使用 Windows x64 独立安装包，建议使用轻量原生运行时（Go 或 Rust）实现任务代理与下载器。若沿用 Electron，安装包体积可能明显超过“几十 MB”，因此 Electron 仅作为原型或界面壳，不作为体积目标的最终方案。

安装包本体包含：

- 执行器主程序；
- 本地 HTTP/WebSocket 控制接口；
- 任务状态和日志界面；
- 受控的模型下载器；
- OCR/FFmpeg 工作进程启动器；
- 更新检查与签名校验逻辑。

安装包不包含：

- OCR 模型权重；
- 永久青语 Token；
- 用户书籍正文数据库；
- 任意 PowerShell 或批处理脚本。

## 4. 首次模型下载

用户点击“获取 OCR”后，执行器先检查本地模型目录：

```text
%LOCALAPPDATA%\\YizhanShengming\\GiantMaterialExecutor\\models\\<model-version>\\
```

模型不存在或校验失败时：

1. 显示“正在准备 OCR 引擎”；
2. 启动受控下载进程，不弹出黑色终端窗口；
3. 从公网模型源下载中文 OCR 模型和必要运行库；
4. 支持断点续传、临时文件、SHA-256 校验和原子改名；
5. 下载失败保留可重试状态，不破坏旧版本模型；
6. 下载完成后自动进入 OCR，不要求用户再次点击。

模型下载进度、大小、速度、剩余时间和错误原因都回传到执行器界面。模型版本由公网任务协议声明，执行器可以保留多个版本并在空闲时清理旧版本。

## 5. OCR 工作进程

执行器主进程负责 UI、任务心跳、取消、更新和错误恢复；每个 OCR 任务启动一个临时工作进程。工作进程完成或失败后自动退出，主执行器继续驻留托盘。

工作进程职责：

- 使用短期任务凭证读取允许的视频地址；
- 流式读取视频，不保存完整 MP4；
- 按固定采样间隔抽帧；
- 使用 Windows 可用的 ONNX/PaddleOCR 中文模型识别；
- 使用与当前本地原型相同的滚屏去重和文本拼接规则；
- 只回传正文、计数、覆盖率和可校对提示；
- 取消或超时后立即停止子进程并删除临时文件。

公网与执行器之间只传任务状态和最终正文，不上传逐帧图片。若必须短暂缓存视频片段，缓存必须位于任务临时目录，并在任务结束、取消或失败清理。

## 6. 任务协议

任务至少包含：

```json
{
  "jobId": "...",
  "materialId": "...",
  "platformBookId": "...",
  "title": "...",
  "videoUrl": "...",
  "videoExpiresAt": "...",
  "modelVersion": "...",
  "leaseToken": "..."
}
```

执行器向公网回传：

- `queued`：等待本地资源；
- `downloading_model`：准备 OCR 模型；
- `running`：读取视频和识别；
- `cleaning`：滚屏去重和正文整理；
- `uploading`：提交正文结果；
- `succeeded`：完成；
- `failed`：失败，附带可读错误码；
- `cancelled`：用户取消。

任务使用租约和心跳。执行器异常退出后，公网任务可重新入队，不重复登记同一 `materialId + platformBookId + modelVersion` 的成功结果。

## 7. 网页端交互

网页不直接执行 OCR，只负责：

- 显示“执行器未安装 / 未启动 / 在线 / 正在下载模型 / 正在 OCR / 已完成”；
- 创建任务并绑定巨量素材、平台书名和 Book ID；
- 显示执行器回传的进度；
- OCR 完成后登记正文和来源 `巨量素材 · ID`；
- 触发后续 AI 判断男女频、风格和标签；
- 失败时提供重试，不重复写入正文。

执行器未安装时，网页显示安装入口和系统要求。公网 OCR 可以保留为后备能力，但不能依赖本机回环接口。

## 8. 更新机制

更新包和模型包分别管理，并均需签名或 SHA-256 校验。

```text
用户点击“更新执行器”
  ↓
下载更新包到临时目录
  ↓
校验签名和版本
  ↓
启动受控 updater
  ↓
主程序退出
  ↓
updater 原子替换文件
  ↓
重新启动主程序
  ↓
updater 自动退出
```

更新进程不能执行用户输入的任意命令，只能处理预定义的安装目录和已校验的更新包。

## 9. 安全与隐私

- 永久青语 Token 只保存在公网服务端环境变量；
- 任务凭证短期有效、限定单个任务和素材地址；
- 视频地址必须带过期时间，执行器拒绝不符合协议的地址；
- 执行器只允许访问任务 API 和任务声明的素材域名；
- 下载包、模型包和更新包必须校验；
- 日志禁止输出 Token、Cookie、完整视频地址和正文全文；
- 本地正文缓存可配置自动清理，默认任务结束后删除中间文件。

## 10. 验收标准

第一阶段 Windows 验收包括：

1. 安装包不携带 OCR 模型，能在干净 Windows x64 环境安装；
2. 首次点击获取 OCR 能自动下载模型并显示进度；
3. 下载中断后可以继续，不重复下载完整模型；
4. 模型准备完成后自动运行 OCR，不需要第二次点击；
5. 任务结束后临时工作进程自动退出，主执行器仍可继续使用；
6. OCR 结果能回传公网并写入对应书籍；
7. 重试、取消、断网、过期任务和执行器崩溃均有可读状态；
8. 更新包能校验、替换并自动重启；
9. 没有把永久 Token 或完整 MP4 留在用户端；
10. 不影响现有豆包本地执行器。
