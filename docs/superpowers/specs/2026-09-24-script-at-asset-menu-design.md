# 剧本生成 `@` 资产菜单设计

## 目标

把剧本完整输出编辑框中的 `@` 从固定候选栏改为即梦式光标锚定菜单。菜单既是人物、场景主图的可视化引用入口，也是缺失资产和缺失图片的就地补全入口。

## 已确认交互

1. 用户在完整输出编辑框或单分镜编辑框内输入 `@` 或 `@关键词` 时，菜单紧贴当前光标位置显示，不占用编辑框的固定高度。
2. 菜单按“人物、场景”显示与关键词匹配的已有资产。
3. 资产有主图时，菜单项显示主图缩略图和资产名称；选择后只替换当前的 `@关键词` 区间为 `@资产名称 `，保留文本其余部分和光标位置。
4. 文本本来已经含有 `@资产名称` 时，渲染/保存前会以同名资产解析引用；若资产有主图，自动建立该提示词对该主图的引用，无需用户再次选择。
5. 同名资产存在但没有主图时，菜单项明确显示“添加图片”。点击后关闭菜单、滚动到左侧资产库，并打开该资产现有的编辑弹窗与图片面板；不会修改提示词文字。
6. 没有同名资产时，菜单显示“+ 创建主体”。点击后先选择“人物”或“场景”，再直接复用已有添加弹窗，并将用户已输入的 `@关键词` 预填到名称字段。用户可上传图片、AI 生成或补完资料；完成后新资产可立即在 `@` 菜单中被解析和选择。

## 组件与数据边界

- `ScriptPage.jsx` 继续拥有文本编辑状态、`@` 查询范围和资产集合。
- 新的 `MentionAssetMenu` 只负责定位、筛选、缩略图展示和三类回调：插入引用、补图、创建资产。
- 复用现有 `EntitySection`、`EntityEditor` 和 `EntityImagePanel`；不新建第二套资产、上传或生成逻辑。
- 所有资产数据继续写入当前账号既有的剧本提取结果；不改动批量工厂、水货生产、预设或历史作品。

## 自动解析规则

- 只识别完整令牌 `@名称`，名称使用当前人物/场景的显示名称精确匹配。
- 同名人物与场景同时存在时，菜单明确显示类型；自动绑定采用用户最后从菜单选择的类型。未选择时不猜测、不创建，也不覆盖已有绑定。
- 没有主图的资产永远不被当成图片引用；只提供“添加图片”入口。
- 用户手写的 `@` 及其内容始终保留，自动解析失败只展示可操作提示，不删除或重写文字。

## 错误处理与验收

- 资产菜单定位失败时退化为编辑框下方浮层，但必须仍可点击、关闭和键盘继续输入。
- 主图加载失败时显示占位图和名称，不能导致编辑页黑屏。
- 创建或补图弹窗取消时，恢复编辑框焦点并保留原始 `@关键词`。
- 回归覆盖：完整输出和单分镜编辑的光标菜单、主图缩略图、无图补图跳转、创建人物/场景的名称预填、`@名称` 自动引用，以及现有模型下拉和编辑器打开流程。

## 非目标

- 本次不将文本内容中的 `@` 自动提交给视频模型，也不生成新图片。
- 本次不改变 H3、视频提示词、批量工厂或漫剧解说的资产结构。
