# 水货漫剧生产流程设计

## 目标

将水货生产调整为“创建漫剧 → 选择分段对话模式 → 确认分段 → 分段生产”的完整漫剧工作流，并采用参考图的项目首页、创建弹窗和横向分段生产表布局。

## 用户流程

### 1. 漫剧项目首页

项目首页沿用深色漫剧工作台视觉：左侧展示作品卡片，顶部提供搜索、筛选、排序和“创建漫剧”按钮。既有项目仍可继续进入生产工作台。

### 2. 创建漫剧

创建弹窗包含：

- 作品名称，必填；
- 小说内容来源：上传小说文本文件或粘贴小说内容；
- 内容就绪后展示“对话模式”选择；
- 确认创建后生成项目并进入分段工作台。

支持的原文文件为 TXT、SRT、VTT。文件读取为文本后进入与粘贴内容相同的 `sourceText` 创建通道；不引入对象存储原文上传作为本阶段前置依赖。

### 3. 两套分段对话模式

- **自动识别**：按剧情冲突、场景变化与叙事节奏切分，适合小说叙事内容。
- **中文双对话**：优先按人物对白、配音时长和镜头节奏切分，适合双人对白或对话驱动的漫剧。

模式值会随智能分段请求发送至服务端。服务端根据模式选择相应的固定分段提示词模板；分段候选和用户最终确认内容继续复用现有候选、预览和确认机制。

### 4. 分段生产工作台

项目创建完成后进入与图四对应的横向分段生产表。每个已确认分段是一行，依次展示：

1. 序号与分段原文；
2. 可编辑的分段内容；
3. 角色与场景资产绑定；
4. 图片与视频提示词；
5. 图片和视频素材格；
6. 重新生成、生成分段、删除分段等操作。

现有图片、视频、资产、任务中心和媒体绑定能力保留。布局从通用卡片式生产台调整为信息密度更高的行式工作台，不改变后端分段、媒体、任务模型。

## 字幕与配音

### 字幕

确认分段时，`subtitleText` 默认写入该分段最终确认的小说正文。用户仍可在分段编辑中修改字幕；重新确认分段只初始化新分段的字幕，不覆盖用户已编辑、已存在的字幕。

### 配音

分段配音的唯一输入为 `subtitleText`，不再优先使用视频提示词。水货前端通过现有 Express `/api/tts` 配音接口提交字幕文本和所选音色参数，获取音频 Blob 后调用水货媒体上传接口，按 audio 媒体绑定至当前分段。音频生成失败时，保留现有字幕和媒体，不覆盖已有音频。

该实现复用已运行的配音后台，不依赖当前 Go audio 模型适配器或 Redis 音频任务。

## 后端边界

- Express 继续负责 `/api/tts` 的既有配音上游代理。
- Go 水货服务继续负责项目、分段、资产、媒体和任务持久化。
- 新增或扩展的 Go 分段请求仅接收 `dialogueMode` 并选择提示词模板。
- 音频由前端经 Express TTS 获取后复用现有水货媒体上传接口写入项目媒体。

## 验证

- 创建弹窗可用名称加粘贴内容或 TXT/SRT/VTT 文件创建项目。
- 两个模式都能提交智能分段请求，并在后端生成不同模式的提示词快照。
- 确认分段后每行字幕默认等于确认后的分段正文。
- 点击分段配音时 `/api/tts` 接收的文本等于该行字幕；返回音频会作为 audio 媒体绑定到同一分段。
- 项目首页和生产工作台在窄屏可横向滚动，不破坏行内编辑与操作。
- 现有图片、视频、资产绑定和任务轮询回归测试通过。
