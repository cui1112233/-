# ai-video 水货功能迁移设计

## 目标

将 `f:\脚本测试\chengming\ai-video` 中的完整 AI 视频生产工作流迁移到一战晟铭的“水货生产”模块。页面与操作流程以 ai-video 为基准复刻，视觉体系、账户认证、权限、主题切换和全局导航保持一战晟铭现有规范。

迁移完成后，用户只在一战晟铭中使用水货生产，不需要切换到独立的 ai-video 应用。

## 不迁移的实现

不直接复制 Vue 页面、Python 路由或 ai-video 的旧数据库表。新功能在一战晟铭既有的 React、Go、MySQL、Redis 和对象存储体系内实现。

## 功能范围

### 1. 项目与原文

- 项目列表、关键字搜索、新建、删除和进入编辑器。
- 项目名称、原文和上传文件管理。
- 原文快速分段、导入分段、智能分段、人工确认和人工排序。
- 查看原始文件与项目素材。

### 2. ai-video 同款生产编辑器

编辑器的分镜卡片按 ai-video 的生产列复刻：

1. 分镜编号与原文。
2. 角色/资产。
3. 图片提示词。
4. 多图片素材及主图。
5. 视频提示词。
6. 视频素材。
7. 单段操作。

支持新增、修改、删除、上下移动分镜；编辑图片/视频提示词；绑定角色、场景、道具；手动上传、预览、下载与删除图片/视频；并将图片标记为主图。

### 3. 角色模板与提示词配置

- 角色类型、角色模板的增删改查。
- 模板图片上传、AI 生图和重新生成。
- AI 从剧本提取角色，并可将候选保存为模板。
- 在分镜中选择/替换角色模板。
- 全局默认配置：角色、图片、视频提示词前后缀；可选择的文本、图片、视频模型；剪映导出目录。
- 项目级 AI 关键词配置和批量应用。

用户配置与项目数据必须按一战晟铭的当前用户隔离。

### 4. AI 与任务能力

- AI 生成分镜。
- 从剧本提取、更新角色，并将角色智能匹配至分镜。
- 生成单段或批量图片提示词、视频提示词。
- 生成单张、多张、单段批量、全项目批量图片。
- 生成单段或全项目图生视频。
- 采用现有 Redis 任务队列：状态为草稿、排队、运行、成功、失败、取消；支持进度、失败原因、取消和重试。
- 视频生成必须使用分镜主图片；无主图时在界面明确提示且阻止提交。
- 管理员模型中心用于维护文本、图片、视频模型及其凭据引用，不能将密钥返回到浏览器。

### 5. 导出与下载

- 单图和单视频下载。
- 按分镜顺序批量下载视频并生成 ZIP。
- 将视频片段按顺序合并为完整视频，并显示导出任务进度、结果和错误。
- 剪映草稿导出，生成可导入剪映的草稿结构与本地媒体引用；导出路径遵守服务器运行环境，不让浏览器传入任意文件路径。
- 导出任务作为任务队列的一种受控任务实现；仅在所有必要视频素材可用时允许创建。

## 架构

### 前端

扩展 `frontend/src/user/pages/shuihuo/`：

- 保留 `ShuihuoProductionPage` 作为入口和项目状态容器。
- 重构项目列表为 ai-video 的项目卡片与搜索模式。
- 新增/扩展编辑器工作台组件，复刻 ai-video Editor 的列式分镜操作，但使用 Ant Design、全局主题 token 和一战晟铭 CSS 变量。
- 新增模板管理、默认配置、提示词配置、文件查看、媒体预览、批量生成、导出进度等模态框或抽屉。
- 所有请求经过 `shared/api/client.js`，自动携带一战晟铭登录 token。

### Node 网关

继续通过 `routes/shuihuo-production.js` 转发 `/api/shuihuo-production/*`。Node 只负责登录态校验和签名桥接，不承载模型密钥或生成任务逻辑。

### Go 服务

扩展 `backend/internal/httpapi/`、`backend/internal/shuihuo/`：

- 项目、分段、资产、媒体、模型、任务保持现有领域模型与数据库迁移方式。
- 增加项目级与用户级配置、角色模板、提示词预设、导出任务及导出结果数据模型。
- 扩展 worker 与 provider adapter，支持提示词生成、图像、图生视频、视频合并和剪映草稿导出。
- 所有长耗时操作统一走 Redis 队列，并使用对象存储保存结果。

### 存储与安全

- 图片、视频、ZIP、合并视频和草稿附件存储在当前 Local/TOS/MinIO 抽象后面。
- 下载端点在验证项目所有权后返回受控资源，不暴露本地绝对路径或对象存储密钥。
- 模型 API key、数据库密码、对象存储密钥只存在于 Go 服务环境变量，不写入 React、Node 响应、模型表公开字段或日志。

## 数据流

1. 用户从一战晟铭登录后进入“水货生产”。
2. React 通过 Node 网关发送带 Bearer Token 的请求。
3. Node 校验登录态，并根据用户名、管理员标记、方法与路径生成签名请求，转发到 Go 服务。
4. Go 校验桥接签名，从 MySQL 读取或写入该用户的项目和生产数据。
5. 生成与导出任务写入 MySQL，并推送到 Redis。
6. Worker 消费任务，调用已配置的模型或本地导出器，将结果写入对象存储与 MySQL。
7. 前端轮询任务/项目状态，展示进度、可预览素材和下载操作。

## 实施顺序

### 阶段 A：编辑器与数据能力

1. 对齐项目列表与 ai-video 的搜索、新建、删除、文件入口。
2. 扩展分段数据字段，完成同款列式分镜编辑器。
3. 完成媒体多图、主图、上传、预览、下载与删除。
4. 完成角色模板、资产绑定和默认/项目提示词配置。

### 阶段 B：AI 生产能力

1. 接入分镜生成、角色提取和角色匹配。
2. 接入图片/视频提示词生成。
3. 接入单段和批量图片/视频任务、进度、取消和重试。
4. 使用真实模型逐项验证文本、图片、视频生成。

### 阶段 C：导出能力

1. 实现单素材下载与视频 ZIP 下载。
2. 实现视频合并任务与结果下载。
3. 实现剪映草稿导出任务。
4. 完成异常处理、权限校验和端到端验收。

## 错误处理与验收

- 未登录、无权限、项目不存在、资源不属于当前用户分别返回明确 HTTP 状态。
- Redis、数据库、存储、模型未就绪时，水货页给出可读原因并禁用对应操作。
- 任务失败必须保留可读错误、错误代码和重试入口。
- 每个阶段至少验证：Go 单元/路由测试、前端构建、Node 网关链路、登录用户下的 API 调用。
- 阶段 C 需使用真实素材执行一次从原文到图片、视频、ZIP、合并视频和剪映草稿的完整链路。
