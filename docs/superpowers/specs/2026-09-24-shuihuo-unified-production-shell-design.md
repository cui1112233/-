# 水货生产统一作品库与生产外壳设计

## 目标

`/shuihuo-production` 是唯一的水货生产入口。它展示同一作品库、统一的作品卡片、封面、任务入口、片段库入口和发布入口，同时容纳两类作品：

- **漫剧解说**：保留现有逐分镜、字幕、配音、图片、视频和剪映导出工作流。
- **批量工厂**：保留现有小说列表、H3 导演、资产、配音时间线、VIDEO、合并和视频管理系统发布工作流。

本次不重写任一生产内核，不把漫剧解说的逐分镜工作台塞入批量工厂，也不把批量工厂的多书生产步骤伪装成漫剧解说。已有作品、批次、视频、预设、任务和发布记录必须原样保留。

## 当前基线与问题

当前页面已经并行读取漫剧解说项目和批量工厂批次，并以作品卡片放入同一列表；但是作品卡片、进入工作台后的标题与导航、任务/媒体入口、空状态和新建入口还带有两套产品心智，导致用户看起来像进入了两个不同系统。

## 方案选择

### 方案 A：只保留两个独立入口

继续维护独立的漫剧解说和批量工厂页面。实现成本最低，但项目、封面、任务和发布无法形成一个统一工作区，不采用。

### 方案 B：统一作品库与统一外壳，保留两种专属工作台（采用）

作品库以标准化的作品摘要展示类型、封面、进度、当前步骤与最近视频；点击后进入同一个水货生产页面外壳，再根据作品类型装载对应专属工作台。公共的返回、标题、封面、任务、片段库和发布入口有一致的位置与文案；生产按钮、分镜结构和后端 API 仍按类型分派。

### 方案 C：强行统一为同一张分镜表

把批量工厂逐书/逐行/H3 工作流转写成漫剧解说的项目/分镜表。会丢失批量工厂的书级设置、自动化冻结、导演 Trace 和批量发布边界，不采用。

## 产品结构

### 统一作品库

- 标题统一为“水货生产”。
- 保留两个明确的新建按钮：**创作漫剧** 与 **新建批量**。
- 每张卡片显示：类型标签、封面（优先最终合并视频首帧）、名称、更新时间、生产进度和可用视频数量。
- 漫剧解说继续从 Shuihuo 项目接口加载；批量工厂继续从 V11 批次接口加载。读取任一来源失败时，另一来源仍可操作。

### 统一生产外壳

- 进入作品后，顶部固定展示返回作品库、作品名称、类型、封面/最新视频状态、总体进度、任务与日志入口。
- 公共媒体动作以“片段库”入口承载：漫剧解说显示本项目分镜媒体；批量工厂显示当前书/VIDEO 的候选版本、合成和上传状态。
- 公共发布动作使用“发布”入口：漫剧解说保留其现有导出能力；批量工厂保留视频管理系统提交及回读确认。没有可发布成品时，明确禁用并说明原因。

### 专属生产区

- `commentary` 类型装载现有 `CommentaryWorkbench`，不改变逐分镜语义。
- `batch_factory` 类型装载现有 `BatchFactoryNovelList`，不改变小说、书级配置、H3、配音、VIDEO、合并、自动化和发布语义。
- 类型判断只依赖已存在的批次标识/项目标识，不通过名称猜测。

## 数据与兼容性

- 不迁移、不删除、不改写现存 Shuihuo 项目或 Batch Factory 批次。
- 作品库适配层只生成前端摘要；真实数据仍由各自现有 API 和存储负责。
- 封面优先级保持：批量工厂最终合并视频首帧 → 当前可播放 VIDEO → 空封面；漫剧解说沿用既有封面字段与媒体首帧。
- 旧链接 `/shuihuo-production`、`/shuihuo-production/creative` 和已有批次/项目打开路径继续有效。

## 异常与可用性

- 一个来源不可读取时，另一个来源的作品、创建和打开操作保持可用。
- 不把模型、视频服务、自动化或发布依赖失败误报为作品库加载失败。
- 不自动触发资产提取、H3 导演、配音、视频生成、合并或上传；打开作品和浏览片段库均为只读。

## 验证

- 源码测试覆盖：统一作品卡片、类型路由、两种新建入口、单来源失败降级、封面优先级与不触发生产副作用。
- 既有批量工厂与漫剧解说的专项测试回归通过。
- 前端构建通过。
- 公网发布后验证：登录状态下作品库同时显示两类作品；分别打开一条漫剧解说和一条批量工厂记录，确认各自原有工作台可用；不生成、不上传、不改写任何已有作品。

## 范围外

- 不合并两套后端数据表或生产 API。
- 不修改模型下拉、`@` 功能、H3 提示词与发布系统的业务规则；这些是独立问题，需单独排查。
- 不删除旧路由、历史容器、已有预设或已保存任务。
