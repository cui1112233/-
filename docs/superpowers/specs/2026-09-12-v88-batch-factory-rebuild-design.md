# V88 全新批量工厂：布局与生产逻辑设计

## 决策

`/batch-factory` 是水货生产的批量入口，不再是 V78 的副本。它把同一套**单本小说工作台**分发给多本书；每本书的原文、资产、约束、分镜、视频、配音、合并结果和发布回执都独立归属。

V88 当前实际入口已经是 `BatchFactoryV11UiPage`，并已通过 Go `/api/batch-factory/v11` 使用 MySQL、版本化设置、Director、生产与合并服务。这是正确的数据骨架，必须扩展而非另建一套 v2 表或回退到 Node JSON。仓库内的旧 preview/JSON 模块只作为历史参考，不能重新挂回入口；V11 现有 UI 仍有缺口：它把“Director”单列成模块、资产 Prompt 部分保存为批次草稿、原文不可编辑、视频卡片未按新五模块完整闭环，且默认合并倍率仍是 1.5。

## 信息架构

```
批次（账号所有）
├─ 小说 A（独立配置快照、版本与状态）
│  ├─ 原文 / 爆款开头 / 配音
│  ├─ 管理资产：人物、场景（道具预留）
│  ├─ 约束设置
│  ├─ 画面提示词：分镜顺序
│  └─ 视频卡片：任务、媒体、最终提示词快照
└─ 小说 B …（不共享 A 的任何生成结果）
```

工作台采用已确认的四栏：

1. 小说列表：只呈现颜色状态、搜索和选择，不显示伪造状态文字。
2. 批次状态中心 + 当前小说：状态统计、筛选、五个可同时展开的单本模块。
3. 当前筛选 + 成片预览：按分镜选择视频，最后一个位置为最终合并成片。
4. 全批次进度：逐书进度、失败原因、选中范围的批量动作。

顶栏保留“生产统一设置、发布统一设置、开始编辑、开始导演、开始视频、快速上传”。每个按钮必须对应真实 API、持久化状态变化和失败反馈；未具备真实契约的能力禁用并说明原因。

## 五个单本模块

1. **原文**：编辑、版本保存；爆款开头在此处生成/编辑/审核；正文变动只标记下游需更新，不静默覆盖。
2. **管理资产**：人物、场景的添加、编辑、预设提示词、单项/批量图片生成和重生。复用 V11 的“直接打开预设资产”交互，而非旧页面的下拉替代品。
3. **约束设置**：按书保存；支持 10/15 秒目标切分和继承/覆盖边界。
4. **画面提示词**：按分镜排序，服务端产出和保存；支持编辑、重生与预设。
5. **视频卡片**：一分镜一卡片；冻结最终输入快照后生成/重试；点击联动外部播放器。

## 服务端与持久化

- 批次、书、书内版本/设置/活动、分镜和状态继续写入已有的 `batch_factory_v11_*` MySQL 表，并以登录账号 owner 隔离；新字段/关系以追加 migration 扩展。
- 生产项目、任务、素材和最终合并继续复用 Go 水货生产域的 `shuihuo_*` 表与队列；批量工厂只保存关联 ID 和不可变的提交快照。
- Node 旧接口不参与 V88 新链路；浏览器经已鉴权的 Go V11 API 读取和写入，任何文件 JSON 都不得成为新增业务数据的权威存储。
- 所有写操作带 revision 或幂等键；陈旧更新返回冲突，刷新和服务重启可恢复。
- 旧 JSON 只作为一次性、显式迁移来源；迁移不会自动把不完整旧数据写入正式表。

## 状态和执行

单本状态由服务端根据其自身工作流和 Go 任务/媒体回执计算：待开始、排队、待生成、生成中、已完成、异常、待合并、已合并、待上传、已发布。批量动作只创建多个独立单本动作；任一书失败不得把整批标记成功。

- **编辑 / 导演 / 视频**：真实队列与逐书回写。
- **合并**：默认倍率固定为 `1`；严格按该书分镜顺序，使用现有 Go FFmpeg + 对象存储能力。缺少能力时保持不可操作。
- **发布到 121**：界面与设置可保留，但功能默认关闭；只有凭据、视频文件、真实回执、刷新读回和脱敏审计都可验证后才单独开放。

## 迁移策略

可迁移：V11 五模块交互、状态中心模型、批量选择范围、资产预设弹窗、按书合并/状态隔离的测试用例。

不迁移：V78/V11 的分支基线、示例数据、JSON store、仅前端成功提示、未验证的 121 上传和任何旧数据直写。

## 验收与发布门禁

候选完成需同时满足：

- 无批次时展示真实空状态，绝不显示样本小说。
- 每个五模块操作有 API、MySQL 重启读回和错误路径证据。
- 单书/多书/全选的动作严格隔离，状态中心与进度以真实任务回执刷新。
- 真实视频任务、成片合并和可播放结果在候选环境至少走通一次；不能用 HTTP 200 代替。
- 121 仍关闭，直到独立通过一书一视频一回执的端到端验证。
- 通过 Node、Go、迁移、前端构建和登录浏览器验证后，才可发布到 V88 公网容器；V78 不接收任何新功能或数据。
