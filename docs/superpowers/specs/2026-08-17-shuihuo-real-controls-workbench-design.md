## 1. 目标与边界

在保留现有项目、模型、任务、素材、导出和账户隔离后端的前提下，将 `/shuihuo-production` 发展为项目级配置加逐行生产的漫剧解说工作台。所有可见的生成、播放、批量、取消、重试和导出按钮必须有真实行为，或在运行依赖不完整时明确说明原因；不再允许无响应的虚拟按钮。

本设计参考用户提供的工作流截图及洛水静态模块分类，但不复制第三方受保护代码、私有接口、认证资料或内部算法。洛水 `.pyd` 只能作为功能边界证据，不能作为可恢复源码。

不在本轮实现的事项：接入未知第三方配音供应商、绕过授权或激活、在浏览器保存密钥、将管理端模型请求模板暴露给用户端。

## 2. 现有基础与问题

现有项目已具备：项目创建与文档/粘贴原文导入、分镜持久化、向上合并/按原文单元拆分/后方新增、手动媒体上传和主图、单项与批量任务 API、任务轮询取消重试、对象存储媒体下载、项目 ZIP 导出，以及音色/语速/音调的任务快照字段。

当前问题不等同于“没有后端”：

1. 行内播放图标未控制音频元素，用户无法试听已有配音。
2. 重新配音、重生图和生成视频虽可进入任务流程，但依赖 Redis、存储、已启用模型和服务器端 Provider 配置；依赖缺失时需要稳定的禁用原因和设置入口。
3. 批量弹窗只覆盖图片、视频、配音，缺少范围预设、批量推理、批量提示词/预设绑定，以及操作后的任务摘要。
4. `AI 推理` 当前主要服务于智能分段；图片/视频提示词候选的后端能力没有成为工作台的主流程。
5. 项目预设和引擎配置没有形成截图所示的项目默认生产策略，且人物、场景、道具按钮没有按类别打开。
6. 导出仅提供 ZIP，未先根据素材完整度解释可用导出方式。

## 3. 工作台信息架构

项目打开后使用全宽纵向表，不显示编辑器内部项目侧栏。保留全站导航和返回项目库入口。

顶部固定区域依次显示：返回项目库、项目名、完成百分比、分镜/图片/视频/音频数量，以及工具栏：`分镜调整`、`人物场景预设`、`引擎配置`、`AI 推理`、`批量操作`、`取消操作`、`任务/日志`、`导出`。

主表固定为七列：`序号`、`字幕`、`配音`、`预设`、`提示词`、`片段库`、`操作`。每一行对应一个已确认分镜和其关联任务/媒体；原文单元的合并、拆分、新增、删除均由后端作为唯一事实来源完成，前端不自行拼接或重排原文。

## 4. 真实操作状态机

每个生成类操作统一遵循以下链路：

```text
用户点击
  -> 校验分镜、主图、模型、运行依赖和权限
  -> 创建任务并持久化 queued 状态
  -> Worker 消费并调用服务器端 Provider
  -> 输出写入对象存储和 media 记录
  -> 任务状态更新为 succeeded / failed / cancelled
  -> 工作台轮询刷新，行内出现可播放/预览/设主图的真实媒体
```

失败不能伪装为“已生成”。UI 使用可区分的状态：

| 场景 | 行为与提示 |
| --- | --- |
| 没有对应启用模型 | 禁用提交，提示“管理员尚未启用图片/视频/音频模型” |
| Redis、对象存储或数据库未就绪 | 禁用提交，显示健康检查缺项；不泄露 endpoint 或凭据 |
| 视频缺少主图 | 仅禁用图生视频，并提示先上传或生成并设为主图 |
| 任务排队或运行中 | 行内显示状态，任务中心允许查看；仅 queued/running 可取消 |
| 任务失败或取消 | 显示服务器给出的安全错误摘要；仅 failed/cancelled 可重试 |
| 任务成功 | 输出媒体归属到该分镜，图片候选可设主图，音频可播放，视频可预览/下载 |

## 5. 第一阶段：让现有可见按钮真实可用

### 5.1 行级配音

`StoryboardRow` 将音频媒体渲染为受控播放器。播放图标的行为是：没有音频时禁用；有一个或多个音频时播放当前主音频，第二次点击暂停；切换行、媒体加载失败或组件卸载时停止并释放 object URL。音频控件保留原生 `audio` 作为无障碍和失败降级。

音色、语速、音调的配置窗口按“分镜音频设置”保存到任务输入快照。重新配音必须复用该快照创建 audio 任务，而不是仅更改前端标签。未配置音频模型时，按钮禁用并说明应由管理员在模型目录启用模型、在服务器完成 Provider 配置。

### 5.2 行级图片和视频

`重新生图` 创建 image 任务；成功图片进入候选库且不得自动覆盖用户已选主图。`生成视频` 默认只允许图生视频：必须存在主图。若未来支持文生视频，必须由项目引擎配置明确启用 `allowTextToVideo`，不能以缺图自动降级提交。

### 5.3 批量与任务日志

批量操作提供范围：全部已确认、未完成、指定编号范围、手工勾选。操作类型首先包含图片、视频、配音；后续提示词推理和翻译复用同一范围组件，但不和生成任务混用。

提交结果显示成功数、失败分镜及安全错误摘要。任务抽屉是项目级日志：默认全部任务，可过滤活跃任务；支持刷新、查看成功素材、取消和重试。它不直接暴露上游请求、密钥、原始响应或 Provider 私有字段。

## 6. 第二阶段：对齐完整生产流程

### 6.1 分镜调整

分镜调整是项目级编辑器，不是单行字幕编辑。它支持导入分镜、按行拆分、智能分段、选择文本模型和系统预设词、智能配音与分镜导出。候选只在弹窗内存在；确认应用才替换项目 confirmed segments。对于用户已经要求的快速流程，上传/粘贴内容后选择“智能识别”或“自动识别”，完成后直接进入工作台，不再增加“确认分段候选”的额外页面。

### 6.2 人物场景预设

人物场景预设为项目级弹窗，标签分为 AI 角色、AI 场景、AI 道具、AI 音色、角色库、场景库、音色库。顶部保存文本模型、预设词、生图模型、画幅、风格参考图、三视图和音频模型的项目级配置。

行内“添加角色/场景/道具”必须传入类别过滤器，只显示对应资产；资产绑定由 `replaceSegmentAssets` 写入。AI 生图和 AI 音色使用后台启用模型提交任务，成功产物作为候选资产，不替换已有资产或主图。

### 6.3 引擎配置与 AI 推理

引擎配置按图像、视频、音频三标签保存项目默认值：模型、提示词前后缀、比例/尺寸/分辨率、参考图规则、视频时长、字幕时长、角色音频等。前端只保存非敏感参数和管理员启用模型 ID；服务器端按模型 ID 读取加密或受保护 Provider 配置。

AI 推理独立于分镜：选择文本模型、系统预设词、类型（画面提示词/视频提示词）、范围（全部/未完成/指定范围）。结果先作为候选预览，应用时只回写未锁定字段；用户锁定的图片或视频提示词绝不被覆盖。翻译是提示词字段操作，不重新切分小说原文。

### 6.4 导出

导出面板根据当前数据实时判定可用模式：原视频、智能剪辑、图片草稿、融合导出、模板导出及当前 ZIP/SRT。素材不足的模式明确禁用并说明缺什么，绝不生成空壳文件冒充成品。首期继续复用已有 ZIP 服务；剪映草稿/模板导出作为后续独立适配器，不依赖第三方受保护实现。

## 7. 组件和接口边界

前端边界：

- `CommentaryWorkbench` 只负责项目快照、工具栏和弹窗编排。
- `StoryboardRow` 只负责一行的展示、受控媒体播放和调用回调；不直接读写 Provider。
- `BatchTaskModal` 只负责范围选择与批量任务提交。
- `TaskDrawer` 只负责项目任务状态、取消/重试与完成素材打开。
- `PresetWorkbenchModal` 和 `ProductionConfigModal` 分别负责资产预设和项目默认引擎设置。
- `frontend/src/shared/api/shuihuoProduction.js` 是全部 HTTP 调用的唯一入口。

后端边界：

- 项目/分镜/资产/媒体/任务仍使用既有 Go store 和账户范围查询。
- 任务创建仅接受项目、分镜、已启用模型 ID 与允许的参数快照；后端补全 Provider 配置。
- Worker 是唯一调用模型、下载输出、写对象存储和创建 generated media 的位置。
- 健康接口只返回安全的依赖状态，不返回密钥、endpoint、请求模板、原始模型响应或对象存储 key。

## 8. 验收与测试

实现按风险分两批验证：

1. 单元/合同：播放状态、模型/依赖禁用原因、批量范围、任务取消重试条件、锁定提示词不被覆盖、资产类别过滤和敏感字段不出现在用户 API。
2. 后端：项目账户隔离、任务输入校验、媒体归属、队列失败状态、导出仅包含当前用户确认分镜的素材。
3. 构建与静态：相关 Node 测试、Go 测试、`npm --prefix frontend run build`、`git diff --check`。
4. 浏览器：打开 `/shuihuo-production`，核对导航、全宽表、弹窗、禁用提示、播放本地已有音频、任务日志；不因验收创建收费模型任务。
5. 真实端到端：仅在用户提供并配置合法模型、Redis、对象存储和 Worker 后，用一个测试项目分别验证图片、视频、配音任务和导出。未完成此项时，不能宣称所有 AI 生成已可用。

## 9. 依赖与风险

真实图片、视频、配音闭环依赖数据库、Redis、对象存储、Worker、对应已启用模型，以及合法的服务器端 Provider 配置。当前任意一个缺失都应由健康接口和任务按钮解释，而不是归咎于工作台布局。

范围控制：第一阶段先修复现有按钮和现有任务能力；第二阶段再扩展工作台。这样避免先做出完整截图样式但继续保留无效操作。所有新增数据均必须按用户和项目隔离；浏览器不能接触模型凭据或管理端请求模板。
