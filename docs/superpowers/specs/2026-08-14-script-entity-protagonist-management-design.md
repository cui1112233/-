# 剧本人物场景维护与主角白名单设计

## 目标

在剧本生成页面中，用户可维护已提取的人物和场景，并通过星标人物建立主角白名单。白名单人物将作为剧本生成的优先叙事与视觉主体。

## 范围

### 人物维护

- 人物区标题右侧提供“添加人物”。
- 每个人物卡显示名称和主角星标。
- 点击星标可在普通人物与主角白名单之间切换。
- 点击人物卡可打开编辑弹窗。
- 编辑弹窗支持保存修改、全屏编辑和删除人物。
- 新增人物复用人物编辑弹窗，保存后加入当前人物列表。

### 场景维护

- 场景区标题右侧提供“添加场景”。
- 点击场景卡可打开编辑弹窗。
- 编辑弹窗支持保存修改、全屏编辑和删除场景。
- 场景没有主角星标。

### 主角白名单

- 每个人物记录具有稳定本地 ID，主角名单以这些 ID 保存，而不是以名称保存。
- 旧草稿和模型提取结果在归一化时补充本地 ID，兼容现有字符串和对象形态的人物、场景数据。
- 星标人物以完整设定作为 `protagonists` 字段随生成请求提交。
- 未标星人物仍作为普通人物提交，不被自动移除。
- 没有主角星标时，不提交有效白名单，保持现有生成行为。

## 数据模型

剧本草稿中的 `extractInfo` 扩展为：

```js
{
  characters: [{ id: 'entity-...', data: { ...原人物设定 } }],
  scenes: [{ id: 'entity-...', data: { ...原场景设定 } }],
  protagonistIds: ['entity-...']
}
```

兼容层负责将旧的字符串或对象人物/场景转换为带 ID 的记录。界面显示和后端请求仍使用记录内原始数据，以避免改变既有提取和输出格式。

## 交互与一致性

- 新增、编辑、星标切换、删除均立即保存账号维度草稿。
- 人物或场景发生维护后，清空当前生成结果并将状态回退到“已提取”，避免结果与当前设定不一致。
- 删除人物时从 `protagonistIds` 同步移除该 ID。
- 删除场景不影响人物白名单。
- 删除确认使用现有危险操作确认交互，避免误删。
- 人物和场景都删除后，生成按钮保持不可用，直到至少存在一项可生成资料。

## 后端生成约束

生成接口接收 `protagonists` 数组。服务端仅接受当前 `characters` 中存在的对象作为主角白名单，忽略伪造或不匹配数据。系统提示词增加以下约束：

- 优先围绕白名单人物组织剧情、镜头和人物一致性。
- 不得改名、合并、替换或弱化白名单人物的身份、外形和关键关系。
- 非白名单人物可依据原文与输入人物设定正常参与剧情。
- 白名单为空时不改变原有剧本生成规则。

## 测试

- 草稿归一化为旧人物、场景补充稳定 ID，并保留主角名单。
- 新增、编辑、删除人物/场景的页面契约。
- 星标切换、删除人物时移除白名单 ID 的页面契约。
- 生成请求包含 `protagonists`，且后端只接受属于当前人物集合的白名单成员。
- 白名单系统提示词只在主角存在时注入。
- 前端生产构建和相关 Node 测试通过。
