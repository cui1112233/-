# 剧本生成标签页独立草稿设计

## 目标

同一账号在同一浏览器同时打开多个剧本生成页面时，每个标签页编辑的小说原文、人物场景、生成状态与未保存输出彼此隔离；成功生成的剧本仍统一写入现有历史记录，并以实际生成时间排序。

## 当前问题

剧本页草稿由 `localStorage` 以账号名作为唯一键保存：

```text
qiantie:script-draft:{username}
```

`localStorage` 会在同源的所有浏览器标签页之间共享。因此任一标签页自动保存草稿后，另一个标签页刷新或重新进入时会读取同一份内容，造成原文和实体卡相互覆盖。

## 设计

### 1. 标签页稳定标识

新增仅用于剧本工作台的标签页 ID：

- 存放在浏览器 `sessionStorage`；
- 第一次进入 `/script` 时生成随机 ID；
- 刷新当前标签页时继续使用同一 ID；
- 复制标签页时，若浏览器复制了 `sessionStorage`，页面启动时检测并在短时间内重新生成 ID，避免两个同时打开的页面使用同一草稿；
- 关闭标签页后，浏览器会自动清理该标签的 `sessionStorage`。

### 2. 草稿存储键

剧本草稿改为按账号和标签页 ID 保存：

```text
qiantie:script-draft:{username}:{tabId}
```

每个页面只读取和写入自己的键。因此以下数据完全隔离：

- 小说原文；
- 当前提取指令；
- 人物、场景、主角标记；
- 用户约束设置；
- 当前生成输出与编辑状态；
- 提取、生成流程状态。

### 3. 迁移与兼容

- 保留旧版账号级草稿键的读取兼容；
- 首次进入新机制且当前标签没有独立草稿时，读取一次旧版草稿作为初始内容；
- 初始内容写入当前标签的独立键后，不再读取旧键；
- 不删除旧版键，避免影响尚未升级的旧页面；
- 草稿数据结构保持当前版本及字段，不改变既有实体、预设和约束归一化规则。

### 4. 历史记录

生成成功时，仍调用既有历史保存接口：

```text
saveHistory({ id, mode, format, duration, output })
```

历史记录不包含标签页 ID，也不需要按草稿隔离。多个标签页生成的结果全部进入当前账号的同一历史列表，沿用服务端/当前历史模块的实际生成时间排序。

### 5. 失败与边界

- `sessionStorage` 不可用时，生成内存标签 ID；该页面在刷新后视为新草稿，不影响其他标签页；
- `localStorage` 不可用时，沿用当前静默不持久化行为；
- 历史保存失败仍不影响已生成的当前页面输出，沿用现有“生成成功，但保存历史失败”的提示；
- 不增加项目管理、草稿命名、草稿列表、跨标签同步或关闭页面确认。

## 实现边界

仅调整：

- `frontend/src/user/pages/scriptDraftStorage.js`：标签页 ID、按标签页草稿键读写、旧键单次迁移；
- `frontend/src/user/pages/ScriptPage.jsx`：初始化和保存时传入当前标签页 ID；
- 对应测试：验证同账号不同标签页键隔离、刷新稳定、旧草稿迁移一次、历史保存调用不附带标签页 ID。

不修改小说面板、后端剧本生成协议、人物/场景智能补全协议和历史数据模型。
