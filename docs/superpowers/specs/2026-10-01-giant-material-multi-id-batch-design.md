# 巨量获取多 ID 批量流程设计

日期：2026-10-01
状态：已与用户逐节确认（方案 A + 原文获取补充）

## 目标

新建批量选"巨量获取"书城时，输入框支持一次粘贴多个巨量素材 ID（每行一个，数量不限）。
点"立即执行"后：自动创建批量并进入工作区，所有书立刻登记为占位书（书名/Book ID/书城已填，正文为空），
正文位置显示实时读取进度条；OCR 读完一本回填一本，自动化流水线随即逐本生产（做完一本传一本）。

## 用户流程（第 1 节确认稿）

1. 新建批量 → 书城选"巨量获取" → 输入框提示"每行一个巨量素材 ID，数量不限"。
2. 按钮："解析全部 | 立即执行 | 开始定时 | 定时任务"。
3. "解析全部"：逐行调青语解析，弹窗内出现清单（每行：书名 · Book ID · 状态）；
   格式错误或查无素材的行标红，不拦截其余行（遵循"按钮保持可点 + toast 反馈"约定）。
4. "立即执行"前置校验：执行器在线、每条解析记录有有效视频时长；缺失时 toast 说明，不预禁用。
5. 点击后：创建批量 → 前端自动跳入工作区 → 全部占位书立刻出现在制作区与小说列表，
   正文位置显示 `BatchFactoryGiantMaterialPendingProgress` 进度条（复用已上线组件：
   `正在读取正文 x% · 视频 a/b 秒`，5 秒轮询 executorJobId）。
6. 读取队列逐条执行（一台执行器串行）；每本成功：正文回填（只填空书，不覆盖）→
   AI 判断 → 自动进入生产流水线。流水线并发默认 2，做完一本传一本（与其他书城一致）。

## 后端改动（第 2 节确认稿，两处）

### 改动 1：automation-orchestrator 占位书不判死

- 位置：`lib/batch-factory-v11/automation-orchestrator.js` L321 附近的正文检查。
- 现状：无正文 → `blocked`（终态，永不重审）。
- 改法：`sourceMetadata.sourceMode === 'giant_material'` 且无正文 → 状态 `waiting`、
  stage `source`、message "等待正文读取"；下一轮巡检发现正文已回填则照常进入流水线。
- 其他书城的书行为不变（无正文仍 blocked）。

### 改动 2：占位书批量登记复用现有接口

- 保持现有单本创建接口不动；复用已上线的占位书登记链路（支持一次登记多本空书，
  带 executorJobId / contentPending / sourceMode=giant_material 元数据）。
- 弹窗前端负责把多条解析记录一次性递给该接口，后端无需新增接口。

## 小说列表"原文获取"（用户补充，已确认）

巨量获取的书在小说列表"内容"列按状态显示：

| 状态 | 内容列显示 |
|---|---|
| 读取中 | 进度条 |
| 读取成功 | "原文"标签（与其他书城一致） |
| 读取失败/被阻塞 | "原文获取"按钮（蓝色可点） |

点击"原文获取"：用书卡已有的 书名 + Book ID + 书城 调用现有取文接口直接拉正文，
成功后回填该书并自动接上 AI 判断与流水线；失败 toast 原因，按钮保持可点可重试。
其他书城的书不显示该按钮。

## 错误处理（第 3 节确认稿）

| 情况 | 处理 |
|---|---|
| 某个 ID 解析失败 | 清单标红，其余照常 |
| 某本书 OCR 失败 | 书卡与内容列提示，可"原文获取"或重新登记重试，不挡其他书 |
| 执行器掉线 | 未读书停在 waiting，执行器恢复后自动续跑 |
| 定时任务 | 同一流程，到点启动 |

## 明确不做

- 不新增后端创建接口（复用占位登记）。
- 不改其他书城书的阻塞语义。
- 不做苹果版执行器。
- 不设 ID 数量上限（用户明确：给多少跑多少）。

## 验收要点

1. 贴 3+ 个 ID 立即执行 → 工作区一次性出现全部占位书并显示进度条。
2. 第一本读完正文自动出现，AI 判断后该书进入生产（无需手动干预）。
3. 制造一次 OCR 失败 → 内容列出现"原文获取" → 点击后正文回填并恢复流水线。
4. 其他书城新建批量回归：无正文书仍为 blocked，行为不变。
5. 相关 node --test 测试通过，npm run build 通过，按精确 SHA 部署后公网验证。
