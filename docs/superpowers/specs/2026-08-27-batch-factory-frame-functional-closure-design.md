# 批量工厂框架功能闭环设计

## 目标

保持当前 `/batch-factory` 的已确认四栏框架、金色入口、隐藏全局导航和标题栏不变，把仓库中现有的批量导演、前缀编译、提示词查看、视频任务状态、合并与下载能力接入这一框架。页面不得再返回仅展示用途的预览实现。

本期以“小说获取完成任务到合并成片可下载”为完成边界。121 上传不在本期接通；仅在该闭环通过用户路径验收后单独设计。

## 用户路径

1. 用户在小说获取页勾选已完成任务，点击“进入批量工厂”。
2. 前端调用批量工厂交接 API，保留任务 ID、Book ID、书名、平台、正文和原始元数据；页面跳转到带 intake 参数的批量工厂。
3. 批量工厂读取交接单，创建批次或直接打开已创建批次；左栏立即展示小说列表。
4. 用户在顶部批次栏选择生产方式、模型、画幅和时长，并明确应用范围；配置保存后显示实际快照摘要。
5. 用户启动导演。中栏显示并可折叠/展开原文、钩子、角色/场景/道具、VIDEO 提示词与操作记录。
6. 用户选择 VIDEO 卡，在唯一播放器区域查看状态或提示词；可执行单书或批量视频生产、失败重试。
7. 全部 VIDEO 成功后，用户在第三栏或右侧批量区合并。合并后在同一个播放框预览，提供 MP4/TXT 下载。

## 布局与交互边界

- 第一栏：小说列表、搜索、状态筛选、重复/配置标记；不能放播放器。
- 第二栏：当前书内容与所有文本类折叠区。所有折叠项有明确默认状态并可重复展开/收起。
- 第三栏：当前书 VIDEO 卡、唯一播放器、单书生产重试和合并。
- 第四栏：全批次 VIDEO 进度、异常、批量合并与下载汇总；不随当前小说切换改变统计口径。
- 生产统一设置使用右侧 Drawer，不离开工作台。前缀模式分为 AI 自动分类和统一手动前缀；系统前缀库由已有 `PREFIX_PRESETS` 和系统预设目录提供，提示词查看必须显示实际编译结果与所选前缀版本。
- 不具备后端契约的控件必须明确禁用并说明原因；不得有可点击但无副作用的按钮。

## 持久化与数据边界

- 批次、小说项、设置快照、交接单、审核结果、视频生产回执和活动记录迁入 MySQL，按登录用户和团队隔离。
- JSON 批次存储仅作为一次性迁移源，不再接收新增核心业务写入。
- 配置修改只能作用于尚未开始的指定范围；已覆盖的单书保持自身快照，强制覆盖需二次确认。
- Book ID 和书名重复允许继续导入，但必须标记且不能导致内部目录或成品覆盖。

## 用户流程验收

用一个普通用户账号执行并记录以下动作：

1. 小说获取完成两本任务，选中并交接；确认批次、Book ID 和正文完整进入列表。
2. 展开/收起五类中栏内容；修改或审核钩子后确认活动记录更新。
3. 查看一张 VIDEO 的实际编译 Prompt，确认包含模型秒数、画幅、角色/场景/道具与前缀。
4. 单书生成、批量生成、失败重试及状态中心连续定位各执行一次。
5. 等待或模拟视频成品状态，执行单书与批量合并；确认播放器切换、下载链接与异常提示。
6. 对每个可见按钮列出“API 调用、状态变化、失败提示”三项证据；缺任一项则修复或移除。

## 非目标

- 不实现 121 或任何第三方平台上传/发布。
- 不将批量工厂加入全局导航。
- 不用前端本地状态伪造批次、生成、合并或发布成功。

## 验证

- MySQL 迁移和用户/团队隔离定向测试。
- 小说获取交接、批次设置、折叠交互、提示词编译、视频状态和合并 API/UI 契约测试。
- 用户路径端到端测试；前端构建、Docker 健康检查及 `/batch-factory` HTTP 检查。

## 自检

- 不含 TODO/TBD 或未定义的交互结果。
- 当前用户确认的框架、入口和导航边界均已明确。
- 121 与批量生产闭环拆分为两个独立阶段，避免将未经验证的外部上传接入核心链路。
