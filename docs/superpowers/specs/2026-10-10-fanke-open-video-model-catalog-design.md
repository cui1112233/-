# 梵客视频 API 平台预设与模型下拉设计

## 目标

在“API 配置 → 平台预设模型”增加一张“梵客视频 API”配置卡。管理员保存 API Key 后，由服务端读取该 Key 当前可用的视频模型目录；管理员从下拉框选择一个模型并启用。该模型随后与现有 MiniMax H3 一样出现在视频模型选择与视频生成链路中，但使用梵客的标准异步 API，不使用 AutoDL 工作流。

## 范围与非目标

- 范围：梵客视频模型的受控配置、目录读取、单模型选择，以及沿用现有 Node 脚本视频异步提交/查询链路。一个梵客 Key 对应一个已选下拉模型。
- 范围：将现有公网 HTTPS 的参考素材 URL 传入 `imageUrls`、`videoUrls`、`audioUrls`，并按上游目录声明的限制校验。
- 非目标：不替换或修改现有 MiniMax H3、AutoDL、Seedance、YD 或本地执行器配置；不执行真实付费生成作为自动化验收；不重启、切换容器或镜像。
- 非目标：不将模型目录、密钥或供应商响应放进浏览器持久化存储，也不允许前端直接调用供应商。

## 方案比较

1. 推荐：服务端实时读取 `GET /api/open/v1/models`，在配置卡的下拉框显示当前 Key 实际有权限且 `status=available` 的视频模型。保存选择时将模型 ID 与能力快照保存在受保护的模型目录中。
   - 优点：与账号权限、价格和规格同步；不会因文档过期把不可用型号显示为可选。
   - 代价：首次填写/修改 Key 后需点击“刷新模型”。
2. 将当前文档中全部模型硬编码为下拉项。
   - 不采用：供应商明确表示目录随账号权限变化，硬编码会导致可选但无权、规格不符或已下架。
3. 允许管理员自由输入模型 ID。
   - 不采用：容易绕过模型能力校验，无法安全地将多图、多视频和音频输入映射到正确限制。

## 配置与数据模型

新增平台预设 ID `fanke-open-video`，`kind=video`、`credentialMode=apiKey`、`adapterKind=fanke_open_video`、固定 Base URL 为 `https://ai.fanke2026.xyz/api/open/v1`。

单个账户的服务器端模型目录仅保留一个该预设记录，包含：

- 加密/现有安全存储机制中的 `credential`；公开 API 仅返回 `hasCredential`。
- 已选 `modelId`、显示名与最后一次获取时的能力快照：`resolutions`、`durations`、`resolution_durations`、`aspect_ratios`、`max_image_refs`、`max_video_refs`、`max_audio_refs`、`prompt_max_chars`、`audio_requires_image`。
- 启用状态与公共适配器标识。目录数据不可信；服务器每次提交均再次按保存的快照校验。

管理员填写 Key 后点击“刷新模型”，浏览器请求本系统的受保护 API；本系统以 `Authorization: Bearer` 和 `X-Public-Model-Ids: 1` 请求供应商 `/models`，过滤视频模型与 `available` 状态后返回不含密钥的目录。选择模型并保存后才可启用。密钥不通过列表、错误或日志返回。

## 配置页面交互

“梵客视频 API”卡片与现有 H3 卡片同级，布局为：API Key 密码输入、模型下拉、额度状态、启用开关、保存配置。下拉未选择时显示“先填写并刷新可用模型”；已保存的 Key 留空表示不改动；刷新失败时保留已保存选择但明确显示错误，不能以新 Key 启用。

下拉项名称使用供应商 `name`，值使用供应商 `id`，必要时显示规格摘要。不会显示全部文档静态清单；它显示该 Key 此时真正可用的全部视频模型，`MiniMax H3-768p` 只是其中一项。

## 生成与轮询

1. 业务页面选中 `fanke-open-video` 后，运行时解析仍经过现有账户/团队授权模型目录；成员只能使用绑定管理者启用的模型。
2. 提交前把参考素材同步为公开 HTTPS URL，按已选模型快照校验比例、时长、分辨率、提示词长度和各类参考素材数量；不支持的字段不发送。
3. 服务端调用 `POST /video/generate`，保存并向业务返回带供应商前缀的 `jobId`。HTTP 2xx 或 `success=true` 只表示受理，绝不视为成片。
4. 状态查询调用 `GET /video/status?jobId=...`；`submitted` 继续等待并尊重 `pollAfterSeconds`（不少于 30 秒），`success` 要求 HTTPS `videoUrl` 才成功，`failed` 返回上游错误并停止轮询。
5. 网络/5xx/响应解析异常只能重试“状态查询”。提交响应丢失时不自动重新 POST，因为供应商没有幂等保证；保留已知 `jobId` 供继续查询与人工核查。

任务 ID 前缀必须与 H3、YFAI 区分，查询代码通过前缀选择正确适配器。浏览器状态、配置响应和错误均不含 Key。上游签名成片 URL 原样保存，不自行拼接或丢失查询参数。

## 错误语义

- 400：模型、规格、素材或提示词不符合所选型号能力，返回可操作的参数错误。
- 401/403：Key 无效或模型权限不足；保持任务未创建。
- 402：余额不足；保持任务未创建。
- 429：提示降低并发；只对轮询退避，不盲目重复提交。
- 5xx/超时：若未得到 `jobId`，返回“提交结果未知，不自动重试”；若已有 `jobId`，继续状态查询。
- 状态成功但没有可用视频 URL：保留 `jobId`，标记为待供应商恢复，不自动重新生成。

## 测试与验收

- 单元测试：目录过滤、公开模型脱敏、保存选择、能力快照校验、请求头、请求体、任务 ID 前缀与状态映射。
- 路由测试：模拟梵客 `/models`、提交、`submitted`、`success`、`failed`、429 与未知提交结果；证明未知提交不会二次 POST。
- 前端源码/交互测试：配置卡有 Key、刷新、下拉、启用和保存路径；不会展示 AutoDL 工作流输入。
- Batch Factory 不属于本次范围；现有 V11/V12、H3 与 Go 生产适配器不修改。
- 真实验收：管理员在公网保存真实 Key、刷新后看到当前账号视频模型并选择一项；仅在用户明确授权成本后提交一条测试任务，核对 `jobId`、最终 `videoUrl` 和业务状态回写。没有此授权时，仅做无付费的配置、目录读取及模拟提交验收。

## 发布边界

所有源代码和测试先在当前隔离 V88 工作树完成。构建、回归、工作区审查和认证后的公开配置页验收均通过后，才进入一次统一正式部署；不单独替换镜像、容器、卷或现有运行数据。
