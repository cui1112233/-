# 小说面板 AI 诊断与部分分镜保留设计

## 目标

在不改变小说面板 V77 Hotfix26 的页面、按钮位置、提示词协议或人物卡流程的前提下，解决两项运行可靠性问题：

1. AI 请求失败时，管理员和用户无法区分本机超时、上游超时、上游 HTTP 错误、网络错误和 JSON/质量校验错误。
2. 整段分镜返回中混有少量错误行引用时，现有质量闸门会拒绝整批结果，导致已经合格的分镜也无法保留。

本设计不将部分结果伪装成完整成功，也不放宽原有“原文引用必须可追溯”的质量标准。

## 已确认边界

- 保留现有 `http://127.0.0.1:3000/novel-panel` iframe、界面布局、V77 Hotfix26 工作台和现有 API 路径。
- 保留现有 `validateOutlineApplyGate` 作为唯一分镜写入质量标准。
- 不记录 API Key、Authorization、完整模型请求正文、完整小说原文或模型完整返回正文。
- 诊断记录按账号隔离；普通用户只能查看自己的记录，管理员沿用现有问题记录权限边界。
- 单镜重生成必须维持全有或全无：单镜不通过质量闸门时，不能写入半条结果。
- 本次不处理人物卡并发/分批，也不把项目历史改为 Hotfix24 手动历史语义；这两项另立任务。

## 方案比较

### 方案 A：服务端持久化诊断 + 部分结果保留（推荐）

服务端在每次 AI 请求结束时写入小型、脱敏的诊断事件；整段分镜的结果按原有质量闸门逐项筛选，保留合格项并返回未写入项。

优点：能定位 504，保留可用工作成果，不要求用户重跑整段。缺点：需要增加最小诊断存储和前端提示。

### 方案 B：只优化错误文案

将 504 显示得更详细，但不记录阶段和输入规模，也继续整批拒绝分镜。

优点：改动少。缺点：无法复盘根因，也仍会丢掉有效分镜。

### 方案 C：直接放宽/删除质量闸门

让所有模型返回直接写入。

优点：表面上减少 422。缺点：错误引用、错位分镜和不受原文约束的内容会进入用户作品，违背 V77 的质量保护要求。

采用方案 A。

## 架构

### AI 诊断事件

在 `routes/novel-panel.js` 的统一模型请求路径中创建一次操作事件。事件不保存模型正文，只保存：

- `id`、时间、账号、操作类型，例如 `analyze`、`outline`、`scene:<id>`、`character:<id>`。
- 请求配置的脱敏元数据：模型名、Base URL 主机名、等待上限、请求体字符数、系统提示字符数、输出 token 预算。
- 结果：HTTP 状态、耗时、成功/失败类别、错误码和简短错误消息。
- 分镜特有结果：模型返回条数、通过条数、拒绝条数、是否部分写入、质量闸门问题摘要。

事件由服务端写入账号目录下独立的 JSONL/受控存储，按固定最大条数滚动，避免无限增长。读取接口仅返回当前账号允许查看的脱敏字段。

错误类别固定为：`upstream_timeout`、`upstream_http`、`upstream_network`、`upstream_invalid_json`、`quality_gate_blocked`、`client_cancelled`、`validation_error`、`unknown`。页面错误文本继续使用现有中文说明，并附上可查询的诊断事件 ID。

### 整段分镜的部分保留

`/outline-scenes` 收到模型结果后：

1. 先运行现有完整质量闸门，完整通过时维持现有 `200` 和 `applied: true` 行为。
2. 完整失败且模式为整段分镜时，按模型返回的每一项分镜构造最小候选结果，并调用同一质量闸门验证该候选项。
3. 仅保留单项质量闸门通过的分镜，按原返回顺序组合；不重写、不猜测、不修正模型的 `source_index` 或 `source_basis`。
4. 若至少一项通过，返回 `200`、`applied: true`、`partial: true`、合格的 `outline_shots` 和 `rejected_shots` 摘要。前端只写入合格项，并提示“已保留 N 条，M 条未写入”，同时展示未写入原因。
5. 若没有任何项通过，维持 `422`、`applied: false`；当前已有分镜不覆盖。
6. 单镜重生成仍只走完整闸门；不启用部分保留。

用户可再次点击整段生成补齐未写入的原文；本次不新增自动补齐请求，避免在中转压力已高时隐藏重试。

### 前端提示

工作台继续使用既有状态区域和错误弹窗，不新增页面区块。收到 `partial: true` 时：

- 显示已保留/未写入数量和诊断 ID。
- 分镜列表只显示已通过并写入的项。
- 未写入项以现有错误/状态提示显示摘要，不显示模型私密系统提示或完整原始响应。

问题记录页使用已有错误日志 API 的呈现模式增加“小说面板 AI 诊断”来源筛选或条目展示，不显示请求正文。

## 错误与安全

- 浏览器取消、断开连接和服务端超时必须结束对应诊断事件，不能留下“运行中”。
- 读取诊断必须校验 Bearer 会话和账号；不得通过事件 ID 跨账号读取。
- 写入失败不能影响原模型响应或分镜写入，只记录到服务端标准日志。
- 脱敏规则覆盖 `api_key`、`authorization`、Bearer token、查询参数中的凭据字段和完整 prompt/body。

## 验收

1. 设置测试、内容分析、人物卡、整段分镜、单镜重生成功/失败均产生脱敏诊断事件。
2. 人为模拟 `UPSTREAM_TIMEOUT` 时，用户可看到事件 ID、`upstream_timeout`、等待上限和耗时，且没有密钥或原文。
3. 整段分镜中一条合格、一条越界时，接口返回 `200`、`partial: true`，只写入合格项。
4. 全部越界时维持 `422`、`applied: false`，现有分镜不受影响。
5. 单镜重生成质量失败时维持全有或全无。
6. 既有 `novel-panel-asset-contract`、`novel-panel-stability`、新诊断与部分保留测试通过，`git diff --check` 通过。
7. 浏览器实测一次小文本完整成功和一次部分保留提示；真实长原文模型质量与远程时延不作为自动化通过的替代证据。
