# 批量工厂北京时间调度与十本队列设计

## 目标

让批量工厂的定时启动以中国北京时间（`Asia/Shanghai`，UTC+8）为唯一用户语义，并让十本书在受控并发下独立、可恢复地完成“正文 → 资产 → 配音时长 → 导演 → VIDEO → 合成 → 视频管理系统上传”流程。

## 已验证现状

- 当前自动化持久化任务保存 ISO `scheduledAt`，但新建和已有批量的界面使用浏览器原生 `datetime-local`；界面没有显示时区，跨时区用户无法确认输入的含义。
- 任务状态 `scheduled` 到点后才切换为 `running`；`full_submit` 的上传阶段位于成片成功之后，调度本身不会直接上传。
- 调度器每 2.5 秒扫描一次，固定同时推进 2 本书，并且代码最大可安全限制为 4 本。
- 《过期承诺》从启动到视频管理系统确认约 61 分钟；其中早期 VIDEO 失败原因为供应商 `Invalid API key`，不是导演、合成或调度器的计算耗时。

## 设计

### 1. 北京时间是唯一输入语义

- 所有“开始定时 / 自动启动时间”控件显示 `北京时间（UTC+8）`。
- 控件显示值和用户输入都按 `Asia/Shanghai` 解释；传给后端前转换为 ISO UTC 时间戳。
- 已存 ISO 时间戳在界面回显时转换为北京时间。
- 保持既有语义：到点只启动自动生产；`full_submit` 仅在每本成片完成后上传视频管理系统。
- 保存的调度任务和任务日志同时显示北京时间和内部 ISO 时间，便于排查而不混淆用户。

### 1.1 立即执行与开始定时并列

- 新建批量的工具栏提供两个明确入口：`立即执行` 和 `开始定时`。
- `立即执行` 不显示或要求时间；创建批量后立即以所选自动化预设和执行模式启动同一条自动化编排。
- `开始定时` 才要求填写北京时间；创建后 job 保持 `scheduled`，到点才进入同一条自动化编排。
- 已创建批量的“自动生产”面板同样提供两个动作，避免用户靠留空时间字段猜测是否会立即启动。
- 两个入口都允许选择“只生成分镜 / 生成视频不提交 / 全自动生成并提交（成片完成后上传）”。立即执行不等于立即提交；只有最后一种模式在成片完成且视频管理系统回读成功后才标记上传完成。

### 2. 受控的十本书队列

- 自动化预设新增“并行书籍数”字段，选项仅为 `1 / 2 / 4`，默认 `2`；不是由单次按钮临时传入，避免重启后改变任务行为。
- 任务创建时冻结该值进 `configSnapshot` 和持久化 job；旧任务缺少字段时按 `2` 兼容。
- 每个 job 单独使用冻结的并行度，不改变其他批量或手工操作。
- 队列以每本书为独立单元：某本在等视频、重试或失败时，空余槽位立即让下一本推进；不让一本文书阻塞全批。
- 并行上限维持 `4`，不把十本书或全部分镜一次性推给视频供应商。每本仍复用现有缺失优先、逐阶段和视频状态回读逻辑。

### 3. 完成保障与可观测性

- 自动任务持久记录每本书的当前阶段、尝试次数、上次错误、下次可重试时间和最终阶段。
- 临时供应商错误采用受限退避重试：只重试当前书的失败阶段；达到上限后标记该书 `failed`，其余书继续。
- 服务重启加载 job 后继续队列；已经成功的资产、导演、视频、成片和上传回执不重复覆盖。
- 批量状态面板显示：总数、排队、进行中、已完成、失败、下次重试时间和当前并行数。
- “全部完成”仅在每本到达 `uploaded`（full_submit）或相应运行模式终态时显示。外部供应商持续拒绝或限流时，系统保证不丢任务、给出可操作失败原因，但不虚假承诺供应商必然成功。

## 数据与兼容性

- 现有作品、书籍、导演卡、视频、成片、上传回执和自动化预设保持不变。
- 不修改手工单书流程；批量队列只决定何时由自动化推进该书。
- 不改变 `full_submit` 的真实上传确认规则：必须保留视频管理系统逐文件/回读成功证据，不能将 HTTP 成功当作上传完成。

## 验收

1. 在非北京时区的浏览器输入“明日 03:00”，后端保存的 ISO 对应 `Asia/Shanghai` 的 03:00，回显仍为北京时间 03:00。
2. 到点前 job 为 `scheduled`；到点后记录 `startedAt`，再开始首个生产阶段；上传记录只在成片后出现。
3. 选择“立即执行”时 job 立即为 `running` 且 `scheduledAt` 为空；选择“开始定时”时 job 为 `scheduled` 且包含北京时间换算后的 ISO 时间。
4. 十本书、并行度 2 时最多两本处于生产推进；一本失败不会阻止其他九本完成。
5. 并行度 4 时最多四本推进；服务重启后该限制和排队顺序仍有效。
6. 临时 VIDEO 供应商错误只重试该 VIDEO，超过上限后该书失败，状态面板可读出错误与下一步。
7. 真实全自动模式只有收到视频管理系统确认后才将书标为 `uploaded`。

## 发布边界

- 全部实现先进入 Git `v88`，从合入后的精确 SHA 构建并发布。
- 发布后用一个未来北京时间定时任务验证 `scheduledAt → startedAt → 成片 → 视频管理系统确认`；不得用手动立即启动替代该验收。
