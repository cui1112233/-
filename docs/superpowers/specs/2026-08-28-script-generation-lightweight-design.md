# 剧本生成轻量化与素材版本设计

## 目标

将当前偏重的同步剧本生成流程收敛为两次模型调用，并保证用户修改或新增人物、场景后，后续生成不会丢失这些变更。

## 核心流程

### 第一次调用：素材解析

输入小说原文和素材解析元提示词，输出人物、场景、统一画面风格及可选剧情主体。结果必须规范化为系统内部 JSON，并交给用户确认和编辑。

### 第二次调用：分镜生成

首次生成发送：小说原文、当前人物 JSON、当前场景 JSON、统一风格、分段开头元提示词、分镜模式元提示词、星标角色白名单和 10 秒/15 秒时长预设。

重生成额外发送上一版分镜结果，并要求修复问题、精致化和换一种表达。第二次调用不发送质量、限制、负面提示词；这些内容由系统生成后追加到每张分镜卡片。

## 数据协议

JSON 是系统唯一权威数据源，至少保存人物 ID、人物字段、关系、星标状态、场景 ID、场景字段、风格和版本信息。用户新增或修改内容必须更新 JSON，并递增素材版本。

Markdown 是展示、下载、备份和人工审阅格式，不作为默认权威来源。只有用户明确执行导入时，才解析 Markdown 并生成新的 JSON 版本。

每次生成记录原文版本、素材 JSON 版本、生成参数和输出版本，旧版本可回退。生成失败不得覆盖上一版成功结果。

## 分镜输出协议

模型输出固定标题纯文本：

```text
### 分镜一
时间：00:00-00:10
画面：...
动作：...
对白：...
音效：...
```

系统按 `### 分镜一`、`### 分镜二` 等标题切卡，同时兼容 `### 分镜 1` 和 `### Shot 1` 等历史格式。缺失字段时保留卡片并标记待完善，不丢弃整批结果。

## 角色白名单

星标角色由当前 JSON 的 `starred` 字段生成主角白名单。模型必须以当前用户确认的完整人物 JSON 为准，不得遗漏、改名、合并或擅自替换人物。切换星标后再次生成，白名单必须随之变化。

## 时长规则

10 秒和 15 秒规则放入对应预设库。代码只选择预设，不再拼装复杂的时长约束。预设要求每个分镜单元从 00:00 开始并在对应时长结束。

## 异常处理与验收

- JSON 无效时阻止生成并提示修复。
- 分镜标题缺失时尝试兼容解析；仍失败则展示原始结果并提示人工处理。
- 重生成失败时保留旧版本。
- 验收必须覆盖：用户新增/修改人物可被后续生成使用；星标切换改变白名单；10 秒/15 秒预设生效；结果稳定切卡；后置提示词不进入模型请求但进入最终卡片；历史版本可回退。
