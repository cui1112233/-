# 自动化预设模型继承与配置安全设计

## 目标

用户只在新建批量时选择一次自动化预设。预设完整写入批量统一配置；单书默认继承统一配置，只有用户显式修改该书时才形成覆盖。

## 已确认根因

账号的自动化预设与任务快照都保存了文本、图片和视频模型 ID，但 `POST /api/config` 保存普通设置时重建配置对象，没有保留 `modelCatalog`。配置写盘随后用空目录覆盖已有模型目录，导致预设引用仍在、模型凭据却不可解析。

## 设计

1. 管理员保存任意普通设置时，原样保留 `modelCatalog` 和 `modelCatalogVersion`；模型增删改只能由专用模型接口完成。
2. 自动化启动继续先应用预设到批量统一配置，并在入队前验证文本、图片和视频模型仍存在、已启用且具备运行凭据。
3. 单书没有显式模型选择时继承统一配置；已有显式覆盖不被批量设置覆盖。
4. 重试沿用当前批量配置并只重跑失败阶段，不清除已完成产物。
5. 不把密钥复制进预设或批量数据，密钥只保存在账号模型目录。

## 数据恢复边界

代码修复可以阻止再次丢失，但不能猜测已经被覆盖的密钥。部署前只从服务器现有备份或受信任配置恢复；找不到可验证来源时，要求用户在个人中心补录一次模型，而不是逐本配置。
