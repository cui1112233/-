# 小说工作台与批量工厂统一执行设计

## 目标

把批量工厂的小说工作台升级为可独立完成单本剧本生产的工作台，同时让批量工厂以同一套单本流程并发处理多本小说。用户可在单本场景完成编辑、提示词生成、视频生成、状态跟踪、失败重试和 121 上传；批量场景只负责选择范围、调度、汇总和批量操作。

本次开发全部在 `v88` 分支完成。公网发布仍遵守现有候选验证、真实登录、持久化和回滚边界。

## 已确认的用户界面规则

1. 每个主导航/功能区都提供一个 `?` 帮助入口，点击后说明该区域的用途、前置条件、操作顺序、成功状态和失败处理。
2. 帮助内容集中维护在一个功能目录中。新增功能必须同时补充目录、页面帮助和 Obsidian 记录，不能只添加按钮而不说明使用方式。
3. 所有用户可见名称使用中文。界面不得出现 `Director`、`Director revision`、`VIDEO` 等内部英文术语。
4. 内部 API 路径、数据库字段、历史 JSON 字段和代码标识暂时保持兼容，例如 `directorRevision`、`videoId`、V11 路径；这些只属于内部协议，不直接展示给用户。

### 主要中文名称

| 内部概念 | 用户可见名称 |
| --- | --- |
| Director | 导演分镜 |
| Director revision | 导演分镜版本 |
| VIDEO | 视频片段 |
| VIDEO ID | 视频片段编号 |
| 重新 Director | 重新生成导演分镜 |
| 开始 Director | 生成导演分镜 |
| Final compiled | 合成成片 |
| 批量上传 | 批量上传到 121 |

状态值已经是中文的继续沿用；如果状态旁边展示内部 ID，只显示中文标签，ID 放在详情或复制入口中。

## 方案比较

### 方案 A：嵌入式统一工作台（采用）

把现有“剧本生成”的单本动作抽成共享的执行模型和 UI 组件，在当前小说工作台内直接展示。批量工厂针对每本书调用同一个执行模型，并提供批量调度器和汇总状态。

优点是提示词、编辑、单条视频任务和错误处理只有一套；单本修正后可以原样批量复用。代价是需要把现有剧本生成页面中已经稳定的状态机和组件边界整理清楚。

### 方案 B：从批量工厂跳转到剧本生成页

单本任务跳转到现有页面，批量任务仍留在批量工厂。

优点是改动短期较小；缺点是批量无法可靠复用单本页面状态，批量执行、重试、汇总和 121 上传会形成另一套逻辑，不满足本需求，放弃。

### 方案 C：复制一套剧本生成逻辑到批量工厂

直接复制现有页面的表单、提示词和视频动作。

短期看起来最快，但会造成提示词版本、状态、错误提示和上传行为逐渐分叉，放弃。

## 系统边界与数据流

### 单本执行单元

单本执行单元接收：

- 书籍/内容身份
- 原文或直接导入内容
- 内容幅度：按原文自然换行计算的逻辑行数；系统默认 5 行，单本可覆盖为 6、7 行或其他有效行数
- 当前编辑稿
- 人物、场景、道具和视觉约束
- 提示词预设及用户自定义约束
- 视频时长、比例和生成设置

它输出并持久化：

- 生成稿和可编辑稿
- 结构化视频片段列表
- 每个片段的最终提示词
- 视频任务 ID、状态、失败原因和下载信息
- 121 上传任务、逐文件回执和后台核验状态

内容幅度的规则固定为：按服务端保存的原文换行分段计数，不按浏览器视觉折行计数；连续空行不作为内容行。生产统一设置保存默认值 5，每本书保存自己的覆盖值。用户在当前小说工作台把一本书改为 6 行并确认后，该书的原文展示立即变为前 6 行；再次改为 7 行并确认后，展示和后续 AI 输入变为前 7 行。未设置单本覆盖时使用生产统一设置的 5 行默认值。

执行顺序固定为：

1. 接收原文或直接导入内容。
2. 编辑或生成剧本。
3. 从同一套提示词规则生成结构化分镜和视频提示词。
4. 用户可单独修改某一片段并重新编译提示词。
5. 单本执行视频生成，保存每个任务的持久化状态。
6. 视频完成后可预览、下载、合并或上传 121。

任何一步失败都必须停在对应状态，显示可操作的重试入口，并保留失败原因；不能把请求已发出、任务已排队或 121 接口已接收混淆成最终成功。

### 批量调度

批量动作只负责：

- 选择一本或多本小说
- 为每本书建立/读取单本执行上下文
- 并发调用单本执行单元，限制并发数
- 汇总每本书及每个视频片段的状态
- 支持暂停、失败重试、只重试失败项和查看单本详情
- 在单本任务完成后批量合成或批量上传 121

批量和单本使用完全相同的提示词编译、视频提交、状态轮询、合成和上传服务。批量不复制提示词模板，也不另造一个“批量版剧本生成器”。

### 内容来源

内容入口至少支持两种来源：

- 小说获取后的内容
- 用户直接导入的文本/Markdown 内容

两者进入同一份内容标准化和单本执行上下文，不以“必须先获取小说”为前置条件。导入内容需要明确书名/内容标识，缺少标识时在界面上要求补齐，而不是生成临时不可追踪任务。

### 小说列表

小说列表保留当前列表式工作区，不改成演示卡片。每本书独立一行，行首提供可单选的勾选框，并提供“全选/取消全选”。每行固定展示：书名、性别、小说 ID、类型、来源、状态。小说获取时沿用服务端识别出的性别和类型；直接导入时也走同一套识别流程，只有在生产统一设置启用“导入内容自动识别”后才自动补全，识别失败必须显示待补全状态和重试入口，不能伪造分类。

列表上方的动作作用域明确显示为“已选 X 本 / 全部 Y 本”。“开启编剧”“开启导演”“开启发布”都支持已选范围和全部范围，批量动作只提交书籍 ID，不把整段正文放进浏览器请求中。

### 生产统一设置与单本覆盖

“生产统一设置”增加“内容幅度”字段，默认值为 5 行；保存时写入服务端批次设置。单本书设置增加同名字段，支持选择 1 至服务端允许的上限行数，也支持“跟随统一设置”。保存单本值时必须携带当前书籍 revision，冲突时要求刷新后重新确认，不能静默覆盖其他修改。

工作台读取书籍时，服务端返回已解析的 `contentPreview`、实际使用行数和来源标识；前端只展示 `contentPreview`，不自行截取全文。调用编剧、人物/场景/道具分析、导演分镜和视频提示词编译时，服务端统一使用同一份已解析内容窗口，从而保证界面看到的 6 行与 AI 实际分析的 6 行一致。

### 三个阶段动作

1. **开启编剧**：接收已选书籍或全部书籍，读取每本书的内容窗口和生产统一设置中的后台提示词，生成剧本、人物提示词、场景提示词、道具提示词和视频提示词；结果逐本持久化，已完成项不因批量重试重复生成。
2. **开启导演**：仅对已经有可用剧本和视频提示词的书籍执行，读取生产统一设置中的视频通道、模型、画幅、时长等配置，创建可恢复的视频任务。批量和单本使用同一个提交入口。
3. **开启发布**：对已生成视频的已选书籍或全部书籍生成 121 上传确认单；确认后按小说获取的上传逻辑提交正文和视频文件，逐本记录文件、配置、远端回执和后台核验状态。

任一阶段都可以从当前选中范围缩小到单本书。阶段按钮必须根据前置条件禁用并解释原因，例如内容窗口为空、尚未完成编剧、没有成功视频或 121 会话失效。

## 帮助系统设计

新增一个集中式帮助目录，例如 `batchFactoryHelp.js`，每个导航项使用稳定 key 配置：

```js
{
  key: 'script-workbench',
  title: '小说工作台',
  summary: '单本完成剧本、提示词和视频任务。',
  steps: ['导入内容', '生成或编辑剧本', '生成提示词', '生成视频'],
  prerequisites: ['已登录', '已配置对应模型或视频服务'],
  success: '显示完成状态、任务编号或可下载结果',
  failure: '查看失败详情后重试当前步骤'
}
```

帮助入口统一使用可访问的按钮，至少包含 `aria-label="查看小说工作台使用说明"`、键盘可操作性和移动端可点击尺寸。帮助内容优先使用弹出说明；复杂流程使用抽屉，避免把操作区挤出屏幕。

## 121 上传边界

上传入口必须复用现有 121 会话、动态配置同步和后台记录核验能力。上传前显示：目标配置、文件数量、覆盖/跳过策略和确认动作；上传后分别展示“已提交”“待确认”“已确认”“失败”状态。

没有有效登录会话、配置档、风格或远端后台回执时，任务不能标记为“已发布”。远端返回已接收但列表暂时查不到时，状态必须是“待确认”，并提供再次核验入口。

## 错误处理和兼容性

- 单本任务和批量任务使用同一套错误码到中文提示的映射。
- 请求超时、上游拒绝、登录失效、参数不完整和持久化失败分别展示，不用统一的“生成失败”。
- 旧批次和旧字段可以继续读取；新写入沿用现有 V11 兼容字段。
- 不修改正式旧容器和正式数据卷；候选环境完成真实流程验收后才允许公网发布。
- 不在客户端推断服务端权威版本、视频身份或上传成功状态。

## 测试与验收

实现采用测试驱动：先写失败测试，再写最小实现。

### 前端

- 帮助目录覆盖所有导航项，帮助按钮有稳定 key 和无障碍标签。
- 用户可见文本不存在 `Director`、`Director revision`、`VIDEO` 等禁用术语。
- 单本流程可以导入内容、生成/编辑剧本、生成提示词、提交视频、刷新后恢复任务状态。
- 批量流程调用同一单本执行入口，能汇总成功、进行中、失败和待确认状态。
- 失败项可单独重试，不会重复提交已成功项。

### 后端与集成

- 直接导入内容和小说获取内容都能创建可追踪的单本上下文。
- 视频任务持久化、刷新恢复、重启恢复和上游失败状态正确。
- 121 无登录、配置缺失、上传接收、后台核验成功和待确认分支都有测试。
- 保留现有 Go V11 契约、迁移和生产路由测试，并补充真实候选环境的端到端验证。

### 发布前真实验收

在 `v88` 候选环境至少完成：一条单本完整链路、一批多本并发链路、刷新/重启恢复、一次失败重试、一次 121 登录与上传核验，然后确认公网实际 bundle、镜像 digest 和目标入口一致。
