# 分镜模式强制基础设定结构设计

**日期：** 2026-08-15  
**状态：** 已确认，待实施计划

## 目标

当用户选择“分镜模式”时，无论叙事策略为连续开头、爆款开头或分段开头，生成结果中的每个独立分镜都必须包含可直接复制给视频生成工具的基础设定头部。该头部由服务端从已提取的人物和场景数据程序化生成，不依赖模型理解或保留占位符模板。

此功能解决“连续开头 + 分镜模式”结果遗漏基础设定、人物外貌和场景环境的问题。连续开头仍只负责忠实按原文顺序推进剧情；分镜模式始终负责独立可用的视频单元结构。

## 适用范围

- 仅 `format === 'shotlist'` 的分镜模式启用。
- 对 `mode === 'continuous'`、`hook`、`segmented` 一视同仁。
- 画布模式、剧情模式、剧本模式不改变现有输出协议。
- 不改变人物与场景提取流程、叙事策略、模型接口、剧本历史或前端卡片交互。

## 强制输出结构

每个模型输出的 `### 分镜N（总时长：10s/15s）` 标题之后，镜头画面之前必须出现以下结构：

```text
### 分镜一（总时长：10s）
【基础设定】生成视频不带字幕 | 9:16
顾宁：年轻女性，五官清秀、淡妆，黑色长发，深色外套与通勤包
赵婷：年轻女性，短发，浅色衬衫与工牌
场景环境：海关安检通道｜白天｜紧张压迫

镜头画面：
00:00-00:03 | 景别 - 机位/角度 - 运镜 - 转场 | 具体画面正文
00:03-00:10 | 景别 - 机位/角度 - 运镜 - 转场 | 具体画面正文
```

固定规则：

1. `【基础设定】生成视频不带字幕 | 9:16` 每个分镜必须恰好出现一次。
2. 人物行最多三行，按提取结果的顺序取前三个人物。
3. 每个人物行的格式为 `姓名：描述`；没有可用姓名的条目不输出。
4. 人物描述按以下已存在模块顺序拼接：基本体征 → 五官与妆容 → 发型与发饰 → 服饰与配饰。
5. 模块缺失时跳过，不补造人物外貌、妆容、年龄、服饰或配件。
6. 有可用场景时必须输出一行 `场景环境：地点｜时间｜情绪基调`，按该顺序拼接已有字段。
7. 场景字段不完整时只输出已有部分；没有任何可用场景字段时不输出空的 `场景环境：` 行。
8. 若没有场景数据，模型可在镜头画面中根据当前原文呈现真实环境，但不得输出 JSON、花括号占位符、`未知` 或空字段。
9. 固定头部之后必须保留 `镜头画面：` 和完整时间轴；不得把头部放在全部分镜之前作为共享前言。

## 数据映射

### 人物

服务端接收已有 `characters` 数组，不改变其数据结构。每个条目可为字符串或对象。

- 姓名候选字段：`角色名称`、`姓名`、`名称`、`name`、`人物`。
- 基本体征候选字段：`基本体征`、`体征`、`身形`、`年龄`、`身份`。
- 五官与妆容候选字段：`五官与妆容`、`五官`、`妆容`、`面容`。
- 发型与发饰候选字段：`发型与发饰`、`发型`、`发饰`。
- 服饰与配饰候选字段：`服饰与配饰`、`服饰`、`服装`、`配饰`、`穿着`。
- 兼容字段 `外貌描述`、`外形`、`外观描述`、`描述`：当四模块字段均不存在时，作为唯一已有外貌描述原样使用；不得拆解、扩写或推测。

对象中的非字符串值通过安全、短文本方式转换；空白值、对象字面量、数组字面量和重复片段不输出。每条人物描述的各模块仅出现一次，避免“黑发，黑发”之类的机械重复。

### 场景

服务端接收已有 `scenes` 数组，使用第一个有可用字段的场景。

- 地点候选字段：`场景名称`、`地点`、`场景`、`name`、`名称`。
- 时间候选字段：`时间`、`时段`、`time`。
- 情绪候选字段：`情绪基调`、`氛围`、`氛围概述`、`atmosphere`。
- 兼容字段 `场景描述`、`描述`：仅在三个主要字段均缺失时作为单段场景环境使用。

## 服务端流程

在 `buildScriptMessages()` 中，服务端在 `format === 'shotlist'` 时构建 `requiredShotHeader`：

1. 从请求体的 `characters`、`scenes` 建立无占位符的固定头部文本。
2. 将该头部与分镜模式提示词一起放入 system prompt。
3. 明确规定：每个 `### 分镜` 后、`镜头画面：` 前必须原样写入这段头部；不得省略、改名、合并成共享前言或改成 JSON。
4. 将固定头部作为可信服务器生成的内容，不允许用户端自定义约束覆盖或替换它。

模型返回文本后，服务端对 `format === 'shotlist'` 执行 `enforceShotlistHeaders(output, requiredShotHeader)`：

1. 识别每个 `### 分镜` 标题所在区块；`---` 和下一个分镜标题确定区块边界。
2. 检查该区块标题后、首个 `镜头画面：` 前是否已含完整且等价的固定头部。
3. 已有完整头部：不修改，避免重复。
4. 缺少任一固定行、行顺序错误或基础设定不完整：移除该区块中模型生成的旧基础设定/统一人物/场景环境头部，再将服务器固定头部插入标题后。
5. 未找到 `镜头画面：` 时，仍在标题后插入固定头部；不伪造镜头时间轴，让原有模型结果和错误处理保持可见。
6. 没有任何 `### 分镜` 标题时不伪造分镜，保留模型原文；后续输出校验可提示格式错误，但本期不自动重试模型。

该后处理仅重写结构头部，不重写镜头画面、对白、时间码、剧情内容或用户已启用约束。

## 提示词更新

更新分镜模式协议，使模型清楚服务器将使用具体固定头部，而不是要求它从 JSON 中自行提取：

- 删除或禁止 `{从JSON...}` 类型的输出占位符。
- 增加“每个分镜必须逐字使用服务端提供的 `【基础设定】`、人物行和场景环境行”的规则。
- 明确连续、爆款和分段策略不改变分镜头部。
- 明确角色行只列服务器提供的前三位；不得把未提供的临时人物加入固定头部。
- 明确不得生成字幕、水印、横幅或与剧情无关的可读文字；剧情内界面不受此限制。

## 错误与边界

- 人物数组为空：仍输出基础设定和可用场景行，不输出空人物行。
- 场景数组为空：仍输出基础设定和人物行，不输出空场景行。
- 人物/场景全部为空：只输出基础设定与镜头画面，不出现任何占位符。
- 同名人物：按提取顺序最多保留一次，避免重复行。
- 单位中的实际人物与固定头部人物不同：固定头部仍使用前三位已提取人物，作为视频角色一致性锚点；镜头画面只描写当前原文实际出现的人物。
- 启用的画面前缀、画质、限制和负面提示词保持现有“每个分镜内部”规则；其位置在基础设定之后、镜头画面之前，且不得覆盖或删除强制基础设定。

## 测试

新增服务端单元测试，使用 `buildScriptMessages()` 和 `enforceShotlistHeaders()` 验证：

1. 连续、爆款、分段三种 `mode` 配合 `shotlist` 均在 system prompt 中要求同一强制结构。
2. 三名人物与完整场景字段生成正确的固定头部和模块顺序。
3. 人物字段缺失时只输出已有字段，不出现编造文本、空冒号或 JSON 占位符。
4. 超过三名人物只保留前三名；同名人物不重复。
5. 空人物、空场景和字符串实体不会导致异常或占位符。
6. 正确头部不重复插入。
7. 缺少头部、缺少一行或顺序错误时，返回结果被替换为完整固定头部。
8. 多个分镜分别拥有一份完整头部；不会只在全局输出一次。
9. 非分镜模式输出绝不经过该强制补齐。
10. 现有约束设置仍保留在每个分镜内部，且不会被头部补齐移除。
