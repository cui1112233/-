# 剧本用户约束提示词设计

## 目标

用户可基于系统约束预设编辑完整提示词，保存为账号私有、跨设备可使用的“我的提示词”或未命名个人副本。管理员系统预设保持不变，其他用户永远无法读取或修改该用户的内容。

## 范围

适用于剧本生成的四类约束：`prefix`、`quality`、`restriction`、`negative`。继续遵循总开关、分类开关和 `shortdrama` 不注入约束的既有规则。

移除“台词添加词”交互和追加式组合。分类最终只使用一个完整的提示词正文：系统预设正文、个人提示词正文或当前未命名个人副本正文。

## 用户界面

每个已开启分类显示：

1. 来源切换：系统预设 / 我的提示词；
2. 对应来源的选择器；
3. 可编辑的“提示词内容”文本区；
4. 操作：保存当前草稿、保存为我的提示词；
5. 个人提示词提供编辑、删除和另存为命名提示词入口。

选择系统预设时，前端读取并把其完整正文载入可编辑文本区。编辑不会写回管理后台。未修改系统预设时可直接用于生成。

用户改写后：

- 保存当前草稿：在后端创建或更新当前账号、当前分类的未命名个人副本；
- 保存为我的提示词：要求输入 1–80 字名称，创建命名个人提示词；
- 未命名个人副本可在后续打开时继续编辑、直接使用或另存为命名提示词。

系统预设不自动创建个人副本；只有用户点击保存当前草稿或保存为我的提示词时才创建账号数据。

## 数据模型

后端新增独立账户数据文件，单条记录：

```json
{
  "id": "uuid",
  "username": "当前登录账号",
  "category": "prefix",
  "name": "我的 2D 校园暖色",
  "body": "完整可执行提示词",
  "createdAt": "ISO-8601",
  "updatedAt": "ISO-8601",
  "lastUsedAt": "ISO-8601 或 null"
}
```

`name` 可为 `null`，代表该账号该分类的未命名个人副本。每个账号与分类最多一条未命名副本；命名提示词数量每个账号每分类最多 100 条，正文最长 12000 字。

所有记录持久化到服务器 `data/system` 范围并使用既有 JSON 事务锁，不能保存在 localStorage。访问一律从认证中间件的 `req.username` 推导，API 请求体不能提供或覆盖 username。

## API

所有接口要求登录：

- `GET /api/script-constraint-prompts?category=<category>`：返回当前账号该分类的个人记录；排序 `lastUsedAt DESC NULLS LAST, updatedAt DESC, createdAt DESC`。
- `POST /api/script-constraint-prompts`：创建命名提示词或未命名副本；请求仅含 `category`、`name`（可空）、`body`。未命名副本存在时改为更新该副本。
- `PUT /api/script-constraint-prompts/:id`：仅允许当前用户名下记录，更新 `name` 与/或 `body`。
- `DELETE /api/script-constraint-prompts/:id`：仅允许当前用户名下记录。
- `POST /api/script-constraint-prompts/usage`：只接收当前生成请求中实际选中的个人提示词 ID 列表；只更新当前账号记录的 `lastUsedAt`。

跨账号 ID 应统一返回不存在，避免确认其他用户私有记录是否存在。

## 生成请求与草稿

约束分类扩展为：

```json
{
  "enabled": true,
  "source": "system",
  "presetId": "script-constraint-prefix-2d",
  "personalPromptId": "uuid 或 空",
  "body": "当前可编辑正文"
}
```

兼容旧草稿：旧 `presetId` 迁移为 `source: system`；旧 `customText` 成为 `body`，并清空已废弃的 `customText`。若有旧 `customText` 且无系统预设，该分类归一化为用户草稿正文，但不会自动写入后端个人库。

生成时：

- 分类必须启用、总开关启用且格式允许；
- `source: personal` 时，后端用当前用户名与 `personalPromptId` 读取该账号记录正文，忽略浏览器提交的 personal body；
- `source: system` 时，后端验证系统约束预设并使用服务端正文；
- `source: draft` 时允许使用当前草稿 `body`，只用于未命名副本保存前的编辑预览；
- 已保存的个人提示词正文永远由后端存储为准；
- 不拼接“台词添加词”或任意第二段内容。

当生成请求被服务端成功接受时，路由记录所选个人提示词 ID 的使用时间。只保存/编辑/打开不改变排序。

## 安全与隔离

- 系统预设仍仅由管理员预设存储维护；普通用户没有写入系统预设 API。
- 个人库 API、生成读取与使用记录都按认证账号强制过滤。
- 系统预设正文读取接口仅返回已发布的 script constraint addon；个人库不从该接口读取。
- 正文不包含密钥、模型配置和管理后台协议锁；公开目录继续不暴露 `body` 或 `protocolLock`。

## 验收

1. 用户编辑 2D 动漫正文、保存为命名个人提示词后，管理员系统正文不变。
2. 同账号换浏览器/换电脑登录能看到同一命名提示词和未命名副本。
3. 用户 A 无法列出、读取、更新、删除或标记用户 B 的记录。
4. 个人提示词在实际剧本生成成功提交后置顶；下一次使用另一条时，后一条置顶、前一条排第二。
5. 打开、编辑、保存而未生成不会改变排序。
6. 未命名个人副本每账号每分类唯一，可继续编辑、使用或另存为命名提示词。
7. `shortdrama` 仍不注入约束。
8. 旧草稿仍可打开并保留原有约束内容。
