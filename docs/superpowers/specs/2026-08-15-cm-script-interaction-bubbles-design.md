# CM 剧本互动气泡设计

## 目标

让右下角 CM 从被动聊天入口变成围绕剧本工作流的互动助手：剧本生成完成后主动提供可点击提示；用户打开对话后可通过快捷气泡选择具体分析任务，再由现有 Agent 会话输出建议或可确认应用的修改稿。

## 交互层级

### 1. CM 头顶主动气泡

CM 在剧本页收到工作状态时显示短对话。剧本生成完成后，自动从以下文案中随机选择一条显示在 CM 头顶：

- 剧本生成好了。要 CM 帮您检查哪里还能更好吗~
- 这版已经完成啦，要不要看看节奏有没有拖沓？
- 我发现可以再检查一下开头钩子，要我看看吗？
- 想确认人物和场景有没有前后不一致吗？
- 要不要让我找找最值得优化的一段？
- 这一版可以继续打磨，我已经准备好帮您分析啦。

头顶气泡可点击，点击后仅打开 CM 对话框，不自动发送分析请求。

其他剧本状态的提示：

- 未输入原文：需要我帮您规划人物和冲突吗？
- 已提取人物场景：要我检查人物有没有遗漏或冲突吗？
- 正在生成：我在等结果，完成后可以帮您继续打磨。
- 提取或生成失败：这次没有成功，要我帮您检查可能原因吗？

### 2. 对话框内快捷气泡

用户点击 CM 或头顶气泡打开对话框后，在输入框上方显示与当前剧本阶段匹配的可点击快捷气泡。点击某个气泡后，沿用现有 `sendQuestion()`、Agent 任务和受限页面上下文链路发送对应预设问题。

剧本生成完成时显示：

| 气泡 | 发送给 CM 的任务 |
| --- | --- |
| 分析整体质量 | 检查节奏、冲突、钩子、逻辑完整性，按优先级给出建议。 |
| 找出最弱的段落 | 指出具体段落、问题原因和可执行修改方向。 |
| 优化开头 10 秒 | 判断开头是否足够抓人，并给出不改变核心事件的优化建议。 |
| 检查人物一致性 | 检查人物身份、性格、关系和称呼是否前后一致。 |
| 检查场景与画面感 | 检查场景是否清晰、镜头是否可拍、空间与道具是否连续。 |
| 强化冲突与反转 | 只给出冲突和反转强化建议，不直接改写当前剧本。 |
| 生成修改稿 | 先分析当前剧本，再输出以 `【修改稿】` 标记的完整可替换版本。 |

其它阶段：

- 未输入原文：规划人物与冲突、如何开始、自由提问；
- 已提取：检查人物遗漏、检查场景遗漏、检查人物关系、自由提问；
- 处理中：保留自由提问，不显示会与正在运行任务冲突的分析动作；
- 失败：分析失败原因、检查当前设置、自由提问。

自由提问始终使用既有输入框，不改变用户自由输入能力。

## 数据与安全边界

- 快捷气泡只是前端预设提示词，不直接执行页面修改；
- CM 继续只接收 `normalizePetContext()` 允许的受限剧本上下文；不读取 iframe 内容、密钥或未授权数据；
- 所有快捷问题继续通过现有 `createAgentTask()` / `askAgent()`，使用当前账号对应任务；
- `生成修改稿` 的结果必须包含 `【修改稿】` 才显示既有“应用到剧本”按钮；用户点击按钮后才触发 `dispatchPetApply()`；
- “强化冲突与反转”等建议类操作不显示自动应用入口；
- 气泡点击、打开对话、取消或关闭对话均不写入剧本草稿；
- 不增加独立 AI 接口、后端表、跨账号共享会话或自动覆盖逻辑。

## 组件边界

- `stacky.js`：按当前剧本上下文与状态生成头顶气泡文案、快捷操作定义及其预设提示词；所有纯选择规则可测试；
- `StackyPet.jsx`：将头顶气泡变为按钮，渲染快捷气泡并将点击映射到现有 `sendQuestion()`；
- `ScriptPage.jsx`：继续通过 `dispatchPetState()` / `dispatchPetContext()` 传递工作状态和已有剧本上下文，不新增剧本写入通道；
- 样式：为头顶可点击气泡和输入区上方的操作气泡提供可访问的按钮样式、小屏换行和 `asking` 禁用状态。

## 验证

1. 剧本生成完成后显示上述六句之一的可点击头顶气泡；点击只打开对话框；
2. 对话框在完成状态显示七个分析快捷气泡；点击后调用现有 Agent 对话，并显示用户问题和 CM 回复；
3. “生成修改稿”回复含 `【修改稿】` 时才显示“应用到剧本”；其他快捷问题不会显示自动应用；
4. 未输入、已提取、处理中、失败状态显示各自对应的快捷选择；
5. 气泡点击不修改剧本，除非用户后续明确点击“应用到剧本”；
6. 自由输入、对话恢复、账号切换、拖动、收起、关闭和 Agent 工作区跳转保持现有行为；
7. 无 Agent 配置或请求失败时沿用现有失败提示和重试，不产生未处理异常。
