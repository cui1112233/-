# 剧本原文输入框清空按钮设计

## 目标

在剧本生成页的小说原文输入框右上角增加 `×` 清空按钮，方便用户直接清空输入内容，同时避免误删已提取的人物、场景和已生成剧本。

## 交互规则

- 原文输入框有内容时显示 `×`；为空时不显示。
- 点击 `×` 后立即将小说原文设为空，不弹出二次确认。
- 清空操作仅影响小说原文输入框和对应草稿字段。
- 清空操作不得删除或重置当前人物、场景、提取阶段、右侧剧本结果、卡片选择和配音状态。
- 用户重新粘贴或编辑小说原文时，同样保留当前人物、场景和剧本结果。
- 用户点击“提取”后，才使用当前原文执行新的提取流程；提取流程开始时清除旧人物、场景和剧本结果，避免新旧内容混用。

## 实现边界

- `ScriptPage.jsx` 为原文输入区域增加相对定位容器和带无障碍标签的清空按钮。
- 清空按钮使用 `form.setFieldValue('novelText', '')` 更新表单，并通过现有草稿保存函数立即持久化。
- 需要调整 `onValuesChange`：原文变更只更新草稿、使进行中的请求失效并更新宠物上下文，不再直接清除已提取数据或剧本结果。
- 在实际开始提取前清除旧的提取数据和剧本结果；若当前原文为空，仍沿用表单必填校验，不能进入提取。
- 样式应避免遮挡 textarea 内容或右侧滚动条，采用输入框右上角的小型圆形按钮，hover 时可见。

## 测试

- 页面契约测试验证原文输入框有清空按钮、具有中文无障碍标签，并通过 `form.setFieldValue('novelText', '')` 清空。
- 验证原文在 `onValuesChange` 时不再出现 `setExtractInfo(normalizeExtractInfo())` 或 `setOutput('')` 的结果重置逻辑。
- 验证提取入口会在开始新的提取前清除旧结果。
- 前端生产构建必须通过。

## 不在范围内

- 不提供撤销清空。
- 不弹出确认框。
- 不清空人物、场景、剧本或配音结果。
- 不改动原文上传、配音或提取接口。
