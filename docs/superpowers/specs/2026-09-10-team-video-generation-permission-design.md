# 组员视频生成授权设计

## 目标

允许团队管理员在现有成员治理流程中，按成员单独开启或关闭“视频生成”能力。授权必须由服务端校验，前端只负责展示状态和提供操作入口。

## 方案

沿用现有 `apiScopes` 机制，新增标准 scope `video`，不新增平行字段。`video` 与 `text`、`image`、`tts` 并列；邀请创建、成员加入、成员治理、联合治理和个人中心均识别该 scope。旧数据不迁移，既有成员保持原权限。

## 数据流与权限边界

1. 团队管理员在团队页或联合治理页勾选/取消“视频生成”。
2. 现有成员授权接口保存 `video` scope，并返回脱敏后的成员信息。
3. 视频生成路由在创建任务前读取当前账号及所属团队的有效 scope；管理员/DEV 按现有规则直接允许，普通 MEMBER 必须拥有 `video` 或 `*`。
4. 未授权请求返回 HTTP 403 和明确中文提示；不得调用上游视频服务，不得消耗额度。
5. 组员继续使用绑定团队的视频配置，但任何 API Key、完整配置值都不返回给组员。

## 界面

- 团队成员创建、邀请和成员编辑表单增加“视频生成”。
- 联合治理成员弹窗增加同一选项。
- 个人中心服务状态增加“团队视频生成”。
- 剧本分镜“生成视频”按钮在未授权时禁用，并显示“暂无视频生成权限”；服务端拒绝仍作为最终保护。

## 兼容与错误处理

- scope 白名单统一扩展为 `text/image/tts/video`，非法值仍返回 400。
- `*` 继续表示全部能力，并在界面中展开为四项。
- 邀请默认权限保持原行为（文本），不自动授予视频权限。
- 授权变更即时生效；已在运行中的任务不回收，后续查询/下载沿用现有任务权限规则。

## 测试与验收

- scope 白名单、邀请落地、成员治理保存和 `*` 展开测试。
- MEMBER 有 `video` 时可创建视频任务；无 `video` 时 403 且上游调用次数为 0。
- DEV/MANAGER 的现有行为不回归。
- 前端构建通过，相关单元测试通过。
