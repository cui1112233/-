# CM 剧本协作宠物设计

## 目标

将当前网页宠物 CM 从通用聊天入口改为剧本生成页的协作助手：它能读取当前小说原文、人物场景提取结果和剧本输出；根据用户的修改意见生成完整候选修改稿；用户在预览后确认覆盖当前剧本，并可以撤销一次。生成或宠物请求失败时，CM 应说明原因并给出恢复操作。

本期仅覆盖整篇剧本，不包含语音、文件、截图、系统级桌宠或局部选区修改。

## 当前问题

剧本页已派发 `novelText`、`extracted` 与 `scriptOutput`，但宠物客户端的上下文归一化只保留页面、摘要、实体数量和建议动作。宠物实际没有小说或剧本正文，不能可靠改稿；同一问题使“应用到剧本”按钮依赖的 `scriptOutput` 永远为空。

现有应用事件会直接整体覆盖当前输出，没有预览、确认、快照或撤销。请求失败还可能同时产生弹窗、toast、宠物气泡和动画，且生成失败会清空当前输出。

## 范围

### 包含

- 剧本页向宠物同步受长度限制的小说原文、提取结果与完整当前剧本。
- 宠物以当前上下文向 Agent 提问，要求整篇改写时得到“修改说明 + 完整修改稿”。
- 识别完整修改稿并打开预览，而不是立即覆盖。
- 预览中展示当前剧本与候选修改稿；可确认应用或放弃。
- 应用前保存一份内存中的撤销快照；应用后允许撤销一次。
- 宠物按错误类型给出简短原因与可执行建议。
- 生成失败保留原有剧本输出。

### 不包含

- 选中段落的局部替换、差异行级高亮、多个候选版本。
- 跨页面共享版本历史、服务器端剧本版本库、导出流程。
- 语音、截图、文件输入、系统通知或原生桌面窗口。

## 用户流程

### 审阅和改稿

1. 用户在剧本页生成或编辑当前剧本。
2. 页面同步小说原文、提取结果和当前剧本给 CM。
3. 用户询问不满意之处，例如“第三场冲突不够强，帮我加强”。
4. CM 将当前上下文和意见发给 Agent。
5. Agent 返回修改说明和以 `【修改稿】` 标识的完整候选剧本。
6. CM 在消息旁显示“预览修改”。
7. 用户打开预览，查看当前剧本与候选修改稿。
8. 用户选择：
   - **应用修改**：保存当前输出为一次撤销快照，覆盖当前输出，进入可编辑状态并保存草稿。
   - **放弃修改**：关闭预览，不改动当前输出。
9. 应用后显示“撤销本次修改”；撤销将快照恢复为当前输出并清除该快照。

### 无当前剧本

当当前页没有剧本输出时，CM 不请求完整改写，提示用户先生成剧本；普通的创作建议仍可回答，但不显示预览修改入口。

### 错误恢复

- 网络/超时：CM 提示“连接模型超时，当前剧本已保留”，提供重试。
- 配置或鉴权错误：提示检查模型接口、模型名或密钥，提供“打开模型设置”。
- 上游格式异常：提示本次未生成可应用修改稿，提供重试。
- 历史保存失败：提示当前剧本与草稿仍在，允许继续编辑；不阻止结果使用。

同一次错误只保留一个主反馈入口：与当前操作关联的 CM 气泡/面板。全局弹窗不得与宠物重复展示同一网络或上游错误。

## 架构与数据流

```text
ScriptPage
  ├─ 当前 output / novelText / extractInfo
  ├─ 受限上下文 → qiantie:pet-context
  ├─ 接收预览、应用、撤销事件
  └─ 本地草稿持久化

StackyPet
  ├─ 保存完整受限上下文
  ├─ 调用 /api/agent/chat
  ├─ 解析 【修改稿】
  ├─ 请求预览，而不直接应用
  └─ 展示错误建议与重试

Agent API
  ├─ 再次限制上下文长度
  ├─ 在存在 scriptOutput 且用户请求改稿时要求完整修改稿
  └─ 返回任务消息

Script preview
  ├─ 显示当前输出与候选输出
  ├─ 确认 → 应用事件
  └─ 放弃 → 无状态写入
```

## 组件边界

### 宠物上下文

保留现有页面、摘要、实体、建议动作字段，并保留 `novelText`、`extracted`、`scriptOutput`。客户端应使用与后端相同或更严格的长度上限，避免在浏览器事件中无上限传递内容。后端继续作为最终限制层。

### 修改稿协议

保持现有文本协议：完整可替换稿必须以 `【修改稿】` 开始。宠物从该标记后提取候选剧本；标记前内容为修改说明。没有标记的回答仅作为普通建议显示，绝不允许应用。

### 预览状态

预览状态属于剧本页，至少包含：`open`、`currentOutput`、`candidateOutput`、`summary`。候选稿在确认前不得写入 `output`、草稿或历史。

### 一次撤销

剧本页保存单一 `previousOutput` 内存快照。只在用户确认应用时创建；每次新应用替换旧快照。撤销成功后清空快照。刷新页面后不保证撤销仍可用。

### 错误建议

错误应归类为网络/超时、配置/鉴权、上游响应、保存失败或未知错误。分类结果驱动宠物文案和可用动作，不依赖模型自行判断错误。重试必须复用原始请求；打开设置只导航到现有设置页。

## 安全和数据约束

- 只同步当前剧本工作内容，不新增屏幕、文件或系统数据读取。
- API Key 不得进入宠物上下文、聊天消息、预览或错误文本。
- 宠物正文与后端上下文均有长度限制。
- 候选修改稿必须由用户确认后才能覆盖当前输出。
- 生成失败不得清空已有输出。

## 验收标准

1. 在已有剧本的剧本页提问时，Agent 请求中包含当前剧本、小说原文和提取结果，且超长内容会被截断。
2. 请求“修改剧本”后，包含 `【修改稿】` 的回答显示“预览修改”。
3. 预览打开前，当前 `output` 不变；确认后完整覆盖；放弃后不变。
4. 应用后能撤销一次，恢复应用前内容；第二次撤销不可用。
5. 没有当前剧本时，不能显示或触发完整改稿应用。
6. 网络、鉴权、超时和上游错误由 CM 给出相应建议，并可执行正确动作；同一错误不重复弹出全局错误框。
7. 剧本生成失败后，用户原有 `output` 保持不变。

## 测试

- 纯函数测试：上下文归一化保留字段并截断；修改稿提取；错误分类。
- 组件测试：预览打开、确认应用、放弃、撤销和无剧本禁用状态。
- 路由测试：Agent 上下文包含必要字段、上游错误分类与安全错误输出。
- 手动流程：生成剧本 → CM 改稿 → 预览 → 应用 → 撤销；断网/超时、错误密钥和保存失败场景。
