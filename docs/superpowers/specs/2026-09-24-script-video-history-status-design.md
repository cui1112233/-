# 分镜历史视频状态展示设计

## 目标

历史分镜任务必须按服务端的最终状态展示，避免将失败或尚在处理的任务错误呈现为可播放视频。

## 范围

- 用户打开某条分镜的历史视频时，前端逐条请求既有的任务查询接口。
- 查询成功的任务以服务端的 `status`、`videoUrl` 与 `error` 覆盖本地历史快照；保留快照中的提示词，以便旧任务也能显示原始分镜摘要。
- `succeeded` 且存在 `videoUrl` 时才显示播放器。
- `processing` 显示“视频生成中，暂不可播放”。
- `failed` 显示“生成失败”及服务端错误；不显示播放器，不自动重新提交。
- 查询暂时失败时保留原有快照，并明确显示“暂时无法读取任务状态”，不把它归类为无播放地址。

## 非目标

- 不删除历史任务、不改写已生成视频地址。
- 不改变视频提供商请求、参考图传递或收费任务提交逻辑。
- 不在打开历史记录时自动发起重新生成。

## 验收

1. 一条失败任务展示失败状态与原因，不再显示“该历史任务没有可播放地址”。
2. 一条处理中任务展示处理中状态。
3. 成功且有地址的任务仍可播放。
4. 历史弹窗中一次查询失败不会阻断其他任务状态刷新。
