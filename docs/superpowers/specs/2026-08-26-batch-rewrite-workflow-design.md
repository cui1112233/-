# 批量改文工作流归并设计

## 目标

把登录、提交设置和任务执行收敛到“处理”和“任务”两个工作入口，降低用户在处理、预览、上传之间来回切换的成本，并保留可追溯的任务详情与规则数据。

## 交互

- 处理页：批量输入、敏感词 AI 唯一开关、目标站登录状态、提交文案与提交方式设置。
- 登录状态位于批量输入区域右下角。已验证显示白色用户名与蓝色圆点；异常显示红色状态与红点；无会话显示红色“未登录”。点击状态打开账号密码弹窗，保存并验证成功后刷新状态。
- 提交设置使用 `details` 折叠区，默认收起。设置包括文案版本、提交方式、配置档/自由参数、最小字数、重试和重复提交保护。
- 任务页：列表、选择、预览/提交、重试和规则操作。详情从处理页移除，点击“查看”在任务页弹窗展示。
- 详情弹窗提供关闭、上一条、下一条；首条/末条禁用，不循环。关闭后可直接点击任务列表其他任务。
- 删除“网站提交”导航与面板；提交历史保留在记录页和任务详情日志中。

## 数据流与兼容

复用现有 `/api/web-submit/config`、`/api/web-submit/test-visible`、`/api/web-submit/preview` 和 `/api/web-submit/submit` 接口，继续保存到 `web_submit` 配置，避免迁移已有账号、配置档和提交历史。详情继续读取 `/api/tasks/:id` 及敏感词、规则追踪、提交日志接口。

## 编码

知识库、处理规则和提示词从配置读取边界统一经过 `repairMojibakeDeep`；已确认的干净备份用于修复当前 Docker 数据，读取时只修复可逆乱码，不覆盖其他工作台设置。

## 错误处理

登录验证失败保留红色异常状态和可读原因；提交未登录时阻止执行并引导点击状态登录；详情接口失败显示弹窗错误，不破坏任务列表。

## 验证

覆盖导航移除、提交设置默认收起、登录状态入口、详情弹窗导航、乱码修复单元测试；执行前端构建、定向 Node 测试、Docker 无缓存重建和目标页面/API 健康检查。
