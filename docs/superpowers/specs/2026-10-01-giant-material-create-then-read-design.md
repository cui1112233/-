# 巨量素材：先创建批量，再获取原文

## 已确认目标

用户在批量工厂选择“巨量获取”、完成素材 ID 解析后，点击“立即执行”应立刻创建批量并进入工作区。每本书先通过已解析出的书城与 Book ID 获取原文；不应因为尚未选择自动化预设而阻塞原文获取。

## 用户流程

1. 输入一条或多条巨量素材 ID，点击“解析全部”。
2. 青语服务返回书城、平台 Book ID、书名和视频信息；缺少书名或 Book ID 的条目保持可见失败，不创建空书。
3. 点击“立即执行”后，系统直接创建批量和占位书，跳转/刷新到工作区。
4. 每本书卡显示“正在通过书城获取原文”；后台使用书城和 Book ID 调用既有 `fetchBookOriginal`。
5. 成功则写入正文并显示已获取；失败保留失败原因与“重试获取/改用滚屏 OCR”的后续入口。
6. 自动制作、视频生成和上传只在用户进入工作区后主动启动；它们继续要求选择自动化预设，不能在“立即执行”阶段被隐式启动。

## 交互边界

- “立即执行”在巨量获取模式下表示“创建并开始获取原文”，不是“全自动制作并上传”。
- 原有非巨量书城的立即执行/定时行为保持不变。
- 巨量素材的“开始定时”仍属于自动制作能力，保持预设选择和定时校验。
- 书城元数据继续写入 `platform` 以及 `sourceMetadata.platformName/platformCode/platformId`；列表行应显示书城，避免用户把“Book ID 已解析”误判为没有书城。

## 实现边界

- 复用已有 `submitGiantMaterial({ automationRun: false })`、占位登记与 `fetchBookOriginal`，不新增新的原文抓取服务。
- 巨量立即执行不弹自动化预设对话框，改为直接调用上述提交路径。
- 在书城直接获取失败时，只记录失败状态；不自动切到 OCR，以避免对多条素材无提示地占用执行器。

## 验收

1. 巨量素材解析成功后，点击“立即执行”不出现预设选择框。
2. 批量创建后，每本书调用一次既有书城原文获取接口。
3. 成功正文在工作区可见，来源保留“巨量素材 · ID”。
4. 失败书显示原因且可重试；缺少必要元数据的素材不创建书。
5. 本次流程不调用自动化、视频或上传接口。
