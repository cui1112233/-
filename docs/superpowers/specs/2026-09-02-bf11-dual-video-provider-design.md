# Batch Factory V11 双视频通道接入设计

- 日期：2026-09-02
- 基线：`fix/bf11-personal-prompt-bridge-20260902` @ `fa2f88ca01275a09cd65bdc2be0703804892a321`
- 集成分支：`feat/bf11-dual-video-provider-integration-20260902`
- 范围：仅 Batch Factory V11；不包含 Novel Fetch、Batch Factory 旧版路由或生产环境切换

## 目标

让同一套 Batch Factory V11 提示词、VIDEO 状态、合并和发布流程支持两个互斥的视频生成通道：

1. 默认的个人中心视频 API：当前服务为 `yd_video`，模型为 `yd2.0-mini`。
2. 可选的豆包本地执行器：用户在自己的 Mac 上登录豆包账号并运行执行器，云端只负责任务控制和 MP4 回传。

## 用户流程

上传文案后仍遵守既有产品规则：

`原文直转` 只调用一次文本 AI；`爆款开头` 先生成 Hook，用户确认后再生成 Director。Director 产生人物、场景、道具、分镜和 VIDEO。每个 VIDEO 保持独立 `visualPrompt`，提交生成时由系统设置、资产和画面约束编译成 `compiledPrompt` 快照。

用户在生产统一设置中选择视频通道：

- 默认：个人中心 API。
- 可选：豆包本地执行器。
- 不自动故障切换，避免重复提交和重复计费。

两条通道都必须回写同一套 VIDEO 生产任务状态，之后使用同一套播放器、按 Director 顺序合并、发布和完成状态。

## 服务端边界

### 个人中心 API

- 服务端根据当前用户读取其个人中心视频配置。
- API Key 只在服务端使用，不返回前端、不写日志。
- 先支持现有 `yd_video` / `yd2.0-mini` 请求和轮询协议。
- Provider 适配层负责提交、轮询、错误归一化和媒体 URL 校验。
- 未配置、配置不完整、服务拒绝或媒体无效时，任务必须失败并显示明确原因。

### 豆包本地执行器

沿用 `feat/v78-doubao-local-executor-s5-artifact-return` @ `eb79b76b97a7db7cbd0539e30a7512ccc517f16c` 的控制协议，但只移植与 V11 生产任务有关的源代码和类型，不合并其旧版 Node Batch Factory 路由。

- Pair/heartbeat/claim/renew/progress/acceptance/result/fail/release。
- 执行器本地保存账号、Cookie、浏览器 Profile 和密码；云端不接收这些材料。
- 接受成功后冻结账号和提交，不允许再次提交同一任务。
- 只接受与任务身份精确绑定的 MP4；禁止按“最新视频”猜测。
- 上传重试只重试上传，不重新生成。
- 没有在线且已配对的执行器时，明确显示等待执行器，不伪造成功。

## UI 行为

生产统一设置增加视频通道选择和可用性说明。按钮接线必须覆盖：

- 生成提示词 / 保存 / 预览
- 生成待处理 VIDEO
- 查看真实状态和错误
- 重试、取消
- 合并
- 发布

能力由服务端返回；不可用按钮禁用或显示原因。UI 不直接接触 API Key、Cookie 或执行器密钥。

## 数据和安全约束

- 继承关系保持：系统 < 批次 < 小说 < VIDEO；显式 false、空字符串和 0 必须保留。
- `compiledPrompt` 只在提交生成时组装并快照；用户可以在提交前最后编辑。
- 任务必须保持 `bookId/sourceTaskId` 身份，不允许跨书混用。
- 每个 VIDEO 的时长仍是单 VIDEO 上限，不改变固定单镜头规则。
- 日志不得出现密码、API Key、Cookie、storage_state、Bearer token 或执行器密钥。
- 本分支不修改 `master`、生产 `:3000`、正式 MySQL 卷或正式账号数据。

## 验收标准

1. 个人中心已配置 `yd2.0-mini` 时，V11 可以提交、轮询并获得真实媒体 URL。
2. 未配置或远程错误时，任务进入明确失败状态，不能掉回旧 Node handler。
3. 已配对豆包执行器时，V11 任务能够领取、续租、报告进度、上传精确 MP4 并成功结束。
4. 执行器离线、租约过期、验收未知、媒体不匹配和上传重试均有可验证状态。
5. 两个通道生成的 VIDEO 都能进入同一播放器、合并和发布链路。
6. 关键按钮均有前后端测试，不能只测试 HTTP 200。
7. 后端、前端和执行器测试通过；再做临时隔离环境 smoke。真实豆包账号登录仍需用户提供专用测试账号后单独验收。

## 不在本次范围

- 不新增第三家视频服务。
- 不修改生产容器或生产数据。
- 不把豆包账号密码上传到云端。
- 不把旧版 Node Batch Factory 路由作为 V11 的业务入口。
