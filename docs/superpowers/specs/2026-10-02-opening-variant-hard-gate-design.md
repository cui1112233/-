# 换开头变体硬门禁设计

## 目标

批量工厂启用“换开头”后，所要求的开头变体必须全部生成出可用正文；任一变体失败时，`opening` 阶段必须失败，并阻止该书继续资产、视频、合成和上传流程。

## 已确认的问题

线上已发布的 `batch-opening-meta` 预设要求模型输出 `===VARIANT N=== 时长：X秒`（标记与时长同一行），但 Go 解析器只接受标记独占一行、下一行才有时长的格式。解析器将全部变体记录为失败，却没有把“无可用变体”上报为阶段错误，自动化因此错误地继续。

## 方案选择

1. 仅修正线上预设：改动最小，但用户自定义预设或模型换行格式变化仍会再次触发同一故障；不采用。
2. **兼容解析 + 明确输出约定 + 硬门禁：采用。** 解析器接受同一行和换行两种已存在格式；模型请求末尾追加不可歧义的机器格式；持久化每个变体的结构化失败原因；只有合并历史成功结果后所有要求变体都成功，阶段才成功。
3. 保存完整模型原始回包用于诊断：可提供更多细节，但会扩大原文与提示词的存储范围；本次不加入。结构化失败原因和阶段错误已足够定位格式、时长或正文缺失问题。

## 数据流与边界

1. `BuildOpeningVariantsContract` 无论使用系统预设还是默认提示词，均在末尾附加唯一可解析的示例格式。
2. `ParseOpeningVariants` 接受 `===VARIANT N===` 后紧接“时长”或换行后“时长”的输入；仍校验索引、时长上限和非空正文。
3. 每个解析失败的变体携带简短的 `failureReason` 并持久化；历史成功变体不可被失败重试覆盖。
4. `RunOpeningVariants` 持久化本次结果与历史成功结果的合并视图。仅当所需 `1..N` 全部为 `succeeded` 时返回成功；否则返回包含缺失索引和原因的错误。
5. `BookStageService` 将该错误记录为 `opening` 阶段失败。现有自动化收到失败响应后不得推进该书的后续阶段；其他书仍可继续。
6. 前端卡片显示具体失败原因；没有历史原因的旧记录显示“历史记录未保留失败原因”。

## 不在本次范围

- 不调用任何付费模型，不自动重跑既有书。
- 不改变巨量 OCR、正文读取、预设选择、视频模型或镜像/数据卷。
- 不存储完整模型原始回包。

## 验收标准

- 线上预设的同一行标记格式可解析为成功变体。
- 换行格式继续可用。
- 任意一个要求变体缺失、时长非法或正文为空时，`opening` 阶段失败且自动生产不再推进该书。
- 已有成功变体在失败重试后仍被保留；若合并后全部成功，阶段可成功。
- 前端与任务日志都能说明失败原因。
