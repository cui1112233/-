# 个人中心账号与团队治理设计

日期：2026-08-28

## 背景与目标

当前个人中心将 DEV 的全局账号管理、当前团队成员授权、联合管理员协作和账号总览混在多个页面中。用户无法稳定判断某个操作影响的是全局账号还是当前团队；已有成员也没有界面入口可转入团队。

本设计将个人中心拆为四个清晰边界：

- 账号与角色：DEV 管理全局账号、角色和团队归属。
- 组员管理：团队负责人管理当前团队的成员 API 授权、额度和邀请。
- 联合治理：联合管理员、跨团队委托和审计。
- API 配置：团队负责人配置自己的模型；成员只读查看托管来源和可用能力。

不修改批量工厂、小说获取或管理后台的业务布局与入口。

## 信息架构

### 新增账号与角色页

新增路由 `/accounts`，仅 DEV 可见，在个人中心“开发者工具”下展示。

页面包含：

1. 顶部统计：总账号数、在线账号数、停用账号数、未归属 MEMBER 数。
2. 操作栏：角色、账号状态、在线状态、所属团队、关键词筛选；“创建账号”命令。
3. 账号表格：账号、角色、所属团队、API 托管负责人、账号状态、在线状态、本月用量和操作菜单。
4. 账号抽屉：资料、角色与团队、账号安全、操作记录四个区块。

账号抽屉不直接展示或读取 API Key。MEMBER 只展示模型托管负责人和已授予的能力范围。

### 组员管理页

`/team` 保留为当前团队的日常管理页：

- 顶部团队选择器仅供 DEV 切换“我的团队”或既有 MANAGER 团队。
- 团队概览、团队额度、成员列表、成员 API 范围、个人额度、邀请和团队名称保留。
- 移除 DEV 全局账号表和“授权管理者”入口。
- 创建成员、邀请、已有成员 API 授权均作用于当前已选团队。

### 联合治理页

`/advanced-team-admin` 只保留联合管理员配置、被委托团队操作和审计。它不是账号创建、角色变更或常规 API 授权入口。

### 会员中心与个人资料

- `会员中心`：身份、当前团队、额度、近期用量和通知总览。
- `个人资料`：头像、显示名称、联系方式、团队职务和安全状态。
- `用量与制作`：个人与当前团队的真实调用、费用快照和制作统计。

同一字段在多个页面出现时，统一以“当前团队”和“当前账号”口径显示；DEV 的当前团队为“我的团队”，不再使用“核心团队”作为替代名称。

## 权限与数据规则

### 角色边界

| 身份 | 账号与角色 | 组员管理 | 联合治理 | API 配置 |
| --- | --- | --- | --- | --- |
| DEV | 全局读写 | 自己团队及所有 MANAGER 团队 | 全部团队 | 自己模型配置 |
| MANAGER | 不可见 | 自己团队 | 自己团队及被委托团队 | 自己模型配置 |
| MEMBER | 不可见 | 不可见 | 不可见 | 只读托管来源与能力 |

### 成员归属

- MEMBER 只能有一个 `boundTo`，其值必须指向活动的 DEV 或 MANAGER 团队负责人。
- DEV 团队成员继承 DEV 的模型配置和团队总额度；MANAGER 团队成员继承对应 MANAGER 的配置和团队总额度。
- 账号归属变更只能由 DEV 在账号与角色页发起。
- 旧字段 `managerUsername` 保持兼容，语义为“团队负责人用户名”；不进行存量数据迁移。

### 转团队流程

1. DEV 选择一个活动 MEMBER 和新团队负责人。
2. 系统展示影响预览：原团队、新团队、模型托管负责人、团队总额度、现有个人额度与 API 范围。
3. DEV 确认后，服务端原子更新 `boundTo`。
4. 服务端清除该成员所有团队 API scope，成员状态变为“待重新授权”。
5. 记录审计日志，并通知成员、新负责人和旧负责人。
6. 新负责人仅能在自己的团队页重新分配文本、生图、配音权限与个人额度。

个人额度默认保留，只有 DEV 在影响预览中明确选择“同时重置额度”时才改为不限额；团队总额度不随成员转移改变。

### 角色变更

- DEV 可将 MEMBER 升级为 MANAGER；成功后自动创建独立团队。
- MANAGER 降级或转为 MEMBER 前，必须先迁移其名下所有 MEMBER。
- DEV 不能被常规成员编辑操作降级；Owner 仍不可被其他账号管理。
- 管理后台权限独立于 `dev`、`manager` 角色与 API scope，单独授权与撤销。

## API 授权规则

- API scope 为 `text`、`image`、`tts`；其授予权在当前团队的组员管理页。
- 授予 API 不等于授予管理后台、角色升级或模型 Key 访问权。
- MEMBER 不可读取、测试、保存团队负责人的 API Key。
- 停用或归档成员不能使用 API、接受邀请或转团队。
- 转团队后旧 scope 必须失效，新团队重新授权后才允许调用。

## 稳定性与体验

### 加载与错误状态

- 所有个人中心页面共享认证和成员资料加载守卫。
- 未完成加载显示骨架屏；请求失败显示可读错误卡与“重试”。
- 不允许主内容区仅留下空标题或空列表。
- 前端使用统一的当前账号来源，避免侧栏角色与页面成员角色不一致。

### 视觉要求

- 延续现有账户中心主题和右侧抽屉交互；不创建嵌套卡片。
- 深浅主题下状态、Tag、表格、抽屉和禁用控件满足可读对比度。
- 账号表在窄屏转为关键字段优先的卡片/折叠行，操作仍可访问。
- 团队页只显示当前团队，页面顶部明确显示该团队负责人和模型托管来源。

## 异常处理

- 目标负责人停用、目标团队不存在、成员归档、成员已处于同一团队时拒绝转移并返回原因。
- 转移提交期间如成员归属已被其他操作改变，返回冲突，不覆盖最新数据。
- MANAGER 试图操作非自己团队成员时返回禁止访问。
- API 重新授权失败时保持“待重新授权”，不恢复旧团队 scope。

## 验证计划

1. DEV 在账号页创建 MEMBER，转入 DEV 团队与 MANAGER 团队。
2. 转移前后校验模型配置来源、团队额度归属、旧 API scope 清理和重新授权。
3. DEV 升级 MEMBER 为 MANAGER，确认独立团队；降级有成员的 MANAGER 必须被阻断。
4. MANAGER 仅可管理自己的团队成员，不能转移成员或改角色。
5. DEV、MANAGER、MEMBER 分别访问所有个人中心路由，验证可见性与后端授权。
6. 接口失败、刷新、深色/浅色、桌面/窄屏验证不空白、不溢出、文字可读。
7. 回归现有团队邀请、成员 API scope、团队额度、在线状态、审计与管理后台权限逻辑。

## 非目标

- 不改写已有团队或成员数据。
- 不把批量工厂、小说获取的提交配置混入个人中心。
- 不把管理后台权限隐式绑定到任何 API 或团队角色。
