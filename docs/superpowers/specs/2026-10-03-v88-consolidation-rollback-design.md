# V88 发布回滚与运行环境收敛设计

## 目标

让 `v88` 成为唯一生产事实来源，把可重复的发布与回滚信息纳入仓库，同时收敛 ECS 上的旧容器、无主卷、临时资源和历史分支，降低磁盘占用与运行时歧义。

## 约束

- 不修改 `master`。
- 不把密钥、Cookie、数据库、任务状态、视频产物或用户内容提交到 Git。
- 回滚必须使用完整 Git SHA 与 GHCR 不可变镜像标签。
- 删除前必须证明对象无容器链接、无路由依赖、无业务数据用途。
- 生产服务继续由 `v88` 的部署契约管理；当前运行服务和数据库卷默认保留。

## 设计

### 发布与回滚事实源

在 `deploy/v88-public/` 增加：

- `CURRENT_RELEASE`：当前生产完整 SHA。
- `releases/<sha>.manifest.json`：Node/Go 镜像引用、分支、验证时间、健康检查结果和回滚前置条件。
- `releases/<sha>.env.example`：不含凭据的可审计配置键集合。
- `ROLLBACK.md`：按 SHA 回滚的操作步骤、验证步骤和失败恢复边界。

发布工作流继续从 `v88` 触发，并要求 Node/Go 使用同一 SHA；回滚只允许选择仓库已有且已验证的发布清单。Git tag `v88-release-<sha>` 作为人类可读的发布锚点。

### ECS 收敛

- 保留当前 8 个运行服务及其业务卷。
- 先验证 `v88-public-shuihuo-compat-legacy-1` 的流量与 Compose 依赖，再停止并移除它。
- 删除无容器链接的 `v78-public_mysql_data` 与匿名 0B 卷；不删除业务卷。
- 清理发布临时目录、已验证无用的旧镜像和过期日志。
- 对 `v88-public_go_api_artifacts` 只做业务级归档策略设计，不直接删除卷内容。

### 分支收敛

- 生产发布线只保留 `v88`。
- `master` 保留为主开发/集成线，不直接部署。
- 近 2～3 个已验证发布点保留 Git tag。
- 已合入、等价替代、历史归档和临时实验分支先生成清单，再删除远程引用；未合入的活跃功能分支必须逐项确认，不自动删除。

## 验收标准

- `CURRENT_RELEASE`、Node 镜像、Go 镜像和线上 `/api/build-info` SHA 一致。
- 回滚清单能在不依赖 ECS 残留文件的情况下恢复指定发布。
- 旧兼容容器移除后，生产路由、Node→Go 健康检查和批量生产关键接口正常。
- 删除候选卷无容器链接，数据库与业务产物大小不变。
- `v88` 工作树干净，部署工作流和回滚文档测试通过。
