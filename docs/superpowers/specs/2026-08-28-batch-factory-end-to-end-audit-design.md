# 批量工厂端到端流程验收设计

## 目标

验证批量工厂从“小说获取”到 121 发布回执的完整真实链路可执行、可恢复、可追踪。测试使用当前已配置的真实 AI、豆包本地执行器和 121 配置，但限定为 1 本测试小说，并优先控制为 1 个 VIDEO，避免不必要的额度和外部副作用。

## 范围与隔离

- 不删除或覆盖现有批次。
- 创建独立测试批次，保留批次 ID、书 ID、来源任务 ID 和原始 TXT。
- 真实生成阶段只提交最小测试数据。
- 发布阶段先执行发布预览和计划校验；只有前置条件完整且用户确认后，才提交 121。

## 六道流程门

### 1. 获取门

小说获取完成并转入批量工厂。必须保留 `sourceTaskId`、`bookId`、标题、平台、元数据和每本独立 TXT；不得跨书串联文本。

### 2. 批次门

创建独立批次并持久化生产方式、视频模型、模型版本、最大时长、画幅、剧本提示词预设和人物场景提示词预设。刷新页面后这些设置仍可回读。

### 3. 导演门

开始导演后，批次和单书状态必须进入排队/处理中，并最终得到结构化人物、场景、道具和 storyboard。爆款模式必须遵守“先改编审核，再导演”的顺序。

### 4. 生产门

每个 VIDEO 必须有独立的 `visualPrompt`、资产引用、时长和画幅；生成前动态编译 `compiledPrompt`，提交后能在水货生产或执行器侧看到对应任务。`visualPrompt` 不得被编译内容反写覆盖。

### 5. 合并门

只有全部 VIDEO 成功、媒体 ID 有效且顺序完整时才允许合并；合并产物应为 `{bookId}.mp4`，并能从服务端回读媒体记录。已合并不直接等于已完成发布。

### 6. 发布门

先生成发布计划，校验组织、121 版本配置、MP4/TXT 一对一映射和发布覆盖规则；提交后必须区分 `submitted`、`accepted_pending`、`failed`，只有真实发布成功才进入终态。

## 证据链

每一阶段记录阶段名、时间、批次 ID、书 ID、VIDEO ID、接口、关键参数摘要、返回状态、持久化状态、页面可见状态和下一步动作。证据分类为：

- **可执行**：真实完成并进入下一门；
- **可恢复**：失败后存在明确重试或人工修订路径；
- **阻断**：当前不能继续，必须修复；
- **假成功**：页面提示成功但没有真实后端产物或回执。

## 高风险检查

- AI 导演超时或返回非 JSON；
- 爆款开头审核结果被导演重新改写；
- 模型最大时长与 VIDEO 时长冲突；
- 生产提交成功但状态回调缺失；
- 合并顺序错误或媒体 ID 串书；
- 121 配置缺失、上传失败或异步待确认；
- 页面刷新或容器重启后批次状态不可恢复。

## 验收输出

输出一份按六道流程门组织的审计报告，包含每门的输入、接口、状态、证据、阻断点、修复建议和复测结果；发现的稳定问题补充为自动化回归测试。真实 121 提交若未获单独确认，只停留在发布预览/计划校验门。
