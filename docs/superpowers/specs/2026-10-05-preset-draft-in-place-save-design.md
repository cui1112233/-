# 系统预设词草稿原地保存设计

## 目标

让管理员能够持续优化同一份草稿（例如 SD 视频提示词 V3）而不产生无意义的新版本；已发布和归档版本仍保持不可变。

## 状态与行为

| 目标版本状态 | 管理台操作 | 后端行为 |
| --- | --- | --- |
| `draft` | 保存草稿 | 原地更新同一 `id + version`，版本号不变 |
| `published` / `archived` | 编辑当前版本 | 打开只读来源的副本；保存时必须显式“另存为新版本” |
| 任意版本 | 另存为新版本 | 复制为同一 ID 的下一个 `draft` 版本 |

发布仍只接受草稿版本；发布时当前已发布版本归档。这项变更不会自动发布任何草稿。

## 接口

- 保留 `POST /api/admin/presets/draft`：仅创建下一个草稿版本。
- 新增 `PUT /api/admin/presets/:id/:version/draft`：仅更新 `draft`；请求体带 `expectedVersion`，必须等于路径版本，防止陈旧表单覆盖。
- 新增审计动作 `preset.draft_updated`，记录更新前后不含正文和协议锁的摘要。

## 管理台

- 点开草稿：主按钮为“保存草稿（Vn）”，调用原地更新接口。
- 点开已发布或归档记录：主按钮为“另存为新版本”，调用创建草稿接口。
- 表格文案明确草稿可继续修改，已发布版本已锁定。

## 安全与兼容

- 权限与现有创建草稿相同，按实际预设模块校验。
- 所有更新仍经过现有字段、约束类别及归属槽校验。
- 不变更公开 `/api/presets` 的“只返回已发布版本”语义。
