# 小说获取处理流、模型与任务页设计

日期：2026-09-24  
维护分支：`v88`

## 目标

让小说获取的“处理”页只负责创建批次与展示本次进度，“任务”页成为唯一的任务和队列中心；模型选择减少为一个直接可用的默认下拉框；失败具有明确停止边界，不会无限调用。

## 已确认交互

### 处理页

- 保留批量输入、版本对应配置档和开始处理。
- 在“版本对应配置档”同一层级放置“默认文本模型”下拉框。
- 下拉只列出启用的文本模型；选择后立即保存，自动作为以后新批次的默认模型。用户再次切换才覆盖默认值，不再要求额外保存动作。
- 启动批次时将当前模型写入队列任务快照。以后切换默认模型不改变已排队、运行中或已完成任务的模型。
- 处理页仅显示当前批次的简短实时进度：解析、分类、原文、敏感处理、AI 文案、视频管理系统提交。它不再渲染第二份全量任务表。

### 任务页

- 任务页是唯一的队列与任务操作中心。
- 顶部汇总：运行中、待执行、等待重试、失败、已停止。
- 列表筛选：当前批次、历史未完成、全部历史。
- 每本显示：书名、批次、当前阶段、阶段状态、实际执行模型、重试次数、耗时、失败原因、原文字数、AI/上传状态。
- 操作：仅重试失败阶段、停止待执行项、删除。删除后，相关 `queued` 或等待重试项立即标记为已停止；已运行任务在当前安全边界后不再进入后续改文或上传。
- 历史队列不自动清空。若提供“停止全部待执行项”，必须二次确认且不影响已完成内容。

## 流程与状态机

```text
处理页选择默认文本模型（即时保存）
  -> 解析输入并锁定本次选择书目
  -> 创建含模型快照的队列任务
  -> 分类男女频/风格
  -> 获取原文
  -> 敏感处理
  -> 生成所选 AI 文案
  -> 视频管理系统提交
  -> 任务页逐阶段回写结果
```

- 分类依赖文本模型。模型不可用时，男女频和风格保持空值并显示“分类失败”，不得伪造默认分类。
- 原文成功、AI 失败时，原文与真实字数保留；重试从 AI 阶段开始，不重复抓取原文。
- 视频管理系统会话不可用时，成功的 AI 文案保留为待上传；重新验证后仅重跑上传。
- 单个失败项按既有队列策略最多自动尝试三次；达到上限后标记失败，等待用户在任务页显式重试。不得无限调用。
- 当前批次结果只能由该批次解析出的书目及输入顺序组成，绝不混入历史任务。

## 错误与可观测性

- 每个失败显示可理解的阶段、模型显示名、重试次数和安全化错误原因；凭据、Cookie、Token 与密码永不显示。
- “模型凭据无效”是模型配置问题，不自动切换其他模型，也不自动消耗替代提供方。
- 手动开始相同输入时优先复用已有待执行任务而非再创建重复项。
- 队列恢复、提升、取消、失败和人工重试均写入审计事件，供任务页显示。

## 验收标准

1. 选择默认文本模型后无需额外保存，下一批使用该模型；已排队批次模型不变。
2. 两本输入在处理页解析为两本，任务页和最终结果只显示该两本。
3. 分类、原文、敏感处理、AI、上传均按书展示状态；失败可定位到具体阶段。
4. 自动失败三次后停止；“只重试失败阶段”不回跑成功阶段。
5. 删除待执行书目后不再执行；历史队列仍可审计且不会污染当前批次。
6. 真实上传验收必须证明：AI 生成成功、视频管理系统会话有效、提交返回回执并在任务页呈现；页面 200 或队列完成不能替代该证据。
