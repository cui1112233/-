# 剧本人物/场景双栏编辑器设计

## 目标

重做 `/script` 中点击人物或场景后的编辑弹窗，使其接近已确认的参考图：左侧继续编辑人物/场景信息，右侧集中管理参考图片。该改动只调整编辑体验，不改变人物/场景数据结构、分镜参考图匹配规则或现有 AI 生图/上传接口契约。

## 已确认的交互

- 弹窗标题根据对象类型显示“编辑人物”或“编辑场景”。
- 桌面端采用双栏布局：左侧信息编辑区，右侧图片资产区；窄屏自动上下排列。
- 左侧保留当前动态字段、小说智能补全和补全结果提示，并继续支持新增对象、删除对象、保存和关闭。
- 右侧显示当前 `mainImageUrl` 的大图预览。
- 右侧下方显示 `imageUrls` 中的所有图片缩略图。
- 点击缩略图将其设为主图，并更新 `mainImageUrl`。
- 点击大图或缩略图可打开放大预览；预览关闭不改变数据。
- 每张图片可删除。删除主图时，若仍有图片则按列表中的下一张可用图片设为主图；没有图片时清空 `mainImageUrl`。
- 右侧提供“上传图片”和“AI 生成”入口。AI 生成使用当前已编辑的人物/场景字段和小说上下文；生成结果追加到图片列表，不覆盖已有主图。
- 不在主界面增加粘贴图片地址输入；已有上传、生图接口继续复用。
- 单张图片时自动成为主图；多张图片时不自动覆盖用户已经选择的主图。

## 数据流与边界

编辑器维护一个与当前对象对应的草稿状态，至少包含字段草稿、`imageUrls` 和 `mainImageUrl`。图片上传或生成成功后只更新弹窗草稿；点击“完成/保存”时一次性通过现有父级回调写回对象。取消或关闭不写回草稿。

图片预览继续通过现有鉴权图片访问方式加载，不能为了预览绕过鉴权直接暴露受保护文件。图片删除只删除当前对象中的图片引用；如后端已有图片删除能力则调用该能力，否则不在本次范围内对物理文件做删除，以避免误删共享资产。

分镜侧继续只读取保存后的 `mainImageUrl` / `imageUrls`，本次不改变分镜卡片的名称显示、发光/灰色使用状态和 H3 参考图请求逻辑。

## 视觉与可用性

- 弹窗宽度约 820–900px，右侧图片区保持稳定的预览比例。
- 空状态显示上传提示和 AI 生成按钮。
- 主图缩略图使用清晰边框或发光标识；非主图保持弱化边框。
- 删除按钮放在缩略图角落，避免与“设为主图”点击区域冲突。
- 生成和上传期间显示 loading，禁止重复提交；失败时在弹窗内显示可理解的错误提示。
- 图片加载失败时显示失败占位，不阻塞文字字段保存。
- 保持深色和浅色主题可读性，窄屏不出现横向溢出。

## 测试范围

- 编辑人物和编辑场景均渲染双栏结构。
- 主图大图、缩略图列表、空状态和放大预览可见。
- 点击缩略图更新主图；删除非主图和主图的选择规则正确。
- 上传/AI 生成结果追加图片，单图自动主图且不会覆盖既有主图。
- 取消不写回，完成后正确保存 `imageUrls` 和 `mainImageUrl`。
- 现有分镜参考图和实体字段保存测试继续通过。

## 非目标

- 不改 MySQL schema 或图片存储目录。
- 不改 H3 视频请求协议。
- 不改人物/场景提取算法。
- 不在本次工作中重构整个 `/script` 页面或素材库。
