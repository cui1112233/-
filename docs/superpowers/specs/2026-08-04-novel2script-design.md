# Novel2Script — 小说转可视化剧本工具设计文档

## 一、产品概述

一个纯前端的网页工具，用户粘贴小说章节内容，自动提取人物与场景，生成可切换四种格式的可视化剧本。面向女频短篇小说，核心卖点是"心理描写的可视化转化"——将所有内心戏转化为AI视频平台可识别的中观以上粒度动作。

---

## 二、技术架构

### 整体架构

```
纯前端 SPA（单 HTML 文件）
├── 左侧可收起导航栏
├── 左右分栏工作台（35/65）
├── 前端直连 AI API（OpenAI 兼容格式）
└── 本地 prompts/ 目录（预留，供未来 API 读取）
```

### 技术选型

| 层级 | 选择 | 理由 |
|------|------|------|
| 框架 | 原生 HTML/CSS/JS | 零依赖，单文件部署，开发量最小 |
| AI 调用 | 前端 fetch 直连 API | 无后端，API Key 存 localStorage |
| API 兼容 | OpenAI 格式 | 兼容 OpenAI / Claude / DeepSeek / 通义千问等 |
| 存储 | localStorage | API Key + 用户偏好，不存服务器 |

### 安全设计

- API Key 仅存浏览器 localStorage，不会上传到任何服务器
- 所有 AI 调用从用户浏览器直接发起
- 无后端，无数据库，无用户系统

## 五、AI 调用流水线

### 两次串行调用

```
用户点击 [一键生成]
        │
        ▼
┌──────────────────────────┐
│ 第1次 AI 调用             │
│ 人物提取 + 场景拆解        │
│ 输入：小说原文              │
│ 输出：JSON（人物+场景）     │
│ 前端渲染为可编辑卡片        │
└──────────┬───────────────┘
           ▼
┌──────────────────────────┐
│ 第2次 AI 调用             │
│ 剧本生成                  │
│ 输入：小说原文 + 人物JSON  │
│       + 场景JSON          │
│ 输出：可视化剧本（文本）    │
│ 格式由用户选择的切换器决定  │
└──────────┬───────────────┘
           ▼
     展示在右侧面板
```

### 失败处理
- 第1次失败：提示错误，可重试，之前结果不保留
- 第2次失败：保留人物/场景卡片，剧本区显示错误提示 + 重试按钮

## 六、四种输出格式

### 格式切换器

在右侧面板顶部，以 Tab 形式切换：影视剧本 | 分镜脚本 | 短视频脚本 | 四合一

### 格式1：影视剧本

标准好莱坞格式，用于影视改编参考。

```
【场景X：场景标题】
地点：XXX  时间：XXX
出场人物：XXX

[动作描写段落]

　　角色名：（表情/动作提示）台词内容

[动作描写段落]

　　角色名：台词内容
```

### 格式2：分镜脚本

按镜头拆分，标注拍摄信息。

```
【镜号1】景别：XXX | 运镜：XXX
画面：XXX
对白/音效：XXX

【镜号2】景别：XXX | 运镜：XXX
画面：XXX
```

### 格式3：短视频脚本（默认格式）

标准短剧剧本格式，面向上线平台。

```
X-1 场景名 时间/内/外
人物：xxx、xxx

△只写镜头能看到的动作、表情、道具、互动、站位，不写心理和环境描写。

人物A（关键句写具体表情/动作/身体状态；普通句可简写或省略）：台词。
人物B（按台词功能决定括号详略）：台词。

△动作或道具特写。

【字幕：地点或关键信息】

【本集结尾卡点】
△画面描述。
人物A（具体表情/动作描写）：最后一句卡点台词。
```

### 格式4：四合一

同一内容，四种格式并列输出，方便对比参考。

## 七、提示词核心规则

### 规则1：心理描写视觉化转化

所有心理活动必须转化为AI视频平台可识别的中观以上粒度动作。

| 心理状态 | ❌ 太微观（AI识别不了） | ✅ 可被识别 |
|---------|------------------------|------------|
| 内心酸涩 | 指尖掐进掌心 | 眼眶迅速泛红，别过头去，肩膀微微发抖 |
| 愤怒 | 牙关咬紧 | 一拳砸在桌上，脖子上青筋暴起 |
| 紧张 | 手心出汗 | 反复捏手指，指节发白；不停舔嘴唇 |
| 压抑 | 呼吸变浅 | 胸口剧烈起伏，深呼吸后缓慢吐出 |
| 回忆 | 眼神涣散 | 盯着一个方向不动，手中动作完全停下 |
| 犹豫 | 嘴唇微动 | 手伸出去又缩回来，拿起东西又放下 |
| 恐惧 | 瞳孔收缩 | 脸色刷白，后退两步，手抖得拿不稳东西 |

要求：
- ✅ 身体姿态变化、大幅度肢体动作、明显面部表情变化、物体交互
- ✅ 可见的生理反应：指节发白、青筋暴起、脸色发白/涨红、眼眶泛红、嘴唇发抖
- ❌ 微观动作：指尖动作、瞳孔变化、睫毛颤动、微表情
- ❌ 不可见感受：心跳加速、手心出汗、脊背发凉、胃里翻涌
- 禁止出现"心里想""感到""觉得""内心"等词汇
- 禁止使用画外音/旁白/内心OS

### 规则2：对白括号 A/B/C 分级

人物括号不是每句都写满，按台词功能分级：

**A级：关键爆点，必须写具体括号**
- 适用：主角反击、反派施压、亮证据、打脸、拒绝、崩溃、结尾卡点
- 格式：`人物（关键动作 + 表情/眼神 + 声音状态）：台词`
- 动作必须是中观以上粒度

**B级：普通推进，简写括号**
- 适用：报数、问话、承接信息、日常对话
- 格式：`人物（一个动作或声音状态）：台词`
- △动作已写清的，括号可省略

**C级：背景/群戏，不写括号**
- 适用：群众口号、短促附和、电话音、录音、背景议论
- 格式：`人物：台词` 或 `人物（声音状态）：台词`

### 规则3：△ 画面描述规则

- 只写镜头能看到的：动作、表情、道具、站位、互动
- 不写心理描写、环境描写、抽象形容
- 每个△段落是一个独立的画面单元

### 规则4：人物提取规则

- 提取所有有名字或可单独识别的角色
- 别名合并（同一人物不同称呼不重复输出）
- 输出字段：姓名、别名、角色定位、身份标签、性别、大致年龄、外貌要点、性格关键词、关系网络、说话风格、章节功能
- 关系网络覆盖：血缘/情感/师门/敌对/从属/利益六种类型

### 规则5：场景提取规则

- 按地点和时间变化拆分
- 同一建筑内不同独立空间分别输出
- 从剧情反推：人物可能的动作对应场景中需要的元素
- 输出字段：场景编号、地点、时间、出场人物、核心事件、情绪基调、冲突类型
