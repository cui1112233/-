# V78 小说获取 V2 最终功能对照审计

**日期：** 2026-09-02  
**发布线：** `release/production-v78.3.0.3-batch-factory-go-first`  
**用途：** 把旧《批量原文改文系统》的功能盘点与 V78 小说获取 V2 当前实现逐项收口，避免只看“测试通过”就误判已经完成。

## 1. 审计基线

此前对用户提供的完整旧源文件做过完整盘点，基线包含 **60 个后台接口** 与 **215 个页面控件**。本文件不重复机械抄写全部控件，而是把这些入口按真实用户流程归并成可验收的功能域，并对照当前 V78 页面、V2 API、执行器、队列、定时任务和 121 Browser Worker。

状态定义：

- **已保留**：旧功能仍存在，用户入口和核心语义继续可用。
- **新版替代**：旧入口或旧参数被 V2 的新流程取代，但用户能力没有丢失。
- **真正遗漏**：旧功能应该保留，但当前代码或页面没有实现。
- **真实环境验证**：代码与自动测试已存在，但必须连接真实外部网站/登录环境才能最后确认。

## 3. 旧入口的新版替代说明

以下不是遗漏，而是经过确认后的主动升级：

1. 旧 `ai_count` 不再决定 AI1~AI5 的连续数量，改为 `targetVersions` 稀疏选择。
2. 121 不再拥有第二套“上传版本选择”；生成目标和网站提交目标由同一次版本选择决定。
3. 历史“重跑”和当前任务“重试”分开：历史重跑创建新批次，任务重试从原任务断点继续。
4. 已取消不再被当作失败；只有用户手动选中后才会重新处理。
5. 当前批次从临时页面状态升级为持久化批次记录。

这些变化与 `docs/superpowers/specs/2026-09-01-v78-novel-fetch-source-aligned-redesign.md` 的硬约束和验收标准一致。

## 4. 真正遗漏

截至本次收口修改，按上述功能域检查：

- **定时任务管理入口**：此前属于真正遗漏；本次已补齐查看、刷新、取消和删除，因此从遗漏清单移除。
- **第二套 121 上传版本选择**：不是遗漏；设计明确要求移除，统一跟随本次目标版本。
- **独立 AI 数量输入**：不是遗漏；V2 已用 AI1~AI5 稀疏目标替代。
- **处理页完整规则编辑器**：不是遗漏；完整规则编辑仍属于“处理规则”页。

**当前没有发现仍应保留但完全没有实现的产品功能入口。**

这句话只代表代码/页面能力对照，不代表外部网站已经在当前环境完成真实登录上传验收。

## 5. 自动验收门槛

`.github/workflows/novel-fetch-v2-check.yml` 必须同时通过：

1. 小说获取 V2 专项测试。
2. `tests/*.test.js + lib/*.test.js + routes/*.test.js` 完整 Node 回归。
3. `services/121-browser-worker` 自身测试。
4. 前端依赖安全审计（moderate/high 必须为 0）。
5. `frontend` 正式 build。

任何一项失败，都不能把小说获取 V2 标成“完成”。

## 6. 真实环境验证

以下属于 **真实环境验证**，CI 无法替代：

1. 使用有效 V78 登录态进入小说获取页面。
2. 解析至少两本小说并只选择部分小说。
3. 选择非连续目标，例如 `原文 + AI1 + AI3`。
4. 分别给 AI1 / AI3 选择不同改文方式。
5. 执行开始处理，确认未选择 AI2 不生成。
6. 执行敏感词 AI 修复并确认当前批次状态刷新。
7. 创建一条未来定时任务，在“定时任务”中查看、刷新、取消并删除。
8. 121 登录状态从红点进入验证，成功后变为在线状态。
9. 对选中小说执行“提交网络”，确认只提交本次已完成且未 confirmed 的目标版本。
10. 重新刷新页面，确认当前批次、任务状态和 121 提交回写仍存在。

如果 121 真实网站页面结构、验证码或网络环境改变，代码可能需要按真实页面重新适配；这类外部变化不能通过静态源码审计提前证明。

## 7. 最终结论

从旧系统能力到 V78 V2 的**代码与页面功能对照**看，本次补齐定时任务管理后，没有发现剩余“真正遗漏”的产品功能；旧入口中被移除的部分都有明确的新版替代逻辑。

但“小说获取 V2 100% 完成”的最终状态必须同时满足：

- 最新 HEAD 的完整 CI 全绿；
- 真实 V78 登录态下完成一次页面 smoke；
- 真实 121 环境完成一次登录 → 提交网络 → confirmed/状态回写 smoke。

在这三项证据齐全以前，发布状态应写为 **代码功能已收口，等待最终环境验收**，不能提前写成“已正式可用”。
